# RoleFlow v1.1.0

## 本版重点

- 消息发现现在能正确区分正式面试邀约、询问意向、索要信息、补充信息和普通沟通。岗位或产品描述里只是出现“面试”时，不会被误判为正式邀约。
- 已验证的附件简历请求卡片会显示为 BOSS 人工待办，不会自动点击“同意”或“拒绝”。同一轮既有 HR 纯文字又有简历请求时，页面会同时给出人工操作提示和可复制的本地回复草稿。
- BOSS 岗位竞争情况卡片不再冒充 HR 文字进入模型；语音、图片、普通附件和未知卡片继续安全停止。
- 岗位主视图先给推进结论，再说明岗位主要工作、公司业务、候选人匹配度、薪资和基于当前资料可支持的机会评价。
- 首轮岗位分析失败、随后重试成功时会保留失败历史，同时正确显示“失败后已解决”，不会继续出现在当前待语义分析中。
- 新增职责 40% + 要求 60% 的连续积分影子比较，但生产判定仍使用二维表。现有样本没有人工确认标签或同岗位重复模型组，不足以证明积分路线更准确或更稳定。

## 浏览器与安全

- 默认使用“RoleFlow 专用 Edge（推荐）”，登录资料保存在 `%LOCALAPPDATA%\RoleFlow\BrowserProfile`，不需要普通用户安装 Edge Control。
- 静止基线仍是同一窗口内一个 `BOSS-SEARCH` 和一个 `BOSS-COMMUNICATION`。消息发现只有在本地缺少完整可信 JD 时，才允许串行打开一个后台临时详情页，并在核验和 checkpoint 后关闭。
- 除用户主动启动工作区时的一次引导外，扫描、JD 读取、分析、消息发现、沟通、轮询和恢复都不会抢占前台。
- 本版对真实 BOSS 只做了低频只读 DOM 取证：核对了平台竞争卡、纯文字和附件简历请求卡的结构。没有点击卡片或按钮，没有填写或发送消息，没有投递或申请。

## 下载

- 普通 Windows 用户下载 `RoleFlow-Setup-1.1.0.exe`。
- 使用同页的 `RoleFlow-Setup-1.1.0.exe.sha256` 核对安装器完整性。
- GitHub 自动生成的 Source code 压缩包不是安装程序。

## 验证与限制

- v1.1.0 最终候选通过 108/108 项离线检查；这些检查使用缩减 DOM 夹具、假浏览器、临时数据库和冻结比较样本，不访问真实 BOSS，也不执行真实沟通。
- 附件简历请求的真实结构已经只读核对，但没有取得可保存的真实页面截图，也没有点击卡片验证动作结果。位置确认和面试排期卡片尚无真实 DOM 证据，仍会安全停止。
- 消息草稿只保存在本机并由用户复制；任何真实发送仍需用户针对当前目标明确操作。
- 安装器尚未代码签名，Windows 可能显示信誉或 SmartScreen 提示。
- 生产岗位判断仍使用二维表；积分路线只保存影子对比，不影响推荐或沟通清单。
