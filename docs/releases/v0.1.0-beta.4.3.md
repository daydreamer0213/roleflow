# RoleFlow v0.1.0-beta.4.3

这是 beta.4.2 新用户人工验收进入真实沟通环节后，对当前可触发阻塞的续验候选版。

## 普通用户下载

- 普通 Windows 用户请下载 `RoleFlow-Setup-0.1.0-beta.4.3.exe`。
- `RoleFlow-Setup-0.1.0-beta.4.3.exe.sha256` 用于校验安装程序完整性。
- `RoleFlow-v0.1.0-beta.4.3-portable.zip` 是包含固定 Node.js 的高级免安装版。
- GitHub 自动生成的 Source code 压缩包不是安装程序。

## 本版改进

- 覆盖安装会保留现有简历、模型设置、筛选方案、岗位、工作流和沟通批次，可直接
  从沟通环节继续人工验收。
- 结果不明的旧条目仍必须由用户填写证据并人工解决，程序不会恢复、重放或补点。
- 当端到端验收状态仍为 `e2e_pending` 时，页面会显示下一条不可变岗位的名称和
  公司；每次授权只处理这一条，随后自动暂停，剩余条目继续保持待处理。
- 普通全批次 `start` / `resume`、旧页面请求和缺少精确 item ID 的直接 CLI 调用
  都无法绕过单项验收边界。
- 真正派发点击前会激活固定 `BOSS-SEARCH` 标签，重新确认数值型 tab ID、窗口、
  active 状态、岗位身份、登录、风控、按钮和坐标；最终目标计算后会紧邻点击再
  确认一次 active，之后最多点击一次。
- 点击结果不明时仍立即停止，保留 `ambiguous` 证据且不自动重试。

## 验收证据

- 完整离线套件通过：`All 97 offline checks passed.`。
- BOSS 相关离线检查只使用 fake browser，不访问真实 BOSS。
- 安装器暂存目录不得包含数据库、简历、API Key、日志、报告、浏览器 profile、
  测试源码或 Edge Control。
- 本版构建和测试不会抓取新岗位、解决现有结果不明条目、点击真实“立即沟通”、
  发送消息或申请岗位。

## 下一次人工验收

1. 在当前 beta.4.2 上覆盖安装 beta.4.3，不卸载、不清空 `E:\RoleFlow\data`。
2. 打开当前沟通批次，对第 1 个结果不明条目填写事实依据并选择“标记停止”；
   这一步只更新本地数据库。
3. 核对页面显示的下一条岗位名称和公司。
4. 用户针对该岗位明确授权后，点击“验收这个岗位并自动暂停”。
5. RoleFlow 无论得到成功、失败还是结果不明，都不会自动进入第三个岗位。

## 已知限制

- 安装程序尚未代码签名，Windows 可能显示信誉或 SmartScreen 提示。
- 卸载时会先显示 Inno Setup 标准确认，再询问是否删除本地数据，因此目前可能
  感觉像连续提示两次。
- 卸载器尚未负责停止 Edge Control bridge；卸载后若安装目录仍被占用，需要先
  确认并关闭对应 bridge 进程。覆盖安装不走删除本地数据流程。
- 安装器不公开分发 Edge Control 扩展和桥接，因为项目尚无可验证的再分发许可；
  全新电脑仍需按说明单独准备浏览器连接组件。
- 自动沟通的真实单岗位端到端稳定性仍待用户针对页面显示的不可变样本另行授权
  验收，不能把离线通过解释为线上已修复。
- 当前岗位详情主线仍只使用 `trusted_pane`；`search_page_api` 是后续独立拓展，
  `standalone_detail` 不启用。
- Wave 5 继续暂停。
