# RoleFlow v1.2.0

## 本版重点

- 桌面工作台按“工作台、求职、沟通、成长”重新组织。首页突出每天反复执行的岗位发现和跨天反馈，岗位页、消息页、求职体检、定向简历与模拟面试都优先显示用户当前要处理的内容。
- 消息发现会读取可见会话中的状态变化和 HR 新回复。已读、送达只保留统计；需要处理的新回复会显示 HR 原文或安全卡片摘要、岗位分析和可编辑回复草稿。
- 回复草稿自动保存。用户复制、标记已手动发送或确认发送时，当时的最终文字会成为后续学习输入；撤回的回答与事实不会继续复用。
- 用户可以逐条或批量确认发送。系统冻结当次确认的岗位与文字，通过固定后台消息页串行执行，并逐条核对目标和结果；登录、风控、页面丢失、目标不一致或结果不明确时立即停止。

## 求职反馈与成长

- 求职体检按 48 小时等待期统计结果，遇到周末顺延。30、50、70 个成熟样本分别对应初步观察、可比较结论和正式诊断。
- 招呼语、简历或求职策略真正改变时开启新的策略轮次。修改前的投递及其迟到结果继续属于旧轮，不会混入新策略的诊断。
- 定向简历以用户原始简历和目标方向为基础，自动生成整份可编辑版本，并列出改动位置、依据和不能越过的事实边界。用户启用最终全文时才创建新的简历版本和策略轮次。
- 通用模拟面试默认只使用冻结简历和有效事实，每道问题都显示简历证据。岗位专项模式仍是可选项；本版不包含公司外部研究、外部题库或语音面试。

## 可靠性与数据边界

- 专用 Edge 在后台或最小化时仍可继续受控读取；正常流程不会抢占用户前台。消息详情只在本地缺少完整可信 JD 时串行打开一个后台临时页，并在核验后关闭。
- 消息会话使用规范 BOSS 岗位编号、既有会话绑定、岗位名称、公司、薪资和基础城市关联本地岗位。“广州”与“广州·区·商圈”不再被误判为不同城市，消息详情也不会再因裸岗位编号创建重复岗位。
- 历史重复岗位、草稿和事件不会在升级时静默删除。数据库迁移前仍会自动备份，用户简历、模型 Key、BOSS 登录资料、岗位数据库和运行日志都不会进入发布包。

## 下载

- 普通 Windows 用户下载 `RoleFlow-Setup-1.2.0.exe`。
- 使用同页的 `RoleFlow-Setup-1.2.0.exe.sha256` 核对安装器完整性。
- `RoleFlow-v1.2.0-portable.zip` 面向需要便携包的高级用户；GitHub 自动生成的 Source code 压缩包不是安装程序。

## 验证与限制

- v1.2.0 最终候选通过 131/131 项离线检查。检查使用 fixture、假浏览器和临时数据库，不访问真实 BOSS，也不产生真实外部写入。
- 桌面改版另完成 15 个页面状态、4 个视口的 60/60 离线浏览器验收；横向溢出、控制台错误、页面异常、失败请求和外部请求均为 0。
- 2026-08-30 的真实全流程验收在用户单次授权下完成 17/17 条批量沟通，并完成只读消息发现与草稿恢复验证。这不是后续版本的持续发送授权；每个新批次仍必须由用户确认。
- 安装器尚未代码签名，Windows 可能显示信誉或 SmartScreen 提示。
- 未取得真实 DOM 证据的位置确认、面试排期及未知消息卡片仍会停止，不会猜测点击或发送。
- 生产岗位判断继续使用已经冻结的二维表。连续积分仅作为历史影子证据，不影响推荐与沟通清单。
