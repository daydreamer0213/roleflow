# 消息机会判断：展示可核对的原因

## 设计与边界

用户需要知道为什么值得聊或不优先，而不是看到内部的“基础条件不满足”。保留原筛选/二维表决策，只修复解释链：优先展示已保存的地点、薪资等具体排除依据；简历匹配单独说明，不能把地点不符翻译成能力低。旧记录直接使用已保存依据，无需重新访问平台、调用模型或修改用户数据。缺少依据时明确待核对，不编造目标城市、薪资门槛或简历事实。

默认页面仍只显示简短结论、关键原因、匹配依据和工作安排，沿用现有折叠资料区，不增加新面板或依赖。

## 执行

- [x] 先补失败回归：新分析原因、旧记录投影、持久化草稿恢复。
- [x] 复用具体规则原因；区分条件排除与简历匹配；修复两平台重启恢复链路。
- [x] 定向检查及独立只读复核；在现有本地消息页核验实际地点记录及下线优先，薪资冲突通过合成样本核验。
- [x] 更新结果记录。只保存当前分支，不合并、发布、改版本，不访问招聘平台或发送消息。

## 验收

地点不符必须指出岗位实际地点，薪资不符必须保留岗位实际薪资及已记录的冲突原因；不能仅展示泛化结论。既有硬性资质缺口、风险、未知和下线状态不被隐藏或误改。重启后相同依据仍可见；历史筛选原因不套用当前计划重新解读。
