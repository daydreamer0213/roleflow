## 验收范围

- 共享外壳：按“工作台 / 求职 / 沟通 / 成长”分组的桌面侧栏、统一标题、表单、按钮、状态与折叠详情样式。
- 今日任务：把每天可重复执行的岗位发现作为主行动，同时显示当前轮次和跨天反馈入口。
- 岗位：发现过程和岗位台账均以结果、进度与下一步为主，运行明细默认折叠。
- 消息：左侧选择 HR 新消息，右侧集中显示原文或安全摘要、岗位分析、可编辑回复和确认动作；已读、送达只保留统计。
- 求职体检：先显示当前策略轮次的结论和 30/50/70 证据进度，再显示前后轮比较与详细数据。
- 简历工作室：整份可编辑草稿是主工作区，只读修改账本作为辅助依据。
- 面试训练：当前问题与回答框是主工作区，历史回答和其他会话默认折叠。
- 辅助页面：onboarding、profile、resumes、settings、diagnostics 和 communication 复用统一外壳与视觉规则。

所有状态均由临时 SQLite、注入式离线 fixture 和假浏览器生成，没有读取用户真实数据库、真实简历或真实 BOSS 页面。

## 用户可见结论

页面现在围绕“现在做什么、进展到哪里、系统得出什么结论、下一步是什么”组织。技术运行细节、历史记录和解释仍可访问，但默认不与主行动争夺注意力。视觉改造没有改变岗位评价、反馈统计、消息学习、草稿自动保存、策略轮次、简历启用或面试生成规则。

## 尚未验证与后续入口

- 真实岗位、消息和简历内容可能比 fixture 更长、更密；需要在后续实际使用中按真实拥挤点继续微调，不能把本次离线验收当成所有真实内容密度已经覆盖。
- 本轮没有读取新的真实 BOSS 消息卡片结构。位置确认和面试排期仍需新的只读 DOM 证据后再扩展。
- 真实简历通用面试仍等待用户本人回答并完成一轮，当前不能评价整轮追问和复盘效果。
- 任何真实消息确认发送都需要用户对新建的单岗位不可变批次另行明确授权；本轮没有填写、粘贴、发送、投递或申请。
- 岗位专项面试的公司/行业研究只在出现真实面试邀请并重新确定范围后考虑。

本地 UI 改造没有需要用户立即决定的阻塞项。推送、合并、打包、版本号和 Release 均未执行。
