# 已废弃：岗位主线本地证据复核设计

> **状态：不得实施。** 2026-07-28 用户复核两个真实岗位后确认，本设计的中文双字片段与技术词模糊匹配会把“AI 辅助前端”和“AI 辅助全栈”同时救回，不能区分工作方法与工作对象。替代设计见
> `docs/superpowers/specs/2026-07-28-role-foundation-evidence-design.md`。

# 岗位主线本地证据复核设计（历史记录）

## 背景

当前轻量匹配链路每个岗位只调用两次模型：

1. `understandJob` 提取岗位主线要求；
2. `matchJob` 只返回有候选人证据的稀疏匹配行，省略项在本地补成 `unknown`。

`roleCoreEvidenceState()` 随后检查主线要求中是否存在 `matched` 或
`transferable` 证据。如果主线要求存在、但模型没有输出任何正向证据，岗位就进入
`backup`。

20 条真实保存 JD 验收显示，这个规则会把两种情况混在一起：

- 候选人确实没有相关证据；
- 候选人有相关证据，但模型在本次输出中没有选中它。

同一个岗位、同一份确认画像、同一套提示词和相同代码曾分别得到一次 `talk` 和两次
`backup`。因此，继续只调整提示词不能让该边界稳定。

## 目标

- 不再把模型省略证据直接等同于候选人没有证据。
- 保留现有两次模型调用，不增加第三次方向判断。
- 只使用用户已确认的匹配卡，不读取或复制完整简历正文。
- 只允许把有可靠本地证据线索的 `backup` 恢复为 `talk`。
- 本地复核不能把岗位提升为 `primary`，也不能制造简历证据。
- 资格冲突、核心硬门槛、安全风险、地点、实习、薪资下限和用户排除词等防护保持不变。
- 不引入职业分类表、行业模板、外部依赖、数据库迁移或网络调用。

## 不采用的方案

### 继续扩写提示词

两条聚焦测试中曾成功一次，但 20 条正式运行和五条复测没有稳定复现。继续添加例子会增加
提示词长度，却不能消除模型选择证据时的随机性。

### 增加第三次模型裁决

第三次调用可以专门判断方向，但会增加单岗位耗时、费用和新的失败点。当前单岗位两阶段平均
仍超过一分钟，不接受该成本。

### 只要主线证据未知就全部放入 `talk`

这能提高召回，但会撤销已经生效的相邻岗位过滤，让明显偏离方向的岗位重新默认勾选。范围过宽，
不采用。

## 选定方案

在 `compactAnalysis()` 中增加一次纯本地复核。输入只包括：

- `jobUnderstanding` 中标记为 `central=true` 的要求标签和 JD 证据短句；
- 已确认匹配卡的 `targetDirections`；
- 已确认匹配卡的 `strongEvidence`；
- 已确认匹配卡的 `transferableCapabilities`。

复核不读取 `userNotes`，因为用户偏好不能证明经历；也不读取未确认简历版本。

### 通用文本匹配

文本匹配只做以下两类确定性比较：

1. 大小写无关的完整英文或技术标识匹配，例如 `AI`、`RAG`、`Agent`、`Dify`；
2. 中文连续双字片段匹配，但必须至少命中两个不同的有效片段。

以下通用片段不计入命中：

- 工作、作流、能力、经验、相关、负责；
- 开发、应用、技术、工具、实践、熟悉；
- 岗位、要求、项目、业务、系统、平台。

这些词跨职业普遍存在，单独重合不能证明岗位方向一致。该列表只排除通用语言，不描述任何职业、
行业或技术栈。

英文或技术标识必须按完整标识比较，不能用子串把 `AI` 错配为 `API`。

### 复核结果

对每条主线要求生成以下内部结果：

- 模型已经给出 `matched` 或 `transferable`：保持模型证据；
- 模型结果为 `unknown`，且确认匹配卡达到上述命中条件：记为
  `locallyCorroborated`；
- 模型明确给出 `missing`：不得被本地复核覆盖；
- 没有可靠命中：保持未知。

分析结果只保存复核计数和被复核的主线要求索引，不复制匹配卡证据正文。

### 分档规则

`roleCoreEvidenceState()` 按以下顺序判断：

1. 至少一条主线要求有模型 `matched` / `transferable` 证据：沿用现有流程；
2. 没有模型正向证据，但至少一条 `unknown` 主线要求得到本地复核：
   保留为 `review/talk`；
3. 主线要求全部没有模型证据，也没有本地复核：沿用现有 `backup`；
4. 模型明确给出的结构化硬冲突：仍由硬阻断规则处理，本地复核无权覆盖。

本地复核只解除 `role_core_unproven_guard`。薪资、经验、岗位质量和其他规则仍可把岗位放入
`backup` 或 `not_recommended`。

## 数据流

1. `createJobAnalysisRunner()` 仍执行现有两个模型阶段。
2. `compactAnalysis()` 在内存中把 `matchingCard` 与主线要求做通用文本匹配。
3. 分析对象新增一个小型内部字段，记录复核数量和要求索引。
4. `applyRuleGuard()`、`decisionBucket()` 和 `workflowEligibility()` 继续共用
   `roleCoreEvidenceState()`，不在三个调用方分别复制规则。
5. 历史分析没有新字段时保持现有行为，不需要迁移数据库或重算历史数据。

## 版本与缓存

- 在分析修订指纹中新增本地决策版本 `decisionRules`。
- 本次版本固定为 `role-core-corroboration-v1`。
- 旧分析缺少该版本时标记为 `decision_rules_changed`，进入现有重分析流程。
- `understandJob` 和 `matchJob` 的模型管线版本不变，因此重分析可以复用两阶段模型缓存，
  只重新执行本地压缩与分档。
- 历史分析对象仍可读取和展示；没有执行重分析前不会被静默改写。

## 用户可见行为

得到本地复核的岗位：

- 显示为 `talk`，不会自动升级为 `primary`；
- 保留“需要进一步核对”的语义；
- 可显示“确认匹配卡存在相关证据线索，建议先聊确认”；
- 不显示为已经完全匹配；
- 不生成新的 `resumeEvidence`；
- 不改变真实沟通或投递授权边界。

## 失败处理

- 匹配卡为空或缺少相关字段：不复核，沿用现有结果。
- 主线要求为空：沿用现有宽松召回行为。
- 只有一个通用中文片段重合：不复核。
- 英文标识只是子串重合：不复核。
- 新字段缺失或格式异常：按零复核处理，不得报错或放宽硬边界。

## 测试

### 离线失败回归

先写测试并确认修改前失败：

1. 模型将“AI 工具实践”留为 `unknown`，确认匹配卡包含已确认的 AI / Agent / RAG
   证据时，岗位应为 `talk`，不得成为 `primary`；
2. 只有“工作、开发、应用、平台”等通用词重合时仍应为 `backup`；
3. `AI` 不得与 `API` 子串误匹配；
4. 模型明确给出 `missing` 时，本地复核不得覆盖；
5. 匹配卡为空时保持 `backup`；
6. 结构化硬阻断仍为 `not_recommended`；
7. 经验、薪资等其他备选规则仍可覆盖本地复核；
8. 历史分析缺少复核字段时保持兼容。

目标测试至少包括：

- `tests/semantic_pipeline_smoke.js`
- `tests/screening_quality_smoke.js`
- `tests/workflow_inventory_smoke.js`
- `tests/generic_evidence_matching_smoke.js`
- `npm.cmd test`

### 少量真实保存 JD 验证

离线测试全绿后，只运行保存 JD 和正式模型，不访问招聘网站：

- 对已知争议岗位使用三个独立新缓存各运行一次；
- 对相邻岗位控制样本运行一次；
- 争议岗位三次都应进入 `talk`；
- 控制样本应保持 `backup`；
- 不得出现新硬阻断、第三次模型调用或契约修复增长。

如果四条验证没有满足上述条件，停止，不运行新的 20 条。

## 验收边界

只有满足以下条件，才讨论再次运行 20 条：

- 离线全量测试通过；
- 争议岗位三次结果稳定；
- 相邻岗位控制样本未被错误救回；
- 单岗位仍只有两次正常模型调用；
- 本地复核只发生 `backup -> talk`，没有 `talk -> primary`；
- 硬阻断和其他风险规则没有放宽；
- 所有真实结果继续只写入 `D:\DevData\RoleFlow-private-benchmark`。

本设计不等于批准合并到正式项目，也不等于批准新的 20 条真实模型运行。
