# 批量沟通验收晋级设计

日期：2026-08-15  
状态：用户已批准

## 1. 已确认事实

- `0.1.0-beta.4.4` 已完成一个真实单岗位端到端验收：
  `初级AI Agent开发工程师 / 广州壹凡科技有限公司` 最终为
  `succeeded`、`click_count=1`，`friend_add` 返回 HTTP 200、业务码 0。
- 批次 `#1` 已在单岗位检查点自动暂停；第 4 至第 12 项仍为
  `pending`、`click_count=0`，共 9 项。
- 这 9 项的不可变执行范围 SHA-256 为
  `50980336b44b898ac75dc5ce8fe07fe0dad0201b3c26d296f68c9c79309f22b0`。
- 当前产品策略把校准验收写死为 `e2e_pending`。该状态刻意拒绝普通
  `start` / `resume`，只允许一次处理一个精确条目的
  `start_one` / `resume_one`。
- 用户现已明确授权对批次 `#1` 剩余 9 项进行连续批量验收。

## 2. 目标

1. 将已经通过单岗位真实验收的 BOSS 沟通策略正式晋级为 `accepted`。
2. 让现有沟通页恢复使用原有完整串行模式，连续处理批次 `#1` 的剩余
   9 个不可变条目。
3. 保留现有逐岗位身份检查、一次点击、随机间隔、访问额度、登录/风控即停、
   结果不明即停和绝不自动重试。
4. 产出可覆盖安装且保留现有数据的 `0.1.0-beta.4.5` 本地安装包。
5. 批量验收结束或安全停止后，只读验收“消息发现”；不发送消息。

## 3. 非目标

- 不新增数据库字段、运行时配置、管理页面或校准状态机。
- 不复制或重建当前沟通批次，不改变 9 个待处理条目的顺序与身份。
- 不删除 `e2e_pending` 的单条防绕过代码；它继续作为未验收策略的安全路径。
- 不改变 BOSS 点击、结果判定、节奏、额度、固定标签或页面恢复逻辑。
- 不启用 `search_page_api`，不使用 `standalone_detail`，不启动 Wave 5。
- 不在实现、离线测试、构建或安装期间访问真实 BOSS。
- 不创建远端标签、不推送、不发布公开版本。

## 4. 最小方案

采用版本化静态策略晋级：

1. 把 `PRODUCT_POLICY.operations.bossCommunication.calibration.acceptance`
   从 `e2e_pending` 改为 `accepted`。
2. 继续复用现有 `communicationCalibrationStatus()`、应用服务、页面视图模型、
   CLI 和执行器；不增加新的分支或抽象。
3. 默认策略为 `accepted` 时，沟通页显示原有完整批次恢复动作，服务端允许
   普通 `resume`，隐藏 CLI 不带 `--single-item`，执行器继续串行选择剩余条目。
4. 现有 `e2e_pending` 防绕过测试继续通过依赖注入或明确测试夹具覆盖，防止以后
   误删单条验收边界。

不采用数据库开关或手工 HTTP/CLI 绕过。前者增加永久状态与迁移成本，后者破坏
产品安全门和可复现发布链。

## 6. 真实批量验收

安装并恢复后台后，重新读取当前 Edge 数值型标签 ID，确认：

- 同一窗口内只有固定 `BOSS-SEARCH` 与 `BOSS-COMMUNICATION` 两张 BOSS 标签；
- 搜索页、沟通页已登录且无风控；
- RoleFlow 页面显示批次 `#1` 的连续恢复动作；
- 9 个待处理条目和范围哈希未变化。

用户在 RoleFlow 界面启动一次连续恢复。执行期间串行观察数据库、日志和页面：

- 每项最多一次点击；
- 每项成功必须有现有精确网络或明确页面证据；
- 登录、风控、标签漂移、页面丢失、身份不符或结果不明立即停止；
- 停止后不自动重试，不手工推进后续项。

## 7. 消息发现验收

批量达到终态或安全停止点后，使用现有消息发现入口做只读验收：

- 读取固定沟通页和本地发现结果；
- 检查页面、计数、岗位关联和错误说明；
- 不点击发送、申请、沟通或其他外部写动作；
- 发现问题先记录与归因，不在真实页面上试错。

## 8. 验证

1. 先写一个会失败的策略/校准回归检查，证明默认验收状态必须为 `accepted`。
2. 验证 `accepted` 默认允许完整批次控制与页面动作。
3. 保留 `e2e_pending` 单项防绕过回归覆盖。
4. 运行沟通定向测试和完整离线套件。
5. 构建并验证 beta.4.5 安装器、阶段文件和哈希。
6. 覆盖安装并验证现有数据未变化。
7. 最后才进行用户授权的真实连续批量验收。
