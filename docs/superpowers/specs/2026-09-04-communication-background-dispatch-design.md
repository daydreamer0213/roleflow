# 后台沟通点击生命周期与失败证据收口

## 范围与依据

用户在 v1.3.1 的批次 #4 遇到一条成功、下一条无匹配请求后中断。当前任务是修复已复现的后台焦点模拟生命周期缺陷，并让下次失败可区分点击和结果观察环节；不能声称已经确定本次真实失败的唯一原因。用户在诊断建议后明确要求“继续”，按既定分工直接落实，不重复询问实现细节。

当前实际浏览器适配器每个 CDP 命令都建立并关闭连接。双本地页面对照显示：启用焦点模拟的连接关闭后设置消失，持有会话则持续有效。官方接口仅提供启停开关：https://chromedevtools.github.io/devtools-protocol/tot/Emulation/#method-setFocusEmulationEnabled 。会话生命周期结论来自本机实际对照，不由文档推断。

## 取舍

- 推荐：在现有 CdpBrowserAdapter 内，仅为已启用焦点模拟的标签保留连接，直到关闭模拟；期间命令复用该连接。所有现有调用者自动获得正确语义，不改公共调用接口。
- 不采用：给所有浏览器命令引入长期连接池，当前没有这种需求。
- 不采用：自动补点、前台激活或单纯延长等待；既不能证明根因，也会产生重复沟通或打断用户。

## 设计

1. `cdp(tabId, method, params)` 维持接口不变。启用焦点模拟后保留 WebSocket；关闭模拟在同一连接执行后释放。命令超时、连接失败或目标关闭时释放资源并报错，不重新建立连接重发动作。普通只读命令仍短连接。
2. 共享的 `sendCdp` 支持内部复用连接，逐条唯一命令编号、逐条超时和监听器清理。不增加依赖、通用连接管理框架或后台调度。
3. 通过现有最终 DOM 守卫注册单次只读点击回执，只记录目标点击是否观察到、是否浏览器可信事件、守卫/点击时焦点。只在原本将点击的已确认目标上观察，不改变点击次数和目标判断。
4. 结果中增加有限的脱敏诊断对象：点击回执、当前按钮状态、文档就绪和中间弹层状态。未观察到回执为未知，不推导为未发送。沿现有 outcome JSON 保存，不迁移数据库；执行器严格白名单过滤。
5. 无匹配请求仍按 ambiguous 中断，错误提示改成“未能确认本次沟通结果”，说明不代表发送失败，保留人工核对和剩余岗位处理入口。

## 验收与边界

- 真实本地 Edge + 两个 data: 页面复现旧实现失去焦点；修复后守卫和一次点击全程保持模拟，结束后恢复，异常/断开不自动重发。
- 假浏览器与临时数据库验证诊断透传、隐私白名单、无回执兼容、一次点击和歧义停止。
- 关键回归、全量严格离线门禁、独立只读复审与精确提交验证。
- 不改筛选、岗位分析、节奏、访问额度、账号风控或真实批次；不推送、合并、打包、发布或替换安装版。
- 真实 BOSS 直接原因和修复后真实效果仍需后续新证据，不能用本地通过替代。
