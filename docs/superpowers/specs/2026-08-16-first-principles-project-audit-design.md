# RoleFlow 第一性原则项目审计与精简设计

> 设计基线：`d50874166dde550e3fda2fe1b8eb235efecc7677`
> 设计日期：2026-08-16
> 本文只定义审计、分级和验证方法，不授权实施功能代码。

## 1. 结论

采用“安全边界先对齐，先恢复被迁移遗漏的有效职责，再删除已完成语义证明的死代码，其余职责只在以后独立课题实际触碰时迁移”的路线。

本课题不以拆分大文件或删行比例为目标。只有同时满足以下条件的代码才进入立即删除批次：

1. 当前产品入口不可达；
2. 没有安装、发布、诊断、恢复、质量评测或测试价值；
3. 没有动态入口、静态资源入口或兼容职责；
4. 能从代码和直接历史说明它原来解决的问题，以及该问题现在由谁负责；
5. 删除后能用最小自动检查证明受支持行为不变。

“当前没有调用”只用于产生审计候选，不能单独证明代码应删除。如果原职责仍然成立、但迁移后的新路径没有接住它，应先恢复职责并增加回归检查；如果原职责和替代关系说不清，则保留。

`src/dashboard/server.js`、`src/cli.js` 和 `src/adapters/sites/boss.js` 虽然集中，但不整体重写。三个文件只在后续独立课题触碰相关职责时做小范围迁移。

## 2. 第一性原则：RoleFlow 必须继续产生什么结果

以下结果和边界是精简时不可牺牲的项目价值。

### 2.1 用户结果

- 用户能在本机保存候选人画像、简历版本、匹配偏好和搜索方案。
- 系统能在安全节奏下采集岗位卡片，并通过当前唯一生产主线 `trusted_pane` 获取完整 JD。
- 系统基于 JD 和候选人事实生成有证据约束的推荐，不把未知事实编造成匹配或沟通内容。
- 扫描、分析、清单确认和沟通可以中断、恢复和追溯，已完成工作不会因进程退出而丢失。
- 消息发现保持只读；消息正文不长期保存，不自动填写或发送。
- 沟通只执行当前不可变清单中已明确授权的岗位，并逐项核验身份和结果。

### 2.2 安全不变量

- 真实 BOSS 默认只读；任何外部写都需要针对当前样本的明确授权。
- 只使用一个登录态和两个固定 BOSS 操作标签：`BOSS-SEARCH`、`BOSS-COMMUNICATION`。
- 每次操作前从当前浏览器绑定读取标签身份；不复用历史标签 ID。
- 扫描、JD、分析、消息读取和沟通运行期间禁止 `Page.bringToFront`、窗口激活和前台焦点恢复。
- 唯一例外是用户主动启动工作台且未指定 `-NoOpen` 时，`workspace-tabs` 在就绪检查结束后执行一次 `Page.bringToFront`：就绪时引导到 Dashboard，未登录时引导到 BOSS。该调用不得用于轮询、恢复、重试或后台浏览器操作。
- 登录、风控、页面丢失、标签漂移、目标不一致或结果不明确时立即停止。
- 随机节奏、周期冷却、访问预算、checkpoint 和不确定结果不重试必须保留。
- `search_page_api` 只保留为研究代码和失败证据，不从产品、扫描、校准或 Gate D 入口传入，不在本课题修复或验证。
- 不使用或重新引入 `standalone_detail`。

### 2.3 质量、数据和隐私不变量

- 不用减少卡片或 JD 覆盖换速度，也不静默降低召回和推荐准确度。
- 筛选实质变化后必须建立全新空 operational baseline；旧数据库只作恢复证据。
- 候选人资料、API Key、BOSS 登录态、日志和数据库继续遵守发布排除边界。
- 存储迁移、兼容门面、恢复逻辑、质量基准和安全测试不能仅因代码多而删除。

### 2.4 工程结果也属于项目价值

以下能力即使不出现在日常 UI 中，也不是天然的死代码：

- 安装、启动、卸载和发布打包；
- 本地自检、诊断和恢复；
- 离线质量基准及其标签校验；
- 数据迁移、快照兼容和回滚证据；
- 用于证明 BOSS 安全边界的离线测试。

## 3. 当前代码事实

### 3.1 规模和入口

- `src` 有 100 个 JavaScript 模块，共 38,985 行。
- 从 `src/cli.js` 的字面量 `require` 入口可达 97 个模块。
- `src/dashboard/assets/workflow.js` 通过 HTTP 静态资源入口使用，不能按 CommonJS 不可达判死。
- 真正不在生产入口中的源码模块只有：
  - `src/adapters/browser/index.js`；
  - `src/core/llm.js`。
- 三个集中文件合计 10,792 行，占源码约 27.7%；文件大本身不能证明其中职责应立即迁移。
- 直接生产依赖只有 `pdfjs-dist`；本课题没有可删除的直接依赖。

### 3.2 静态候选与语义审查结果

静态扫描找到 13 个“未导出、名称只出现于定义处”的函数。继续检查函数引入/失去调用的直接提交、当前替代路径和回归检查后，结果不是 13 个全部删除，而是 12 个删除候选和 1 个职责迁移候选：

| 候选 | 原来解决的问题 | 当前证据或接替者 | 结论 |
|---|---|---|---|
| `src/adapters/browser/index.js` | 预留统一浏览器基类和 Playwright 适配器 | 从初始提交起没有消费者；生产和测试直接使用 `edge_control`、`cdp` | 删除候选 |
| `src/core/llm.js#createGreeting` | 早期规则模板招呼语 | 生产沟通已由 `draftCommunication` 的双侧证据契约负责；旧函数只给 `self_check` 造 fixture | 删除候选，测试改用固定 fixture |
| `mock.js#inferSeniority` | 从 JD 文本猜岗位级别 | Mock 岗位理解已改为 `hiringTracks`，匹配阶段显式选 `selectedTrack` | 删除候选 |
| `boss.js#dedupeJobs` | 按岗位身份保留更完整记录 | 从初始提交起从未被调用；当前扫描分别由 `mergeUniqueCards`、`mergeScanCandidate`、`mergeBossJobFacts` 去重并保留详情 | 删除候选 |
| `boss.js#sanitizeCommunicationObservation` | 归一化沟通结果证据 | 结果核验已改为 `classifyBossCommunicationNetworkLog` 与页面状态分类，并保留不确定即停止语义 | 删除候选 |
| `cli.js#resolveKeywords` | 从命令行或旧配置取关键词 | 从初始提交起从未被调用；当前入口使用带优先级和来源的 `resolvePlannedKeywords` | 删除候选 |
| `job_analysis.js#resumeVersionsForJobMatch` | 把完整简历版本送入岗位匹配 | 当前稀疏契约使用 `candidateProfileForJobMatch` 和已确认匹配卡；现有测试明确要求不重复发送 `resumeVersions` | 删除候选 |
| `profile_schema.js#normalizeResumeVersion` | 从模型画像虚构/归一化简历版本 | 当前画像固定 `resumeVersions: []`；真实版本只由用户上传后进入 `candidate_store` | 删除候选 |
| `server.js#createUploadedMatchingCardDraft` | 上传简历后生成匹配卡草稿 | 持久化 onboarding 流程的 `processOnboardingRun` 已负责建卡、fallback、checkpoint 和重试，且有离线测试 | 删除候选 |
| `server.js#workflowStatusLabel`、`workflowShortfallLabel` | 给今日任务显示流程状态和候选不足原因 | 同名职责已迁到 `view_models/today.js` 并由页面使用 | 删除候选 |
| `server.js#hardBlockerLabels` | 把硬限制对象变成可显示文字 | `view_models/workflow.js` 构建 review rows 时已执行相同归一化 | 删除候选 |
| `server.js#keywordLines` | 把关键词结构转成表单文本 | `pages/today.js` 已接管相同格式化 | 删除候选 |
| `reports/render.js#formatConfidence` | 显示旧的数值置信度 | 四档推荐上线后，报告改用 `recommendationLabel` 和判定理由，不再把模型置信度当产品决策 | 删除候选 |
| `server.js#scanLabel` | 把扫描种类和运行状态翻译成人能看懂的进度文字 | 页面迁移后 `buildTodayViewModel` 虽收到 `run`，却只读取未传入的 `runLabel`，导致非空扫描状态仍回退成“尚未运行” | **不得直接删除；迁入 view model 并补回归检查** |

因此不再承诺“至少删除 157 行”。删行不是证明；本课题只删除表中完成语义证明的两个模块和 12 个函数。清理未使用导入和常量时也必须逐项经过相同检查，不能把词法扫描结果直接变成删除清单。

### 3.3 测试事实

- `tests/run_all.js` 直接注册 97 个离线检查文件。
- `tests/four_tier_decision_smoke.js` 没有直接注册，但由安装/本地自检入口 `tests/self_check.js` 执行，仍有实际价值。
- `tests/analysis_revision_smoke.js` 没有注册，也没有被其他测试加载；当前不会执行。
- 该孤立测试中的 revision 失效、策略哈希和薪资边界大部分已由 `semantic_pipeline_smoke.js`、`inherited_search_scope_smoke.js`、`screening_quality_smoke.js` 覆盖。
- 其中六个低薪边界组合仍有独立表达价值。设计要求把这六个紧凑用例迁入 `screening_quality_smoke.js`，再删除 130 行孤立测试；不保留虚构 104 行重复样本来制造覆盖规模。

### 3.4 启动引导例外

代码证据表明，当前 `Page.bringToFront` 不是扫描期间的焦点恢复：

- `scripts/start-workspace.ps1` 只在用户主动启动且未指定 `-NoOpen` 时调用一次 `workspace-tabs`；
- `src/core/workspace_tabs.js` 在就绪检查完成后只调用一次 `browser.bringToFront(...)`；
- 就绪时目标是 Dashboard，未登录时目标是 BOSS，目的是告诉用户下一步在哪里操作；
- 扫描、消息读取和沟通生产路径没有调用该方法，相关测试明确要求调用次数为 0。

因此保留两个浏览器适配器的 `bringToFront` 方法和启动调用。实施时只把规范改为“唯一启动例外”，并保留以下防扩散门：

- 生产调用点只能是 `src/core/workspace_tabs.js` 的启动收尾；
- 每次显式启动最多调用一次；
- `-NoOpen` 不调用 `workspace-tabs`，因此不聚焦；
- 扫描、消息读取、沟通、风控恢复和页面丢失恢复仍必须保持 0 次调用。

### 3.5 当前产品边界矛盾

静态证据确认一处当前代码与权威文档不一致：`src/dashboard/server.js`、`src/core/scan_execution.js` 和 `src/cli.js` 仍能把 `search_page_api` 传入正式扫描路径，相关默认测试也覆盖了该传递。

该路径可由 HTTP 参数或 CLI 参数触发，不是纯理论分支。设计把它列为实施前首先处理的边界一致性修正：

- 正式入口固定产生 `trusted_pane`。Dashboard 或 CLI 显式请求 `search_page_api` 时必须返回明确错误，不得静默降级后继续扫描。
- 历史快照若记录了 `search_page_api`，产品恢复入口必须停止并提示“该研究模式不能恢复，请新建 `trusted_pane` 扫描”；原快照和数据库证据不得删除或改写。
- `src/adapters/sites/boss.js` 中的 `search_page_api` 研究实现、历史快照识别和失败证据原样保留；本课题不进入该分支、不修复、不优化、不执行真实或模拟校准。

这部分只改变未受支持的实验入口行为，不改变受支持的 v1.0 产品结果。

## 4. 方案比较

### 方案 A：高置信减法，推荐

先修正明确安全边界矛盾，恢复迁移遗漏的扫描状态文字，再删除已证明无现行职责的模块、函数、导入和孤立测试。大文件职责只登记，不主动拆分。

优点：改动小、证据强、容易回滚；不把另外三个课题绑进一次重构。
代价：总行数下降有限，三个集中文件仍然存在。

### 方案 B：同时清理模块边界

除方案 A 外，再统一 export、合并短文件、抽取状态标签和通用路由。

优点：表面结构更整齐。
代价：大量改动只是在移动代码；会破坏测试 seam、兼容门面和后续课题的独立性，实际产品收益小。

### 方案 C：立即拆分三个大文件

按领域重写 Dashboard、CLI 和 BOSS 适配器。

优点：最终目录可能更理想。
代价：同时触碰扫描、JD、分析、沟通、安全和存储恢复，验证面过大；违反“不启动 Wave 5、不做全项目重写”的当前边界。

结论：只采用方案 A。方案 B、C 不进入实施计划。

## 5. 如何证明一项代码没有当前价值

### 5.1 模块

一个模块只有同时通过以下检查才能删除：

1. 不可从生产入口的静态依赖图到达；
2. 不由 HTTP 静态资源、子进程、PowerShell、批处理、安装器或发布工作流引用；
3. 不由测试、自检、诊断、恢复或质量脚本引用；
4. 顶层没有必须执行的注册、迁移或副作用；
5. 删除后的最小回归门通过。

### 5.2 导出和函数

- 未导出的函数必须在文件内没有调用。
- 必须查看直接历史，说明它原来保护的用户结果或工程结果；若从引入起就没有调用，也要确认它不是动态入口或待实现的受支持能力。
- 必须指出当前接替者以及接替者的回归检查；没有接替者时，只能在原职责本身已明确废止或从未成立时删除。
- 如果审查发现“旧函数仍有意义、只是新路径漏接”，应归入职责迁移，不得删除后掩盖回归。
- 导出项必须同时检查生产、测试和脚本消费者。
- 仅供测试使用的导出不是自动删除项；测试 seam 只有在对应实现一并删除或已有更小替代时才清理。
- 只减少 `module.exports` 中一个名字、但不能删除实现的修改不单独立项，避免制造无价值 diff。

### 5.3 脚本

脚本即使没有 `require` 调用，也可能是人工入口。删除前必须检查：

- `package.json`；
- 根目录 `.bat`、`run.ps1`；
- 安装器和 GitHub Release 工作流；
- 当前 README/运维入口；
- 测试和诊断调用；
- `require.main === module` 的独立命令用途。

当前没有脚本达到高置信删除标准。

### 5.4 测试

测试删除前必须回答：

1. 它是否由 `run_all.js` 直接注册，或由自检入口间接加载？
2. 它保护的是安全、质量、恢复、迁移、发布还是普通行为？
3. 同一不变量是否已在更合适的注册测试中覆盖？
4. 若有少量独有断言，能否先迁移到现有测试再删除文件？

测试行数不计入“越少越好”；只有不执行、重复且不再提供独有证据的测试才删。

## 6. 审计报告分级

每一项必须记录路径、证据、替代、风险和回归门，并归入以下一类：

| 分级 | 含义 | 当前例子 |
|---|---|---|
| 删除 | 当前入口不可达、原职责已有接替或从未成立，且没有独有价值 | 两个不可达模块、12 个完成语义证明的函数 |
| 缩短 | 行为保留，用已有函数或原生能力表达 | 未使用导入/常量；孤立测试迁移后删除 |
| 职责迁移 | 职责真实存在，原调用在迁移中漏接，或只应在后续课题触碰时移动 | `scanLabel` 迁入 today view model；Dashboard 消息/进度页面；CLI 扫描编排 |
| 保留 | 产品、安全、质量、恢复或兼容价值已确认 | BOSS 安全代码、存储门面、质量基准、发布脚本 |

报告不设置删行 KPI。预计删行只用于检查实际 diff 是否与已批准候选相符。

## 7. 实施批次与最小回归门

本节只定义批次边界；逐文件命令和操作顺序由用户确认本设计后的实施计划给出。

### 批次 1：浏览器边界一致性

范围：

- 保留用户主动启动时的一次性 `Page.bringToFront` 引导，并把权威规则改为这一处明确例外；
- 正式产品扫描只允许 `trusted_pane`；
- 保留 `search_page_api` 研究实现和历史证据，不进入该分支。

最小回归门：

- 静态扫描确认 `.bringToFront(` 的生产调用点只有 `src/core/workspace_tabs.js`；
- `workspace_tabs_smoke.js` 证明显式启动最多引导一次，并根据就绪状态选择 Dashboard 或 BOSS；
- 消息读取、扫描和沟通测试继续证明运行期间从不调用 `bringToFront`；
- 扫描参数测试证明 Dashboard 和 CLI 不能传入 `search_page_api`；
- 不运行任何直接进入 `search_page_api` 适配器分支的测试，不访问真实 BOSS。

### 批次 2：恢复扫描状态文字职责

范围：

- 把 `scanLabel` 的状态翻译职责迁入 `src/dashboard/view_models/today.js`，让 view model 直接根据 `input.run` 和活跃天数生成文字；
- 删除 server 中的遗留定义只能发生在新职责已接通且测试先证明回归之后；
- 不改变扫描状态机、执行节奏、预算、恢复逻辑或页面轮询行为。

最小回归门：

- view model 测试覆盖日常/广泛/补读/活跃度扫描的 running 和 completed 文案；
- 覆盖 `partial`、`failed`、`interrupted` 和 `idle` 的通用文案；
- 页面级测试证明持久化扫描状态不再错误显示为“尚未运行”；
- 不访问真实 BOSS。

### 批次 3：完成语义证明的死代码

范围：

- 删除 `src/adapters/browser/index.js`；
- 删除 `src/core/llm.js`，把自检所需 greeting 改为本地固定 fixture；
- 删除表中 12 个已完成语义证明的死函数；`scanLabel` 的 server 遗留定义属于批次 2 已验证职责迁移后的原位置清理，不计入死函数；

7. 没有新增依赖、框架、抽象层或大文件整体重写；
8. 所有修改均先验证后提交，且没有真实 BOSS 读写。
