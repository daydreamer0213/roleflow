# RoleFlow 专用 Edge 沟通能力补齐设计

## 背景与根因

2026-08-25 的批量沟通在首条岗位中断，实际错误为：

`TypeError: this.browser.startNetworkLog is not a function`

沟通执行原先依赖 Edge Control 的网络记录接口确认 BOSS 是否接受沟通请求。普通用户主线切换到专用 Edge 后，浏览器实现改为 `CdpBrowserAdapter`，但没有迁移 `startNetworkLog`、`getNetworkLogMark`、`readNetworkLog` 和 `stopNetworkLog`。沟通入口只检查了固定标签页生命周期，没有检查网络结果能力。

测试中的模拟浏览器直接实现了全部方法，因此掩盖了真实适配器能力不一致。执行器又出于防重复发送的安全考虑，在实际点击前先把条目标记为 `click_dispatched`；所以能力错误虽然发生在点击之前，数据库仍保守记录为 `ambiguous`。

## 现场结论

- 本次错误发生在 `clickAt()` 之前，本轮首条岗位没有执行实际沟通点击。
- 第一条之外的八条岗位均未尝试。
- 数据库的 `click_count=1` 是防重复发送账本，不是平台已经收到沟通的证据。
- 旧批次保持中断证据，不自动重试或恢复。

## 目标

1. 专用 Edge 提供与已验收沟通流程相同的网络结果观察能力。
2. 浏览器能力缺失必须在批次开始和任何点击账本变化之前失败。
3. 继续以“目标身份 + 页面结果 + 网络结果”验证真实沟通，不能为了兼容专用 Edge而降低安全标准。
4. 网络观察严格限域、限量、仅驻留内存，不持久化敏感 URL 参数或响应正文。
5. 保留一次点击、结果不明不自动重试、串行沟通和风险控制立即停止的规则。

## 非目标

- 不恢复依赖外部 Edge Control 的普通用户主线。
- 不用仅观察按钮文字变化代替网络结果。
- 不自动发送草稿，不扩大任何已确认批次的授权范围。
- 不对本轮旧批次做自动重放。

## 设计

### 1. 定义明确的浏览器沟通能力契约

沟通执行要求浏览器同时提供：

- 标签页列举、导航、DOM 读取和 CDP 命令。
- 后台坐标点击和焦点模拟。
- `startNetworkLog()`、`getNetworkLogMark()`、`readNetworkLog()`、`stopNetworkLog()`。

CLI 在绑定标签页、启动沟通 session 和修改条目状态之前完成能力预检。缺失时返回专用的兼容性错误，不进入批次执行器，因此不会产生假的 `click_count=1`。

### 2. 在 CdpBrowserAdapter 内实现原生网络观察

网络观察属于浏览器传输层，不放入 BOSS 站点逻辑。每个被观察标签页使用一个受控的长连接 CDP WebSocket：

1. 连接目标标签页并启用 `Network` domain。
2. 从启用成功后开始分配单调递增序号。
3. 只记录允许的 XHR/Fetch URL，当前仅沟通配置与加好友接口。
4. 记录请求开始、响应状态、完成或失败时间。
5. 仅对允许的少量响应读取受限正文，用于解析 BOSS 业务码。
6. 达到条数、正文数量或正文大小上限后停止扩张，不影响页面请求。
7. 验证完成或异常退出时执行 `Network.disable` 并关闭 WebSocket。

接口返回形状与 Edge Control 当前契约一致，使 `BossSiteAdapter` 无需按浏览器类型分叉。

### 3. 隐私与边界

- URL 过滤在内存记录前完成；非允许端点不进入日志。
- 不采集请求正文、Cookie、Authorization 或页面聊天内容。
- 响应正文只保留在内存中，受 `maxBodies` 和 `maxBodyBytes` 约束。
- 最终持久化证据只包含端点类别、HTTP 状态、BOSS 业务码类别和耗时；不保存查询参数或原始响应正文。
- 标签页关闭、浏览器断开或 stop 调用必须释放观察连接。

### 4. 保留保守点击账本

实际点击前写入 `click_dispatched` 是为了覆盖“点击已经发出但进程在落库前崩溃”的不可恢复窗口，这一安全顺序保留。

改进点是把所有可静态确认的能力检查和网络观察启动放在进入点击账本之前。只有网络观察已成功准备、岗位身份重新确认且执行许可仍有效时，才进入一次性点击边界。此后发生的任何不确定错误仍按 `ambiguous` 停止，禁止自动重试。

### 5. 旧批次处理

本轮批次同时包含一条保守歧义记录和一条不应进入的届别/实习岗位，不适合继续。它应保留为验收证据并废弃。资格规则和专用 Edge 能力修复后生成新批次，用户确认新快照后才能进行新的真实沟通。

## 测试与验收

离线回归必须覆盖：

- 真实 `CdpBrowserAdapter` 类具有完整网络观察接口，而不是只由假浏览器提供。
- 能力缺失在批次和条目状态变化前失败。
- CDP Network 成功、HTTP 失败、业务码失败、网络失败、无匹配请求和响应正文超限。
- 只记录允许的 BOSS 域名和端点，不泄露查询参数、响应内容或私密标识。
- stop、标签页丢失和浏览器断开均释放连接。
- 网络观察准备失败时 `clickAt()` 调用次数为零。
- 观察成功后仍保持一次点击、身份复核、后台执行和结果不明不重试。
- Edge Control 和专用 Edge 对站点适配器提供同一能力契约。

人工真实验收必须另行确认一个新的单岗位不可变批次。先执行一条，核对 BOSS 真实结果、RoleFlow 本地结果和网络证据一致后，才允许继续剩余新批次；该验收授权不继承本轮旧批次。
