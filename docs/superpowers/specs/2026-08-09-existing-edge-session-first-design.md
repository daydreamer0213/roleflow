# RoleFlow 普通 Edge 已登录会话优先设计

日期：2026-08-09
状态：用户已批准
目标分支：`codex/boss-pane-switch-repair`

## 1. 背景

RoleFlow 当前同时支持两种浏览器通道：

- `edge`：通过 Edge Control 扩展和本地桥接服务控制用户已经打开的普通 Edge；
- `portable`：启动带 `--remote-debugging-port=9222` 的项目专用 Edge，并使用独立的 `.runtime\edge-profile`。

本轮岗位详情修复在 `portable` 会话上进行真实只读验收时，项目专用 profile 的 BOSS 登录已失效。与此同时，普通 Edge 中已经存在两个登录成功的固定 BOSS 标签页：

- 一个 `/web/geek/jobs` 搜索页；
- 一个 `/web/geek/chat` 沟通页。

两个标签页位于同一窗口，Edge Control 桥接与扩展均健康，未检测到登录页或风控页。继续默认启动项目专用 Edge 会产生第二套 BOSS 会话并要求用户重复登录，因此浏览器接管策略需要调整。

## 2. 已批准的产品决策

RoleFlow 默认复用普通 Edge 中现有的已登录 BOSS 页面。

项目专用 Edge/CDP 保留为用户明确选择的备用模式，但：

- 不作为默认模式；
- 普通 Edge 不可用时不自动回退；
- 不允许在同一轮扫描、恢复或沟通批次中静默切换浏览器通道；
- 不允许为了回退自动创建第二套 BOSS 登录会话。

## 3. 范围

### 3.1 本阶段包含

- 普通 Edge 会话的只读就绪检查；
- 启动页、扫描接口和新继承工作流的默认浏览器参数改为 `edge`；
- 工作流和沟通批次继续使用已经冻结的浏览器权限；普通直接扫描继续由入口显式传参；
- 启动器默认检查/启动 Edge Control 桥，而不是启动项目专用 Edge；
- 工作台文案和显式备用入口调整；
- 普通 Edge 不可用时的失败关闭与可操作提示；
- 现有 `portable` 模式的显式兼容入口；
- 离线测试、整分支审查和隔离数据库上的真实只读验收。

### 3.2 本阶段不包含

- BOSS 沟通、发送、投递或申请动作；
- 自动登录、账号密码或验证码填写；
- 浏览器标签组创建或管理；
- 将 CDP 事后附加到已运行的普通 Edge；
- 把普通 Edge profile 复制到项目专用 profile；
- 修改岗位匹配、卡片覆盖、JD 覆盖或推荐阈值；
- 自动关闭用户普通 Edge 的任何标签页或窗口。
- 重写现有浏览器适配器、扫描编排器、恢复流程或沟通执行器。

标签组能力继续作为独立后续阶段。标签组只负责界面整理，不参与安全身份判断。

## 4. 核心安全边界

### 4.1 单一浏览器权限

继承工作流和沟通批次继续冻结一个浏览器权限：

```json
{
  "browserMode": "edge"
}
```

或用户显式选择备用模式时：

```json
{
  "browserMode": "portable",
  "cdpPort": 9222
}
```

运行中的单个进程不得从一种模式自动切换到另一种模式。工作流和沟通批次恢复时必须继续使用已经保存的模式。

普通直接扫描的现有执行快照不保存浏览器模式。本阶段不扩展该快照；每次直接扫描或恢复由调用入口明确传入模式，默认传入 `edge`，并且任何失败都不得在同一进程中自动改成 `portable`。

### 4.2 普通 Edge 标签页拓扑

默认 `edge` 模式只在以下条件全部满足时进入扫描：

1. Edge Control 桥和扩展健康；
2. 正好存在一个 `BOSS-SEARCH`：
   - host 是 `zhipin.com`；
   - path 是 `/web/geek/jobs`；
   - 搜索结果 DOM 可用；
3. 正好存在一个 `BOSS-COMMUNICATION`：
   - host 是 `zhipin.com`；
   - path 是 `/web/geek/chat`；
4. 两个标签页都有可信 `windowId`，且 `windowId` 完全相同；
5. 两个页面都没有登录失效、风控、验证码或页面丢失信号。

扫描只使用 `BOSS-SEARCH`。`BOSS-COMMUNICATION` 在只读扫描期间保持不动。

RoleFlow 不为岗位创建标签页，不创建第二个 BOSS 窗口，也不并行读取两个详情。

### 4.3 失败关闭

以下任一条件出现时立即停止，不自动回退到 `portable`：

- Edge Control 桥不可用；
- 扩展未连接；
- 缺少固定搜索页或沟通页；
- 标签页分布在不同窗口；
- 窗口身份缺失；
- 登录失效；
- 风控或验证码；
- 搜索页、详情页或目标岗位身份不匹配；
- 浏览器连接中断。

错误必须包含具体处理建议，例如：

- 打开或刷新 Edge Control 扩展；
- 在普通 Edge 中登录 BOSS；
- 保留一个搜索页和一个沟通页；
- 把两个固定标签放到同一窗口；
- 返回搜索结果页后重试。

错误提示不得建议系统自动启动项目专用 Edge。

## 5. 架构

### 5.1 复用现有浏览器权限链路

本阶段不新增浏览器权限抽象。继续复用现有：

- `createBrowser()` / `createDashboardBrowser()`；
- `EdgeControlAdapter` / `CdpBrowserAdapter`；
- `resolveWorkflowResumeBrowserMode()`；
- 工作流 planner 和沟通批次策略中的 `browserMode`；
- 沟通批次已有的浏览器权限继承和一致性校验。

只调整新运行的入口默认值：

1. 新运行未指定模式时使用 `edge`；
2. 用户显式选择 `portable` 时继续使用 `portable/9222`；
3. 已经保存 `browserMode` 的工作流或沟通批次继续使用原值；
4. `edge` 不可用时返回失败，不改写参数、不回退到 `portable`。

这样浏览器模式仍沿现有参数和 JSON 快照向后传递，不改变后续工作流的阶段、状态机或数据关系。

### 5.2 普通 Edge 就绪检查器

就绪检查通过现有 `EdgeControlAdapter` 读取：

- 标签列表；
- `windowId`；
- 当前 URL 的 host/path；
- 登录、风控和页面结构 DOM。

检查器只读，不导航、不点击、不创建标签页、不置换活动页。

它返回脱敏结果：

```js
{
  status: "ready",
  browserMode: "edge",
  searchTabId,
  communicationTabId,
  windowId
}
```

或稳定失败结果：

```js
{
  status: "not_ready",
  reasonCode,
  message
}
```

日志不得包含标题、公司、岗位 URL、JD、cookie、localStorage 或页面正文。

### 5.3 启动流程

默认启动流程调整为：

```text
Start.bat
  -> 安装/自检
  -> 检查或启动 Edge Control bridge
  -> 启动本地工作台
  -> 只读检查普通 Edge 固定 BOSS 标签
  -> 就绪时打开/复用同窗口的 RoleFlow 工作台标签
```

默认流程不得调用 `start-portable-edge.ps1`。

显式备用入口继续允许用户启动项目专用 Edge，例如：

```powershell
scripts\start-workspace.ps1 -BrowserMode portable
```

或工作台中的“项目专用 Edge（手动备用）”选项。

### 5.4 扫描和恢复

新工作流默认保存：

```json
{
  "browserMode": "edge"
}
```

工作流恢复必须验证：

- 当前请求模式与批次快照一致；
- 当前固定标签页满足同窗和登录要求；
- 搜索目标和筛选快照与批次兼容。

旧工作流或沟通批次冻结为 `portable` 时，不得在恢复时改成 `edge`。

普通直接扫描批次沿用现有恢复接口。恢复命令显式传入 `--browser edge`，并继续使用原来的执行快照、目标检查点和访问记录；不新增浏览器模式字段，也不改写历史快照。

### 5.5 沟通批次

新工作流默认使用 `edge` 后，其后创建的沟通批次继续继承并冻结 `edge`。

本阶段不改变任何沟通安全门禁：

- 首次真实校准点击仍需单独明确授权；
- 只有已确认的不可变清单可进入执行；
- 严格串行；
- 每个岗位都要核对身份和结果；
- 风控、登录失效、页面丢失或结果不明立即停止。

本阶段的测试和真实验收均不得执行沟通或投递。

### 5.6 对后续工作流的影响

后续工作流只接收不同的默认 `browserMode`，其余逻辑保持不变：

- 岗位冻结、详情读取、评分、推荐和队列生成不变；
- 扫描检查点和恢复算法不变；
- 沟通清单确认、校准门禁和串行执行规则不变；
- 历史工作流仍按已保存的浏览器模式恢复；
- 数据库结构和状态枚举不变。

因此这是入口和默认参数调整，不是工作流重构。

## 6. 用户界面

默认文案：

- `当前已登录 Edge（推荐）`
- `项目专用 Edge（手动备用，需要独立登录）`

普通 Edge 未就绪时，主操作按钮保持禁用，并显示具体原因。不得自动改变下拉框选择，也不得自动打开项目专用 Edge。

旧工作流恢复页继续显示其冻结模式：

- 旧 `portable` 工作流只能用 `portable` 恢复；
- 旧 `edge` 工作流只能用 `edge` 恢复；
- 新工作流默认冻结为 `edge`。

## 7. 数据和兼容性

不新增数据库列。

继续使用现有 JSON 快照和批次策略中的：

- `browserMode`；
- `cdpPort`（仅 `portable`）；
- 扫描执行快照；
- 沟通批次浏览器策略。

普通直接扫描的执行快照目前不包含浏览器模式，本阶段保持这一数据结构不变。

兼容规则：

- 明确保存为 `portable` 的历史工作流和沟通批次保持不变；
- 明确保存为 `edge` 的历史工作流和沟通批次保持不变；
- 缺少浏览器模式的旧记录沿用现有旧版兼容规则，不在迁移中批量改写；
- 只有新创建的运行默认值变为 `edge`。

## 8. 当前失败验收的处理

当前隔离验收批次由 `--browser portable` 启动，并因 `BOSS_LOGIN_REQUIRED` 中断。该普通直接扫描批次没有冻结浏览器模式，因此可以保留同一数据库和批次检查点，使用现有恢复接口显式改由普通 Edge 继续。

实施完成后：

1. 保留当前隔离数据库和批次 `#1`；
2. 确认普通 Edge 的两个固定 BOSS 标签同窗、已登录且无风控；
3. 使用 `--browser edge --resume-batch 1` 恢复；
4. 不再启动项目专用 Edge；
5. 继续遵守最多 10 张卡、最多 6 次详情的串行只读限制；
6. 验证至少一个非默认岗位通过 `standalone_detail` 成功；
7. 验证没有通信、投递、额外 BOSS 标签或第二窗口；
8. 验证正式数据库哈希完全不变。

临时启动的项目专用 Edge 只能在以下条件全部满足后关闭：

- 已确认普通 Edge 两个固定标签同窗、已登录且无风控；
- 已确认 9222 监听者属于本项目的 `.runtime\edge-profile`；
- 只关闭该项目专用实例，不关闭普通 Edge；
- 关闭前记录标签数量和进程身份，关闭后确认 9222 已释放。

## 9. 测试策略

### 9.1 浏览器权限单元测试

- 新直接扫描和新工作流的入口默认传入 `edge`；
- 显式 `portable` 保留 `9222`；
- 已冻结的工作流和沟通批次不可切换；
- 普通直接扫描恢复继续使用原目标快照和检查点；
- `edge` 不可用时不返回 `portable`；
- 未知模式失败。

### 9.2 普通 Edge 就绪测试

- 两个固定 BOSS 标签、同一可靠窗口时通过；
- 缺搜索页失败；
- 缺沟通页失败；
- 多个搜索页或沟通页失败；
- 跨窗口失败；
- 缺失 `windowId` 失败；
- 登录页失败；
- 风控页失败；
- 搜索 DOM 缺失失败；
- 检查过程没有导航、点击或创建标签。

### 9.3 启动和工作台测试

- 默认启动不调用 `start-portable-edge.ps1`；
- 默认启动检查 Edge Control；
- 工作台新扫描默认传 `--browser edge`；
- 显式备用才传 `--browser portable --cdp-port 9222`；
- 新继承工作流默认保存 `edge`；
- 恢复继续使用冻结模式；
- 普通 Edge 不可用时显示可操作错误，不自动回退。

### 9.4 扫描和批次测试

- 普通 Edge 中只使用固定搜索标签；
- 独立详情继续在同一搜索标签串行导航；
- 固定沟通标签保持不动；
- 不创建岗位标签；
- 访问模式、额度、检查点和脱敏审计保持现有修复后的契约；
- 新沟通批次继承工作流的 `edge` 权限，但不执行任何沟通动作。

### 9.5 完整验证

- 所有聚焦测试通过；
- 完整离线测试通过；
- `git diff --check` 无输出；
- 独立整分支代码审查无 Critical 或 Important；
- 当前隔离数据库从原检查点恢复后的真实只读验收通过；
- 正式数据库哈希不变；
- 普通 Edge 最终仍保持两个同窗固定 BOSS 标签；
- 没有通信、投递、登录填写或风险页面。

## 10. 回溯和合并顺序

1. 保留当前 `checkpoint/pre-live-boss-detail-acceptance-20260809`，记录旧 `portable` 验收前状态；
2. 在浏览器策略实施前建立新的 Git 检查点；
3. 浏览器策略作为独立提交序列实施和审查；
4. 普通 Edge 真实只读验收前再建立检查点；
5. 验收通过后，在 `main` 建立阶段二合并前标签；
6. 使用 `--no-ff` 合并修复分支；
7. 在合并后的 `main` 再跑完整离线测试；
8. 不删除修复分支、工作树或检查点标签，除非用户另行明确要求。

## 11. 成功标准

本设计完成的判定条件是：

- 普通 Edge 是所有新运行的默认浏览器；
- 已登录的固定 BOSS 页面被直接复用；
- 普通 Edge 不可用时停止并提示，不自动启动项目专用 Edge；
- `portable` 只能由用户显式选择；
- 同一运行不会跨浏览器模式切换；
- 岗位详情修复继续满足精确身份、串行访问、额度恢复和隐私要求；
- 新隔离库的真实只读验收至少产生一个 `standalone_detail/succeeded`；
- 正式数据库不变；
- 完整测试和独立审查通过；
- 合并前后都有可回溯检查点。
