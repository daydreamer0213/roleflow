# Gate D 共享访问账本与条件验收收口设计

**日期：** 2026-08-13
**状态：** 已由用户批准按推荐方案实施

## 背景

2026-08-12 的 Gate D 验收为校准、重试和正式运行创建了多个全新 operational baseline。岗位数据必须按规则隔离，但 BOSS 账号的真实访问次数和风控状态属于同一个外部账号，不能随着数据库切换而清零。

现有实现把两类数据都记录在当前 operational database：

- 岗位、JD、分析结果和工作流状态；
- `site_access_events` 与 `site_runtime_states`。

因此，更换 baseline 后，程序只看到新数据库中的访问记录，无法约束同一账号在此前 baseline 中已经发生的访问。这个缺陷在反复创建空 baseline 的验收环境中会真实触发；普通用户持续使用同一个数据库时通常不会触发。

本轮还确认了一个独立 UI 问题：队列岗位卡片会把内部参数名
`multiBusinessDistrict` 直接显示给用户。底层风险记录有诊断价值，但不应成为岗位卡片的主风险文案。

## 决策与边界

1. 新增显式 `--access-ledger-db <path>` 参数，只供真实校准和 Gate D 等需要跨 baseline 的运行使用。
2. 未传该参数时，产品继续使用当前 operational database 作为访问账本，保持既有行为不变。
3. 传入参数时：
   - 预算判断、风险恢复模式和幂等键检查读取共享账本；
   - 每次成功预留先写共享账本，再向当前 operational database 写一份审计记录；
   - 风控事件和站点暂停状态同时写入共享账本与当前 operational database；
   - 共享账本无法打开时，在创建浏览器或访问 BOSS 前失败关闭。
   - 参数缺少文件路径时直接报错，不得创建名为 `true` 的空账本；
   - Windows 下同一文件路径按不区分大小写识别，避免重复打开和重复计数。
4. 共享账本按 BOSS 账号隔离。下一次验收若更换账号，必须使用新的账本文件，不能复用原账号账本。
5. 不改变 `trusted_pane`、关键词、详情上限、JD 覆盖、随机节奏和冷却策略。
6. `search_page_api` 继续冻结为后续拓展任务，本轮不修改、不启用、不做真实验收。
7. 不引入独立详情页，不重新验证或修改前台激活行为。
8. Dashboard 只在展示层移除 `multiBusinessDistrict`；若同一内部风险中还有其他未解析参数，其他参数仍可展示。数据库中的原始风险保留。

## 数据流

一次允许的 BOSS 只读动作按以下顺序执行：

1. 共享账本开启事务并读取当前账号的历史访问；
2. 依据已有 normal / recovery / locked 模式判断预算；
3. 把预留事件写入共享账本并提交；
4. 把同一事件写入当前 operational database，供本轮报告和排查；
5. 才允许调用浏览器执行实际动作。

如果第 3 或第 4 步失败，浏览器动作不执行。共享账本已经写入但 operational audit 失败时，宁可保守地多计一次，也不能少计一次。

风控信号发生时，先写共享账本，再写本轮 operational database。即使本轮 baseline 永久排除，共享账本仍保留账号级风险状态。若持久化本身失败，运行仍必须按原始风控错误完成中断收尾；持久化失败另行记录，不能把 scan run 留在运行中。

## 兼容性

- CLI 默认行为完全不变；
- 共享账本复用现有 SQLite schema 和访问预算函数，不新增第二套风险算法；
- 旧 baseline 仍保持只读证据，不自动混入质量评测；
- Gate D 导出仍只读取正式 baseline，不从共享账本读取岗位或分析结果。

## 验证

离线回归至少覆盖：

1. 两个不同 operational database 共用一个账本时，第二个 baseline 能看到第一个的预算消耗；
2. 共享账本中的预留事件也写入当前 baseline 的审计记录；
3. 风控事件同时进入共享账本和当前 baseline；
4. 未显式指定共享账本时，旧行为保持不变；
5. 队列岗位卡片不显示 `multiBusinessDistrict`，但保留其他真实风险；
6. 不调用浏览器、不访问 BOSS 的完整离线套件通过。

## 本轮验收结论边界

本轮使用已抓取岗位继续完成模型分析和本地页面验收，不把中断的抓取数据库当作正式 Gate D 样本。BOSS 固定标签缺失后不自行创建或恢复标签，因此消息页真实少量读取记为环境条件，不能据此宣称完整端到端通过。

达到以下条件后，本轮可记为“有条件通过”：

- 现有岗位分析结果可追溯；
- Dashboard、队列、自动沟通入口和消息页本地只读页面通过；
- 不发生真实沟通或发送；
- 共享访问账本和本轮真实 UI 缺陷完成离线验证；
- 代码提交并推送；
- 等账号冷却或切换账号后，再使用账号对应的共享账本完成一次全新正式 Gate D。
