# RoleFlow 工作流正确性与安全恢复设计

**日期：** 2026-08-13
**状态：** 概念方案已获用户确认，书面规范待用户复核
**所属：** beta.4 人工验收整改子项目 A

## 1. 目标

在不放松外部动作安全门的前提下，使只读导航、页面误操作和暂时性页面问题可以
恢复；同时修复继承模式校验、进度统计、沟通标签冲突、歧义结果语义和 HR 主动
入站断点。

本设计不修改 `trusted_pane` 的详情激活方式，不新增详情采集路径，也不执行真实
沟通。

## 2. 安全分级

### 2.1 自动恢复一次

仅适用于能够证明尚未发生外部写动作的情况：

- 固定标签仍存在于原窗口，但用户把搜索标签导航到同源的其他 BOSS 页面；
- 页面加载尚未稳定；
- 页面 helper 在导航后尚未注入；
- 消息标签仍为原数值 ID，但暂时不在 `/web/geek/chat`；
- 浏览器桥接发生一次短暂只读超时。

恢复必须满足：

1. 使用原始数值 `tabId` 和 `windowId`，传回桥接时不得转换为字符串；
2. 标签仍在已绑定窗口；
3. URL 仍为 `https://www.zhipin.com`；
4. 登录和风控检查通过；
5. 使用工作流或沟通批次中已冻结的可信 URL；
6. 对新增导航计入现有访问预算和安全账本；
7. 最多自动恢复一次，第二次失败转为暂停。

### 2.2 暂停当前阶段或处理当前条目

适用于尚未点击，但不能安全继续的情况：

- 岗位身份在点击前不匹配；
- 操作元素在稳定等待后仍不存在；
- 搜索或消息标签存在，但身份无法恢复；
- 桥接持续不可用；
- 只读消息目标在打开前后漂移。

岗位本身不可用或身份不匹配时，按现有 item 终态记录并继续下一条；浏览器权威
或页面身份无法确认时，暂停当前批次，保留所有检查点，不结束已完成的采集和
分析。

### 2.3 硬停止外部动作

以下情况不得自动恢复外部动作：

- 登录失效或出现平台风控；
- 固定标签丢失、换窗或被重新绑定；
- `click_count > 0` 后结果不明确；
- 点击审计、批次摘要或条目状态不一致；
- 可能产生重复沟通的任何情况。

硬停止只冻结 BOSS 外部动作执行器。已经完成的岗位采集、分析和清单继续保留。

### 2.4 用户修复后显式恢复

“硬停止”不等于永久作废整轮。用户误关或误导航固定标签后：

1. RoleFlow 保留工作流、扫描检查点、沟通条目和访问账本；
2. 页面说明需要重新打开的两个固定页面；
3. RoleFlow 不自动创建标签、不自动换窗、不自动切换 browser authority；
4. 用户在同一个已登录 Edge profile 中重新准备好一个搜索页和一个消息页；
5. 用户点击“重新检查浏览器页面”后，RoleFlow 重新核验登录、风控、同窗、搜索
   范围和消息页身份；
6. 扫描只读阶段可以沿用现有恢复批次继续未完成目标；
7. 沟通阶段只有所有已点击条目都已得到人工处理，且当前没有
   `click_dispatched/ambiguous` 条目时，才允许为剩余 pending 条目显式建立新绑定；
8. 风控状态未解除时，即使页面恢复也不能继续。

每次显式重新绑定增加 `bindingGeneration` 并写入脱敏审计。它是用户发起的恢复，
不是自动重试，也不改变已确认岗位清单。

## 3. 继承模式校验

`validateSearchPlan()` 增加显式采集上下文，不再用
`validatePlatformCities=false` 同时表达两个不同含义。

规则：

- `acquisitionMode="inherited"`：
  - 城市、区域、平台薪资档等来自已验证的当前搜索页；
  - Search Plan 中的城市可以为空；
  - 仍要求至少一个目标方向和至少两个关键词；
  - 仍校验薪资上下限、排除词冲突和扫描预算。
- `acquisitionMode="generated"`：
  - 继续要求至少一个城市；
  - 继续校验 BOSS 城市代码。

Dashboard 按钮、阻塞提示、服务端启动和 CLI 恢复必须调用同一规则。不能只解禁
前端按钮。

## 4. 阶段化进度与“剩余工作”

### 4.1 数据来源

不新增第二套进度账本，复用：

- 冻结扫描快照中的目标列表；
- `scan_target_results` 的每目标最新结果；
- 当前批次岗位与完整 JD 覆盖；
- `workflow_job_tasks` 的分析状态；
- `communication_batch_items` 的沟通状态。

工作流进度快照增加只读分项：

```text
scanTargets: total / completed / pending / partial / failed
details: collected / read / pending
analysis: total / succeeded / running / retryPending / detailRequired / failed
communication: total / pending / ambiguous / succeeded / stopped
```

### 4.2 页面语义

“剩余工作”不再把不同阶段盲目相加，而是显示当前阶段的真实主待办：

- 扫描中：`还需完成 X 个搜索目标；Y 个详情待读取`；
- 分析中：`还有 X 个岗位待分析；Y 个岗位待补详情`；
- 等待确认：`已准备 X 个候选岗位，等待你确认清单`；
- 沟通中：`还有 X 个岗位未执行；Y 个结果待人工确认`；
- 完成：`本轮没有未完成工作`。

详情待补和分析待处理始终分列，避免把同一岗位重复计入一个不透明总数。

前端轮询与首次服务端渲染使用同一个 view model 计算函数，防止刷新前后数字不一致。

### 4.3 控制文案

- 运行中“下一步”显示：`系统正在继续处理，无需操作`。
- 安全冷却显示恢复时间。
- “暂停本轮”保留为次要按钮，不再获得主要操作标记，也不在轮询时自动聚焦。
- 所有沟通枚举通过统一中文映射输出；未知状态显示“状态待确认”，同时在诊断页
  保留原始枚举。

## 5. 沟通歧义的恢复语义

现有 `communicationAmbiguityState()`、人工证据表单、
`resolveAmbiguousCommunicationItem()` 和
`resumeInterruptedCommunicationBatch()` 继续作为唯一安全门，不新建第二套状态机。

当执行器收到 `COMMUNICATION_RESULT_AMBIGUOUS` 并把条目转为 `ambiguous`：

1. 条目记录保持 `ambiguous`，`click_count` 不变；
2. 批次保持可恢复的 `interrupted`；
3. 工作流存储状态可以保持 `interrupted`，但 view model 必须派生为
   `needs_resolution`；
4. 页面标题显示“等待人工确认沟通结果”，不得显示“沟通失败”；
5. 剩余 pending 条目不执行；
6. 只显示“确认已沟通”或“标记停止”，并要求可核验的本地说明；
7. 所有歧义条目处理完后，复用现有 resume 路径继续剩余条目；
8. 不允许自动重试已经点击的岗位。

普通浏览器中断且所有进行中条目 `click_count=0` 时，现有恢复逻辑可以把
`opening/verified` 退回 `pending`。该恢复与点击后的歧义恢复必须继续严格分离。

## 6. 固定双标签职责

本节只改变 `browserMode="edge"` 的普通 Edge 双标签产品路径。
`browserMode="portable"` 继续作为用户显式选择的备用 authority，保持当前绑定和
登录隔离，不自动回退、不借本次整改改变其标签模型。

### 6.1 角色

- `BOSS-SEARCH`：采集阶段使用搜索页；沟通阶段临时承载本来就必须打开的少量
  沟通岗位详情。
- `BOSS-COMMUNICATION`：始终保留 `/web/geek/chat`，供结果核验和消息只读发现。

不创建第三个标签，不创建每岗位标签，不切换浏览器 profile。

### 6.2 不可变绑定

普通 Edge 沟通在任何点击前建立以下持久化运行绑定：

```text
browser.mode
browser.windowId
browser.searchTabId
browser.messageTabId
browser.searchReturnUrl
browser.searchScrollTop
browser.bindingGeneration
```

`windowId` 和两个 `tabId` 必须是 Edge bridge 返回的原始数值。绑定写入
`communication_batches.runtime_json`，与不可变的岗位/政策 `policy_json` 分离。
首次执行只允许从空 runtime 原子写入；恢复时只允许核对同一代绑定。用户按
2.4 节显式恢复时，才允许在无未决点击的前提下增加一代绑定，并保留上一代审计。

`searchReturnUrl` 必须是当时固定搜索标签的完整可信 BOSS 搜索 URL，且与工作流
冻结的 `searchScope` 具有相同来源、路径和筛选范围。`searchScrollTop` 只保存
非负数值，不保存 DOM 或页面内容。

### 6.3 沟通生命周期

整批沟通只建立一个串行浏览器会话：

1. 核对两个固定标签和窗口；
2. 核对搜索返回地址与冻结搜索范围；
3. 在搜索标签导航到第一条的可信岗位详情；
4. 执行现有身份复核、最多一次点击和结果观察；
5. 当前条目得到明确终态且仍可继续时，直接导航到下一条可信岗位详情，不先往返
   搜索页；
6. 批次完成、达到目标、用户暂停、明确失败、歧义或其他异常时，在外层
   `finally` 中把搜索标签恢复到 `searchReturnUrl`；
7. 页面稳定后，把已保存滚动位置限制在当前可滚动范围内恢复；
8. 再次确认搜索标签和消息标签身份；
9. 只有恢复完成，批次进程才允许报告本次浏览器会话已经安全收尾。

滚动容器结构改变时，URL 和筛选恢复仍可成功；页面显示“列表位置已重置”，不把
滚动恢复失败误报为沟通失败。

点击后发生歧义时立即终止后续条目并执行搜索页恢复，然后等待用户在未被占用的
消息标签核验。

一次批次会话最多增加一次搜索页恢复导航。不得为了“每项都回到首页”增加岗位间
往返；岗位详情访问次数仍只等于实际处理的沟通条目数。

异常重启时，只有当前代的原数值标签、原窗口和冻结策略同时匹配，才能先恢复搜索
页再允许用户继续。标签缺失或换窗先停止，不创建替代标签；用户重新准备页面后按
2.4 节显式建立下一代绑定。

这不是 `standalone_detail` 采集：它不参与批量 JD 读取，岗位详情访问次数只等于
用户已确认的沟通条目数。

## 7. HR 主动入站机会

### 7.1 现有能力

继续使用 `message_discovery_unresolved_items` 保留未匹配会话，并保持：

- 不保存招聘者姓名；
- 不保存消息正文、完整 header、DOM、Cookie 或请求参数；
- 不自动生成或发送回复；
- 单个未匹配会话不阻塞后续有效会话。

### 7.2 本地确认信息

对 `possible_hr_reply` 且无法匹配本地卡片的会话，未解决记录增加当前 reader 已经
核验的岗位字段：

- 岗位标题；
- 公司；
- 薪资；
- 城市；
- 这些字段的组合摘要。

岗位标题必须存在；公司缺失或岗位身份前后漂移时只能继续保持未解决，不能创建
机会。招聘者身份和消息正文仍不得落库。

### 7.3 用户处理

消息页为每条未解决入站提供三个本地动作：

1. **关联现有岗位**：列出标题和公司一致的本地候选；有多个时必须由用户选择。
2. **保存为 HR 主动机会**：以 conversation digest 生成稳定的本地 source ID，
   创建一个不参与自动沟通的岗位和 `needs_user_action` 进度卡。
3. **不纳入 RoleFlow**：明确确认后提交 preview baseline，记录脱敏审计并清除
   未解决标记。

前两个动作必须在一个事务中完成岗位、进度卡、thread key、审计和未解决清理；
失败时全部回滚。新机会不得自动加入沟通批次，也不得自动回复。

保存为主动机会需要当前候选人已有活动筛选方案；没有方案时保持未解决并引导用户
先完成筛选方案。主动机会不创建扫描批次或岗位 observation，不进入 Gate D、
推荐规则或采集覆盖统计；求职进展页必须通过进度卡直接读取并展示它，不能依赖
扫描决策池间接出现。

处理成功后，下次只读发现可以按现有消息分类流程生成本地草稿。

## 8. 回归合同

### 8.1 校验与进度

- 空城市的 inherited 方案通过；同一方案的 generated 模式失败。
- 少于两个关键词、薪资上下限反转和排除词冲突在两种模式都失败。
- 7 个详情待补且模型 pending 为 0 时，页面不得显示剩余 0。
- 沟通批次 `ambiguous=1,pending=1` 时显示“1 个待人工确认、1 个未执行”。
- 运行中下一步不是“暂停本轮”，暂停按钮不自动聚焦。
- 工作流页和沟通页不显示 raw English status。

### 8.2 沟通

- 普通 Edge 沟通不调用 `createTab()`，不导航消息标签。
- 搜索标签在整批成功、达到目标、用户暂停、明确失败、点击前异常和点击后歧义中
  都只执行一次收尾恢复。
- 搜索恢复失败时不继续下一条。
- 原始数值 tab/window ID 原样传入桥接。
- 未决点击存在时禁止重新绑定；全部人工处理后才允许用户显式增加 binding generation。
- 点击后歧义仍最多一次点击，人工处理前 resume 被拒绝。
- 点击前可恢复错误最多重试一次；风险、登录和绑定漂移不重试。

### 8.3 消息

- 无本地卡片的 HR 主动会话保存脱敏岗位信息并继续处理后续队列。
- 缺岗位标题或身份漂移时不能导入。
- 关联、创建和忽略均不调用模型、不填写页面、不发送消息。
- 新建机会进入 `needs_user_action`，不进入自动沟通候选。
- 新建机会不产生 scan batch/observation，也不进入质量评测。
- 数据库、日志和公共 API 均不出现招聘者姓名或消息正文。

## 9. 验收

先运行聚焦回归和完整离线套件。离线通过后，真实 Edge 只允许：

1. 核对两个固定标签仍在同一窗口；
2. 使用一个数据库中已保存的岗位 URL，让搜索标签只读进入详情；
3. 不点击沟通按钮；
4. 恢复原搜索 URL 和滚动位置；
5. 核对消息标签始终停留在聊天页；
6. 少量运行消息只读发现，确认未解决入站能显示安全岗位身份。

任何登录、风控、标签或窗口漂移立即停止。真实沟通成功/歧义路径不在本轮自动
复测中。

## 10. 不在本子项目范围

- 修改 `trusted_pane`；
- `search_page_api`；
- 新增第三个 BOSS 标签；
- 真实沟通点击；
- 自动回复 HR；
- 为历史任意已读会话批量建卡；
- 更改 JD、推荐和扫描覆盖规则。
