# 岗位分析：用户主视图、重试状态与积分影子评估设计

日期：2026-08-25

## 目标与边界

本阶段不推翻现有岗位分析链路，而是在当前代码事实之上解决三个相互关联、但可以分别验证的问题：

1. 主视图先给用户可行动的结论，再自然回答岗位做什么、公司做什么、候选人是否匹配、薪资如何，以及现有资料能支持的公司机会评价；
2. 将“本轮曾经失败”与“当前仍未解决”分开表达，保留失败历史，同时让重试成功后的当前状态恢复为已完成；
3. 建立一条真正独立的积分影子路线，用冻结样本和后续重复模型样本比较稳定性、安全性与人工判断一致性，在获得证据前不切换生产判定。

本阶段不扩建公司情报系统，不新增外部公司调查，不改变 BOSS 浏览行为，不让影子积分影响岗位筛选、推荐、沟通或其他生产流程。

## 当前代码与数据证据

### 生产路线不是纯二维表，而是“模型抽取 + 本地量化 + 二维表”

当前语义模型主要输出职责、要求的匹配状态以及所选岗位路线。随后本地代码确定性地计算：

- 职责得分和覆盖率，并将其归入职责对齐等级；
- 核心要求与辅助要求的加权匹配度，其中核心要求权重为 70%，辅助要求为 30%；
- 匹配状态分值，其中匹配为 1、可迁移为 0.5、缺失为 0；
- 最终匹配档位，再通过“职责对齐等级 × 匹配档位”的二维表得到生产决策；
- 证据不足、职责方向错误、硬性要求不满足等上限或降级规则。

因此，生产结果的可重复部分已经量化。剩余漂移主要来自上游模型对职责、要求和岗位路线的抽取，而不是二维表本身。单纯把最终二维表替换成一个总分，不能自动消除模型抽取漂移。

### 现有“影子积分”不是独立候选路线

现有 `shadow_scorecard` 仍调用生产二维表判定，只在外层增加硬边界和证据保护。当前离线 Gate D 夹具共有 51 条原始样本，其中 43 条可用于质量比较，但 51 条人工标签都仍是待确认状态。

在当前样本上，生产二维表和现有影子结果的档位分布完全一致，协议一致率为 100%。这只能证明影子包装没有改变结果，不能回答“二维表与积分谁更稳定、谁更准确”。由于没有已确认人工标签，也不能据此判断任何路线更接近用户判断。

### 当前主视图已有足够字段，但展示顺序偏内部

岗位数据已经普遍包含公司名、薪资、匹配理由和风险，较新的完整分析还包含岗位职责摘要、行业背景、岗位质量与隐藏风险。当前主卡主要突出元数据、决策标签和原始匹配理由，更完整的岗位职责和“决策来源”放在展开区。

本地当前数据没有独立的公司业务场景字段，但多数完整分析已有行业背景。因而第一阶段可以使用公司名、行业背景、岗位职责和岗位质量生成有边界的自然评价，无需再发起公司调查或增加模型调用。

### 重试成功后的当前健康状态与历史任务状态来自不同事实源

当前健康检查以同一计划下最新岗位观察为依据，能够判断岗位当前是否已经完成语义分析。对本地现有两条“首次模型分析失败、队列重试成功”的岗位，健康检查目前不会再误报 `analysis_incomplete`；旧问题在当前代码和数据中无法直接复现。

但流程进度仍按原始工作流任务统计历史成功或失败，因此页面仍会显示“分析失败 2”，即使这两条都已通过后续重试解决。这里不是删除历史失败，而是需要明确区分两个事实：

- 历史事实：本轮首次执行是否失败；
- 当前事实：该岗位的最新分析是否仍未解决。

同时需要加入回归检查，防止健康检查未来再次把已解决的历史失败当作当前未完成。

## 设计一：面向用户的岗位结论主视图

### 信息顺序

主视图统一按以下顺序组织：

1. **结论**：是否值得优先推进，以及最重要的一句话原因；
2. **岗位**：这个岗位主要做什么；
3. **公司与机会**：公司处于什么行业、该岗位在业务里的可能位置，以及现有资料支持的机会评价；
4. **匹配度**：候选人的主要匹配点和最值得注意的缺口；
5. **薪资**：原始薪资范围；
6. **风险与下一步**：需要确认的事项和建议动作。

主视图不显示“二维表”“积分”“匹配依据”“决策来源”等内部机制标题。现有的证据计数、决策来源和详细分析不删除，继续放在展开区供排查和复核。

### 内容来源与自然降级

- 岗位描述优先使用结构化岗位职责摘要；缺失时使用现有标题和可用职责信息，避免编造具体工作；
- 公司描述使用公司名和已有行业背景；行业背景缺失时，只说明从当前岗位资料可以确认的内容；
- 公司机会评价结合岗位职责、行业背景和岗位质量，表达为自然短句，不单独设置生硬的免责声明标题；
- 匹配度使用已有匹配理由、职责对齐结果和风险，不向用户展示内部打分过程；
- 薪资直接保留招聘页面提供的原始范围，不换算或推测未提供的奖金、股权和福利。

为控制改动范围，第一阶段在现有 Dashboard 渲染边界内建立窄的展示投影，不重构分析模型，也不复制消息发现模块的完整视图结构。

## 设计二：失败历史与当前状态分离

### 状态语义

流程进度增加三个清晰计数：

- `historicalFailed`：本轮首次分析任务失败数，作为历史证据永久保留；
- `resolvedAfterFailure`：首次失败但最新岗位分析已经完成或形成明确阻断结论的数量；
- `unresolvedFailed`：首次失败且当前最新分析仍未完成的数量。

对单条岗位任务也使用相同语义：原始任务状态仍是历史状态；若最新计划观察已经完成，则显示“首次失败，后续已解决”，而不是笼统显示“失败”。

### 事实归属

- 历史失败来自不可变的工作流任务或分析尝试记录；
- 当前解决状态来自同一计划下最新岗位观察和当前分析结果；
- 健康检查继续只用最新状态判断当前是否缺失语义分析；
- 历史失败记录、分析尝试和错误证据均不删除、不覆盖。

当最新观察不存在、属于其他计划、仍要求语义刷新，或数据之间无法安全对应时，保持“当前未解决”，不乐观推断为已完成。

## 设计三：真正独立的积分影子路线

### 候选积分

新增的积分候选只在离线评估脚本中运行，复用已经存在并可追溯的中间量，而不是重新调用模型：

- 职责匹配得分；
- 核心与辅助要求的加权匹配度；
- 职责和要求的证据覆盖率；
- 已确认的硬边界、严重风险和职责方向错误；
- 当前岗位分析中的缺失、可迁移和匹配状态。

首个候选版本以现有的“职责 40% + 要求 60%”联合匹配度作为连续分数起点，阈值是待验证假设，不作为新的产品真理。积分先映射为四个候选档位，再应用不可被总分抵消的保护规则：

- 硬性边界或职责方向明显错误时不得被高分提升；
- 关键证据不足时最高只能进入谨慎档；
- 核心要求确认缺失时不得因辅助项高分而进入高优先级；
- 未知状态不能当作零风险或已满足。

这些保护规则与连续积分分开统计，使报告能看清“原始积分建议”和“安全保护后的候选结果”，而不是把所有差异藏进一个不透明总分。

### 比较指标

冻结同一批输入，同时运行现有生产二维表和积分候选，报告至少包含：

- 各档位数量和逐条一致/变化方向；
- 被积分提升、被积分降级以及被安全规则截断的样本；
- 硬边界逃逸数，目标必须为 0；
- 不同证据覆盖区间下的变化；
- 有确认人工标签时，两条路线各自与标签的一致率和排序质量；
- 有同岗位重复模型结果时，两条路线的档位波动率与分数波动范围。

当前 43 条可用样本没有确认标签，只能先验证计算、分布、边界和差异，不能宣称准确率提升。模型重复运行属于后续有成本的外部调用，需要届时单独确认范围和费用；人工标签也需要通过后续复核获得。

### 切换门槛

积分路线只有同时满足以下条件时才进入生产切换讨论：

1. 同岗位重复模型样本上的档位波动率低于现有二维表；
2. 在已确认人工标签上不劣于现有二维表；
3. 硬边界逃逸和危险提升均为 0；
4. 对生产岗位分布的变化可以逐条解释，并经过用户确认。

任一条件没有证据时，生产继续使用现有二维表。影子报告本身不得写回岗位决策或影响后续推荐。

## 实施拆分

为避免把三个问题混成一次大改，实施分成两个独立计划：

1. **岗位用户视图与重试状态**：调整 Dashboard 展示投影和流程状态语义，加入当前健康状态回归；
2. **积分影子评估**：新增独立离线积分候选与比较报告，不接入生产。

每个计划都先保留能复现当前缺口的失败回归检查，再做最小实现，并分别通过针对性测试。两个计划完成后再运行完整离线门禁。

## 验证范围

离线验证至少证明：

- 岗位主卡先显示结论，并自然覆盖岗位、公司机会、匹配和薪资；
- 内部判定机制仍可在展开区查看，但不占据主视图；
- 首次失败、后来成功的岗位显示为“后续已解决”，当前未解决数为 0，历史失败数仍保留；
- 健康检查不会因历史失败生成当前 `analysis_incomplete`；
- 真正未完成的岗位仍会被健康检查和进度页识别；
- 积分候选不会被生产代码调用，不会写回数据库；
- 硬边界无法被积分抵消，缺少证据时不会被提升；
- 比较报告在没有人工标签或重复模型样本时明确标记证据不足，不输出准确率或稳定性胜负结论。

本阶段全部使用离线夹具、假数据库和本地只读样本验证，不访问真实 BOSS，不执行模型外部调用，也不发送任何消息。
