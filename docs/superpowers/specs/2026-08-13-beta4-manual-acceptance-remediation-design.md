# RoleFlow beta.4 人工验收整改总设计

**日期：** 2026-08-13
**状态：** 概念方案已获用户确认，书面规范待用户复核
**范围：** beta.3 首次完整人工流程验收暴露的 15 个真实问题

## 1. 结论

beta.3 的岗位采集、完整 JD、分析和人工确认主链已经具备可用基础。本轮不重写
RoleFlow，也不启动 Wave 5，而是在现有工作流、SQLite 检查点、服务端页面和固定
Edge 标签体系上完成三组可独立验收的整改：

1. 工作流正确性、安全恢复和消息入站；
2. 首次使用、模型配置、简历进度与 Dashboard 信息层级；
3. Windows 安装、启动和卸载产品化。

三组工作按上述顺序实施。每组必须有独立回归、独立提交和独立验收结果，前一组
未通过时不得把后一组的视觉改动当作问题已解决。

## 2. 已确认事实

### 2.1 本轮人工运行

- 简历请求 `/api/resume` 持续约 4 分 57 秒。
- `analyzeResume` 持续 142,761 ms，第一次因
  `MODEL_OUTPUT_TRUNCATED` 失败，第二次成功。
- `buildCandidateMatchCard` 持续 47,007 ms，一次成功。
- `recommendSearchPlan` 持续 105,995 ms，第一次因
  `MODEL_OUTPUT_TRUNCATED` 失败，第二次成功。
- 岗位流程持续约 41 分 46 秒，共采集 89 个岗位，82 个岗位取得完整详情并完成
  分析，7 个岗位仍缺详情。
- 沟通批次包含 2 个岗位。第一个岗位记录了一次点击，但结果观察器没有捕获到
  匹配请求，因此进入 `COMMUNICATION_RESULT_AMBIGUOUS`；第二个岗位没有执行。
- 消息只读发现能看到 HR 主动发起的会话，但没有本地进度卡时会进入
  `BOSS_MESSAGE_CARD_NOT_FOUND`，不能纳入后续流程。

### 2.2 根因摘要

- “剩余工作 0”只统计模型任务的 pending/running/retry，没有统计详情和沟通。
- “下一步：暂停本轮”把一个可选控制错误地当作推荐动作。
- 继承模式仍被城市阻塞，是共享验证器无条件要求城市造成的。
- 自动沟通明确把 `BOSS-COMMUNICATION` 聊天标签导航到岗位详情，导致消息页丢失。
- `ambiguous` 的底层人工处理门已经存在，但工作流把它渲染成了整轮普通中断。
- 消息未匹配记录已经持久化，但只保存摘要指纹和错误码，没有可供本地用户确认
  的岗位身份。
- 发给模型前的姓名遮盖是必要边界；不合理的是把遮盖占位符保存并展示给本机
  用户。
- 发布物目前是开发者绿色包，安装时执行完整测试，没有标准安装进度和卸载入口。

### 2.3 已关闭且不得重复整改的问题

- Gate D 跨 baseline 访问丢失已通过账号级共享访问账本关闭；本设计继续复用该
  账本，不新增第二套风控算法。
- 更换 BOSS 账号时必须继续使用独立账号账本，不能复用旧账号账本。
- `trusted_pane` 当前正式证据为 `Page.bringToFront=0`、`focus_tab=0`，不登记为
  抢前台缺陷，也不再修改其激活方式。
- 反复创建测试 baseline 是验收环境特性，不是普通用户路径。后续真实验收必须
  先冻结一次访问计划、共用账号账本，失败后不靠重复运行绕过冷却或预算。

## 3. 不可改变的全局边界

- 正式采集、校准和产品流程只使用 `trusted_pane`。
- `search_page_api` 保留为后续拓展，本轮不修、不测、不启用、不删除。
- 不启用或重新设计 `standalone_detail` 批量详情采集。
- 不降低五个正式关键词、`maxDetailTotal=220`、完整 JD 覆盖、召回和匹配质量。
- BOSS 继续串行访问，保留随机等待、冷却、安全账本、固定标签身份和风控即停。
- 一次真实验收只执行事先声明的最小页面探针和运行，不追加临时循环或并行探测。
- 没有新的明确授权时，不执行沟通、发送消息、申请或投递。
- Wave 5 继续暂停。
- 不引入前端框架，不全面重构 `src/dashboard/server.js` 或 `src/cli.js`。
- 不为理论竞态、热升级或当前产品路径不会触发的问题增加代码。

## 4. 方案比较

### 方案 A：只改页面文案

可以快速改善观感，但城市误阻塞、沟通标签冲突、歧义恢复和陌生入站消息仍然
错误。拒绝。

### 方案 B：在现有架构上分阶段产品化

复用现有工作流、持久化进度、歧义人工处理和未匹配消息账本，只增加当前路径
缺少的语义、恢复和产品入口。每个问题保留最小回归。采用。

### 方案 C：桌面壳、MSIX 和状态机全面重写

可形成全新产品结构，但会同时改动浏览器权威、数据目录、启动方式和工作流，
回归面远大于本轮 15 个问题。拒绝。

## 7. 全局验收规则

### 自动化

- 每项非平凡行为先有能复现旧问题的失败测试，再做最小实现。
- 每个子项目运行聚焦测试、`git diff --check` 和完整 `npm.cmd test`。
- 默认测试不得访问真实 BOSS、真实模型、真实简历或主数据库。
- 数据库迁移必须通过旧库升级、外键、`quick_check` 和回滚保护。
- 不新增未经批准的运行时依赖。

### 本地页面

- 使用临时数据库和假模型验收 1440×900、1280×720 和 375×812。
- 首屏主要操作、阶段进度、错误恢复、键盘焦点和窄屏布局均需通过。
- 页面不得显示数据库英文枚举、隐私占位符或原始技术错误作为主要说明。

### 真实 Edge

- 实现阶段不抓取新岗位，不执行沟通，不发送消息。
- 离线门通过后，最多进行一次固定搜索标签“已保存岗位详情 → 恢复搜索页”的
  只读复测；不点击沟通按钮。
- 消息页只允许少量只读检查，不读取或输出消息正文。
- 登录、风控、标签缺失、窗口漂移立即停止。
- 真正沟通端到端验收仍需用户对该次点击单独明确授权。

## 8. 发布门

beta.4 候选发布必须同时满足：

1. 三个子项目的自动化门均通过；
2. 当前 15 个问题都有代码证据、测试证据或明确的外部依赖结论；
3. `trusted_pane` 采集行为、JD 覆盖和账号安全节奏未改变；
4. 安装器在干净临时目录完成安装、启动、保留数据卸载和完全删除数据卸载；
5. 用户再进行一次不依赖 Codex 操作的完整人工流程；
6. Wave 5 仍由用户在 beta.4 人工验收后决定。

## 9. 明确不在本轮实施的事项

- `search_page_api` 扩展链路；
- `standalone_detail` 批量详情方案；
- 完整多平台筛选参数注入；
- 自动回复 HR、自动投递或申请；
- MSIX、自动更新和代码签名采购；
- 第三个固定 BOSS 标签；
- Dashboard 前端框架迁移；
- Wave 5。
