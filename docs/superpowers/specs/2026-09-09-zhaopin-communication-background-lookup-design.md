# 智联沟通定位的后台标题渲染

## 目标与授权

继续已批准的真实智联验收，正常操作保持后台，不发送回复、简历或申请。用户已要求按现场设计继续，不反复确认已确定的实现方向。本次仅修复沟通定位阶段遗漏的已有后台渲染支持。

## 真实证据

- 2026-09-09 14:24 UTC，批次6/条目42/岗位339从正常本地UI启动，20次滚动后 TARGET_NOT_FOUND；零沟通点击。
- 只读对照 `D:/DevData/RoleFlow-zhaopin-message-context-20260908/lookup-comparison-20260909.json`：原定位路径实际加载至399卡片，但目标无法获得可信sourceId；启用已有 `openSearchRenderScope` 后，下一次采样419卡片、目标索引24可识别，原活动标签和5个标签总数不变。
- 同时被动DOM显示目标JobCard组件编号和名称存在，但 `.vue-clamp__text` 的文本与 aria-label 为空。不能将组件数据单独当作可见身份；标题渲染后现有校验自然通过。
- 扫描已在整个关键词操作期间持有此作用域；沟通仅在 waitForSearchReady 内暂时持有，列表继续加载和定位时已释放。

## 方案

推荐复用 ZhaopinSiteAdapter.openSearchRenderScope，覆盖 inspectCommunicationJob 的搜索页读取、导航就绪、滚动及 inspectCard，并在成功、失败和取消时释放。保持既有嵌套作用域行为；从已验证IM返回时先验证再导航，在搜索页开启作用域。不得新增前台激活、视口/尺寸更改、独立详情页、网络直调、发送重试或增加逻辑扫描上限。

不选放宽标题/sourceId身份规则，也不选增加滚动次数；两者都不能修复已证实的渲染遗漏。

## 验证

合成浏览器让后续页的岗位标题只在后台渲染支持开启时出现，通过生产adapter断言找到同一岗位且零发送。旧代码必须行为失败；新增成功与异常/取消资源释放检查。限定复核通过后，主控运行同一生产入口的只读真实定位，再运行冻结代码的完整门禁；最多一条普通招呼仍由主控在正常本地UI执行。

当天额度例外仅在隔离验收服务中使用；为这次诊断与页面恢复，9月9日智联搜索导航临时上限从24扩至32，详情450不变，午夜自动失效。它不是生产默认策略或发送授权。
