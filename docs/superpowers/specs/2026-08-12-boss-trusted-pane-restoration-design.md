# BOSS 可信右栏读取恢复与后台调度纠偏设计

日期：2026-08-12  
状态：右栏模式已恢复；后台静默边界由 `2026-08-12-boss-explicit-dual-detail-mode-design.md` 接管

## 1. 结论

RoleFlow 正式 BOSS 扫描继续采用已经通过真实运行验证的右栏读取链路：

```text
固定 BOSS-SEARCH 标签
  -> Page.bringToFront
  -> 精确岗位卡片坐标
  -> CDP 可信鼠标点击
  -> 右栏加载
  -> 卡片、组件、右栏、标题和完整 JD 多重校验
```

恢复 2026-08-12 提交 `951eebf` 误删的 `bringToFront()` 调用及对应测试合同。保留之后已经完成的安全节奏、访问额度、检查点、风险时间窗和扫描/沟通风险策略修复。

页面同源详情接口仅作为显式 `search_page_api` 静默模式进入独立校准；默认仍是右栏模式，两者之间不自动回退。

## 2. 证据与根因

### 2.1 成熟主链路证据

- 完整验收运行得到 104 个唯一岗位、102 个完整 JD、0 个详情读取失败。
- 可信坐标点击修复后，另一轮前 55 次 `pane_detail_result` 全部成功；第 56 次因真实 BOSS 安全验证页而正确停止。
- 2026-08-12 另一轮在人工停止前完成 10/10 次详情读取。

### 2.2 被否定的后台点击变体

提交 `951eebf` 删除了切换岗位前的 `Page.bringToFront`，仅保留隐藏标签中的 `Input.dispatchMouseEvent`。真实正式尝试结果为：

- 10 次 `BOSS_PANE_SWITCH_TIMEOUT`；
- 1 次成功仅复用了原本已显示的右栏岗位；
- 不能证明隐藏标签中的输入事件能够可靠切换 BOSS 岗位。

因此失败的是“删除标签激活”的变体，不是成熟右栏读取架构。

### 2.3 前台异常根因

前台异常发生时，主控创建了独立 Codex 任务 `RoleFlow Gate D 正式只读扫描守护`，并要求它“在任务自己的前台 shell 中运行”。扫描执行期间，主控连续向该任务发送消息：

- 子任务日志记录一次 `turn_aborted`；
- 9 秒后记录新的 `task_started`；
- 后续消息继续插入正在运行的回合。

项目 Dashboard 的正常扫描入口已经使用：

```js
{
  windowsHide: true,
  stdio: ["ignore", "pipe", "pipe"]
}
```

所以本次纠偏把问题归到 Codex 调度方式：不得再用独立任务的前台 shell 充当长期扫描守护器，也不得在扫描执行中反复唤醒该任务。

现有证据没有证明 `Page.bringToFront` 会把整个 Edge 窗口置为 Windows 前台。后续真实校准记录扫描前后 Windows 前台进程；如发现 Edge 被激活，立即停止并把它作为独立兼容性问题处理，不改变本次主链路决策。

## 3. 代码范围

只修改：

- `src/adapters/sites/boss.js`
- `tests/source_acquisition_smoke.js`

恢复顺序：

1. 确认浏览器同时提供 `bringToFront()` 和 `clickAt()`。
2. 调用 `bringToFront(tabId)`。
3. 重新检查固定标签绑定和搜索页身份。
4. 读取目标卡片坐标。
5. 再次检查固定标签和搜索页。
6. 调用一次 `clickAt()`。
7. 再次检查固定标签和搜索页。
8. 继续现有多重岗位身份、标题、加载状态和 JD 完整性校验。

禁止借本次恢复：

- 接入同源详情接口；
- 新增自动回退；
- 新建或导航独立详情标签；
- 修改评分、推荐、沟通或消息模块；
- 删除现有访问节奏和风险控制；
- 启动 Wave 5。

## 4. 运行与监控合同

正式扫描只通过项目现有 Dashboard/扫描生命周期启动。它负责隐藏子进程、PID、SQLite 心跳、检查点和终态结算。

主控只允许：

- 读取 `scan_runs`、`batches`、`scan_target_results` 和聚合事件；
- 读取精确 PID 是否仍存在；
- 在明确停止条件下终止精确扫描 PID；
- 在终态后读取固定导出和评测结果。

主控不得：

- 创建 Codex“扫描守护任务”；
- 在可见任务终端中长期运行扫描；
- 用持续消息驱动扫描进度；
- 扫描运行中操作 Edge；
- 启动第二条并发扫描。

## 5. 验收门槛

### 5.1 离线门

- 回归测试先证明删除 `bringToFront()` 时会失败。
- 激活顺序严格为：`bringToFront -> bindings/search check -> locate -> bindings/search check -> clickAt -> bindings/search check`。
- 缺少任一可信浏览器能力时失败关闭。
- 点击后身份漂移、页面丢失、登录或风控信号继续失败关闭。
- 全量离线套件通过。
- 独立任务审查和全分支审查均无 Critical/Important 问题。

### 5.2 真实校准门

使用全新空操作表基线，先执行产品安全校验允许的最小 2 个关键词、最多 3 个详情：

- 3/3 详情读取成功；
- 每条岗位身份和完整 JD 校验通过；
- 无登录、风控、页面丢失和固定标签漂移；
- 无新浏览器窗口或标签；
- 无命令行窗口弹出；
- Windows 前台进程观测没有出现异常切换；
- 不执行沟通、发送或投递。

校准未通过时停止，不进入正式全量扫描。

### 5.3 全量验收门

校准通过后另建一份全新正式基线，执行完整 daily 扫描：

- 所有目标达到可解释终态；
- 扫描 run 和 batch 达到真实终态；
- 统计 raw/unique、完整 JD、详情成功/失败码、技术状态和分析状态；
- 不使用任何历史或 interrupted 数据冒充本轮质量样本；
- 仅在完整终态后固定导出一次；
- 完成现有矩阵与影子积分卡评测，未完成人工标签时明确标注，不宣称 precision/recall 改善；
- 最后使用 Edge 支持人工验收 Dashboard、自动沟通入口和消息只读页面，不执行新的真实沟通。

达到以上门槛且没有阻塞问题后，Wave 0–4 可进入第一阶段收口；后续模块调优另立计划。
