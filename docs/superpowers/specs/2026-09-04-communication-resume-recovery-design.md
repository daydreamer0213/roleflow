# 沟通续接与搜索条件解耦

用户已确认：沟通使用固定搜索标签直接打开不可变清单中的岗位，不依赖搜索结果；搜索筛选条件相等不是沟通权限。重启恢复有价值，但只改善工作区体验，不作为沟通门槛。

## 已确认问题

- 当前 CLI 执行与 Dashboard 重新绑定均比较当前搜索条件和旧范围，导致合法的固定搜索页被拒绝。
- 批次已保存中断原因，但工作流与沟通页未展示批次错误；执行前失败时工作流仍为复核状态，看起来像点击无反应。
- 默认搜索页的初始关键词准备不读取未完成本轮的条件，重建后可能只剩关键词。

## 最小实现

1. 删除两处搜索范围等值检查。保留合法 BOSS 搜索 URL、固定同窗标签、浏览器权限、绑定代次、不可变岗位身份、点击账本、风险与歧义停止。每次从当前搜索页捕获返回 URL 和滚动位置，执行后恢复当前页面。Dashboard 继续前重绑定；直接 CLI 仅允许已绑定的暂停批次重新捕获页面，已运行批次仍严格检查本次绑定，中断批次不能绕过恢复控制。
2. 两个页面均展示批次中断的原因、影响、下一步和折叠技术信息；保留已有继续/人工核对入口。歧义结果仍不可直接继续；运行恢复后不显示旧错误。
3. 工作区关键词准备读取同一候选人、同一方案的未完成本轮。仅在搜索页没有关键词且没有实际筛选参数时，恢复该轮冻结搜索条件与关键词：继承模式采用冻结 URL；通用模式复用既有目标生成器采用冻结城市和首个筛选分组。已有关键词或筛选时保持用户页面。未完成任务不存在时仍按当前方案准备首词。恢复只准备搜索页，不恢复扫描进度或启动任务、发送。

不改扫描条件一致性规则，不加新标签，不改 DOM、节奏或数据库结构。只做离线测试，不修改运行中的安装目录或用户数据库，不执行真实沟通。
