# 验收流程健壮性设计

## 目标

修复首次使用验收中暴露的三个根因问题：模型设置重复提交、入门流程提前放行、Dashboard 浏览器只读检查并发导致 `Runtime.evaluate` 超时。修复后，重复点击不会产生重复外部模型测试；匹配偏好卡只能在筛选方案完成后确认；浏览器读取保持后台、串行、可恢复。

## 已确认事实

- 真实日志显示，同一模型配置在短时间内产生多次 `/api/settings/model` 请求；其中一个已被页面放弃的请求仍在后台完成保存。
- 保存后的 `/settings` 页面曾耗时约 10 秒；当前路由会为同一请求多次读取并解密相同模型设置。
- 真实数据时间线显示：匹配偏好卡草稿先于筛选方案 48 秒生成，用户在方案完成前确认了草稿。
- 两次“执行一轮”失败都发生在浏览器就绪轮询与正式启动读取重叠时；两条 `Runtime.evaluate` 同时达到 15000ms 上限。失败前没有创建 workflow 或 scan 记录。
- 现场只读检查确认两个 BOSS 固定页仍存在，之后单次枚举约 80ms；这是间歇性竞争和重复读取，不是标签页永久损坏。

## 设计

### 1. 模型设置提交

- 设置页在原生表单 `submit` 事件开始时进入一次性提交状态。
- 当前提交按钮显示“正在测试并保存…”，整个表单阻止再次提交，但不删除原请求的 `taskProfile` 和 `action` 字段。
- Dashboard 为内容完全相同且仍在执行的模型设置请求生成仅驻留内存的 SHA-256 指纹。指纹包含 API Key，但原文不记录、不返回、不落盘。
- 相同并发请求共享同一个 Promise，只执行一次模型连接测试和一次原子保存；不同内容继续按各自请求执行。
- 设置页的模型状态在一次 GET 中只装载一次；两项主模型的可用性从同一份已装载状态计算，避免重复解密。

### 2. 入门流程门禁

- `publicOnboardingRun` 只有在 `status=completed`、`stage=ready`、`matchingCardId` 和 `searchPlanId` 同时存在时才返回匹配偏好卡入口。
- `building_plan` 阶段即使已有匹配偏好卡草稿，也不显示可点击的下一步。
- 筛选方案生成失败时保留草稿和已完成步骤，只显示现有“重试当前处理”，不允许绕过方案确认偏好卡。

### 3. 浏览器只读操作串行化

- Dashboard 内建立一个最小的 Promise 串行器，只覆盖当前页面可能互相竞争的 BOSS 只读操作：浏览器就绪检查、继承筛选预览、正式 workflow 启动前的采集上下文读取和需要浏览器的恢复预检。
- 相同的并发就绪检查合并为一次，避免多个页面或计时器重复读取。
- 用户提交“执行一轮”时，客户端立即停止后续 5 秒轮询；已在进行的检查由服务端串行器自然完成，正式启动随后执行。
- `CdpBrowserAdapter` 对已知 tab ID 的命令只用 `/json/list` 验证目标并取得 WebSocket 地址，不再调用会对所有页面执行 `document.visibilityState` 的完整 `listTabs()`。
- `BossSiteAdapter.preflight({tabId})` 直接检查指定 tab，不再先完整枚举。初始和结束的固定页数量、窗口身份、前台状态复核继续由 `inspectBossOperatorTabs` 保留。
- 不调用 `Page.bringToFront`，不增加导航，不改变 9222、随机节奏、冷却、访问预算或风险控制规则。

## 错误处理

- 浏览器超时仍映射为可恢复的浏览器不可用状态；启动失败前不创建 workflow、scan 或访问额度记录。
- 不自动重试任何可能产生外部副作用的操作。本设计仅减少重复只读检查和竞争。
- 模型设置合并仅针对完全相同且同时在途的请求；失败由所有等待者收到同一错误，旧配置由既有原子回滚机制保留。

## 验证

- 并发发送两份相同模型设置请求，断言连接测试每个任务只执行一次，两份响应都成功，Key 不出现在页面、日志或 JSON。
- 在 onboarding 已生成 matchingCard、但 recommendPlan 仍挂起时读取状态和页面，断言没有下一步；释放 plan 后才出现入口。
- 并发发起浏览器 readiness 与 acquisition preview，断言两个注入的真实 route dependency 从不重叠。
- 模拟“执行一轮”提交后触发计时器，断言不再产生 readiness 请求。
- CDP transport 检查断言针对已知 tab 的 `evalValue` 不会读取其他 tab 的可见状态。
- 聚焦测试通过后运行全部离线检查；只用本地 mock Dashboard 做桌面/窄屏交互验收，不访问真实 BOSS。
