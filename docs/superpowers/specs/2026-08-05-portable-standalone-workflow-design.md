# RoleFlow 项目专用 Edge 独立运行设计

## 背景

RoleFlow 已经具备两种浏览器连接方式：

- `edge`：通过 Edge Control 扩展和本地桥接服务控制用户日常使用的 Edge。
- `portable`：项目以 `--remote-debugging-port=9222` 和独立用户目录启动 Edge，并通过本机 CDP 接口直接控制。

当前一键启动脚本会启动项目专用 Edge，但新版继承模式主工作流却固定要求 `edge`。因此，仅双击 `Start.bat` 的普通用户仍可能在“执行一轮”处遇到 Edge Control 未连接错误。这与“不依赖 Codex、扩展或额外桥接服务完成一轮正常运行”的产品目标不一致。

## 目标

让普通用户在完成一次 BOSS 登录和模型配置后，只需：

1. 双击 `Start.bat`。
2. 在项目专用 Edge 的 BOSS 搜索页设置筛选条件。
3. 在本地工作台点击“执行一轮”。
4. 审核并确认沟通清单。
5. 点击“开始沟通”。

扫描、恢复和沟通均使用项目专用 Edge，不依赖 Codex、Edge Control 扩展或 Edge Control 桥接服务。

## 非目标

- 不删除 Edge Control 兼容入口。
- 不修改模型、提示词、评分、关键词选择、扫描预算或沟通额度。
- 不迁移或清理现有数据库。
- 不自动登录 BOSS，不处理验证码，也不绕过风控。
- 不将工作流改为后台定时或无人确认的自动沟通。
- 不降低岗位身份、标签页窗口身份、点击结果和风险信号的现有校验强度。

## 方案选择

### 采用：主工作流统一使用项目专用 Edge

主工作流的继承范围解析、扫描、恢复、沟通批次和沟通执行统一使用 `portable`。`Start.bat` 已经具备启动项目专用 Edge 和本地工作台的基础能力，只需补齐 CDP 标签页窗口身份和主工作流接线。

优点：

- 一键启动路径与实际执行路径一致。
- 不依赖扩展、桥接进程或 Codex 环境。
- 独立浏览器用户目录可持久保存 BOSS 登录状态。
- 浏览器控制范围被限制在项目启动的 Edge 实例内。

代价：

- 用户首次需要在项目专用 Edge 中重新登录 BOSS。
- 日常 Edge 与项目专用 Edge 的登录状态彼此独立。

### 不采用：自动检测两种浏览器

自动优先 Edge Control、失败后切换 CDP 会使新建和恢复工作流可能落到不同浏览器会话，也会增加页面身份漂移和误操作风险。

### 不采用：继续依赖 Edge Control，只自动启动桥接

该方案代码改动较小，但仍要求安装扩展并保持扩展健康，不能满足独立运行目标。

## 架构设计

### 1. 一键启动

保留现有入口：

```text
Start.bat
  -> scripts/start-workspace.ps1
  -> scripts/start-portable-edge.ps1
  -> run.ps1 dashboard --port 8787
  -> 打开 http://127.0.0.1:8787/
```

`start-portable-edge.ps1` 继续使用：

- 本机回环地址上的 CDP 端口 `9222`。
- 项目目录下的 `.runtime\edge-profile`。
- 已安装的 Microsoft Edge。

启动脚本不调用 `start-edge-control.ps1`。如果 Edge 已经运行，则复用同一 CDP 实例和用户目录。

### 2. CDP 标签页窗口身份

现有 `CdpBrowserAdapter.listTabs()` 只返回标签页 ID、标题、URL 和 WebSocket 地址。沟通安全检查还要求可靠的 `windowId`，用于证明搜索标签页和沟通标签页属于同一个浏览器窗口。

CDP 适配器应通过浏览器级 CDP 命令读取每个目标的窗口 ID，并把 `windowId` 加入标签页描述。任何标签页无法取得窗口身份时，不得伪造默认值；后续沟通准备应继续按现有规则拒绝执行。

创建沟通标签页后，也必须能在下一次 `listTabs()` 中取得相同窗口的真实 `windowId`。现有“同窗口复用一个沟通标签页、否则只创建一个新标签页”的策略保持不变。

### 3. 继承模式启动

工作流页面的“执行一轮”表单固定提交：

```text
browserMode=portable
cdpPort=9222
```

工作流启动处理器使用 `CdpBrowserAdapter` 解析项目专用 Edge 当前 BOSS 搜索页，而不是直接构造 `EdgeControlAdapter`。解析仍须在创建工作流或启动子进程之前完成。

只有以下条件全部满足才创建工作流：

- CDP 浏览器可连接。
- 当前存在可信 BOSS 搜索结果页。
- 登录状态有效且没有风险控制页面。
- 当前页面可构建继承范围。
- Search Plan、已确认匹配偏好卡和模型状态满足现有门禁。

启动时冻结的搜索范围、关键词来源和平台策略保持不变。

### 4. 扫描与恢复

新建继承工作流固定使用：

```text
--browser portable --cdp-port 9222
```

工作流在现有规划 JSON 中保存浏览器模式和 CDP 端口，恢复时沿用已保存值，不新增数据库列。恢复继续使用工作流中冻结的继承范围，不根据当前 URL 重新构建范围。

恢复前仍需检查项目专用 Edge 可连接、搜索标签页有效以及扫描批次兼容性。不得在恢复时自动切换到 Edge Control。

### 5. 清单与沟通

由主工作流创建的沟通批次固定保存 `browserMode=portable`。项目专用 Edge 的端口固定为 `9222`，沟通子进程显式传入该端口，不新增沟通批次数据库字段。

沟通执行继续遵守：

- 搜索标签页和沟通标签页必须属于同一窗口。
- 只创建或复用一个固定沟通标签页。
- 每个岗位执行前重新核验 URL、岗位 ID、标题、公司和动作状态。
- 点击最多派发一次。
- 点击结果不能确认时记录为 `ambiguous`，不得自动补点。
- 登录、风控、页面漂移、窗口身份丢失或目标不一致时立即停止。

清单确认和“开始沟通”仍是两个独立人工动作。

### 6. Edge Control 兼容入口

保留以下高级兼容能力：

- CLI 的 `--browser edge`。
- `scripts/start-edge-control.ps1`。
- 高级扫描入口中显式选择“当前 Edge”。

它们不再是主工作流或 `Start.bat` 的依赖。继承工作流不会在两种浏览器之间自动回退。

## 页面与提示

主工作流页面统一显示“使用项目专用 Edge 的 BOSS 搜索页”。

失败提示必须给出用户可直接执行的动作：

- CDP 未启动：提示重新运行 `Start.bat`。
- 未登录：提示在项目专用 Edge 登录 BOSS。
- 不是搜索页：提示在项目专用 Edge 打开岗位搜索结果页。
- 搜索页丢失：提示恢复固定搜索标签页后点击“继续本轮”。
- 窗口身份不可确认：停止沟通，并提示关闭多余窗口后重新启动项目专用 Edge。
- 风控或验证页：立即停止，不提示刷新、重试或切换账号绕过。

## 数据与兼容性

- 不变更候选人画像、简历、Search Plan、岗位、扫描批次和分析缓存结构。
- 工作流规划快照保存浏览器模式及 CDP 端口；旧的 `generated` 工作流继续按已有模式恢复。
- 旧的 `inherited` 工作流如果明确保存为 `edge`，不得静默改成 `portable`；继续原模式或给出明确的兼容性提示。
- 新建继承工作流使用 `portable`。

## 测试设计

按测试驱动顺序增加或扩展以下检查：

1. 浏览器传输测试：CDP 标签页包含真实 `windowId`；窗口查询失败时不伪造身份。
2. 工作流仪表盘测试：新建继承工作流使用 `portable` 和 `9222`，解析器不依赖 Edge Control。
3. 工作流恢复测试：新工作流沿用保存的 `portable` 和端口；旧工作流不被静默切换。
4. 扫描启动测试：子进程参数包含 `--browser portable --cdp-port 9222`。
5. 沟通批次测试：主工作流生成的批次保存 `portable`，沟通子进程使用相同端口。
6. 沟通页面测试：搜索和沟通标签页窗口一致时可继续，窗口身份缺失或不一致时保持失败关闭。
7. 启动路径测试：普通启动不要求 Edge Control 配置或桥接服务。
8. 完整运行 `npm.cmd test` 和 `git diff --check`。

## 实机验收

在 Edge Control 桥接服务保持关闭的情况下：

1. 双击 `Start.bat`。
2. 确认项目专用 Edge 和工作台均启动。
3. 第一次使用时登录 BOSS。
4. 在项目专用 Edge 打开搜索结果页并设置筛选。
5. 启动一轮，确认页面显示继承范围并进入扫描。
6. 扫描完成后检查推荐清单。
7. 用户确认不可变清单。
8. 用户点击“开始沟通”后，验证系统只使用同一窗口的固定沟通标签页。
9. 遇到任何登录、风控、目标不一致或结果歧义，确认系统立即停止并保留状态。

真实沟通仍以用户对该批不可变清单的确认和“开始沟通”操作为授权边界。
