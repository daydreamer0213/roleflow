# 收到的机会与消息处理焦点

状态：用户已批准，2026-09-10 开始实施。基线 `93676e4647aeae9765501850660120dc6462e723`。

## 用户要完成的事

求职体检回答两个不同问题：我主动联系的效果如何；我实际收到了哪些联系和机会。消息页回答：现在需要处理谁，对方说了什么，我如何回复。后台的归属、成熟时间和队列状态不能占据这些问题的视觉中心。

## 统计口径

- 保留“当前方案 / 累计记录”的主动联系平台表、按平台的策略隔离和已有诊断。明确反馈立即计数；48 小时、周末顺延与 30/50/70 只约束充分观察后的诊断。
- 新增正式的“收到的联系”平台表，展示 HR 联系、索要简历、面试邀请。这部分是当前用户已保存的消息记录，不强行归到当前投递方案，也不依赖主动联系记录或完整 JD。
- 单位为会话：同一平台、同一可靠会话身份的重复读取/多个消息分组只算一次；有卡片绑定的历史反馈归到其会话。没有可靠会话身份的旧岗位反馈不冒充独立新会话。缺少投递记录不等于已证实 HR 主动发起。
- 消息正文和简历请求卡已读到、但岗位关联仍待核对的会话照常统计；真正空白/仍在加载的项不算收到联系。索要简历、邀请等同一会话可以同时命中，不能把列相加当总数。
- 表格数字可查看对应记录，记录提供消息入口；消息仍需补岗位资料也要能看到请求。已处理记录可只读查看，不重建发送草稿。历史分类事件与可用正文分开处理；没有保留原文时明确说明，不虚构原文。
- 复用现有 SQLite 记录，不引入新事实表、迁移、依赖或平台读取。统计函数只读，按 profile 隔离，不能受 500 条 UI 恢复上限截断。

## 消息页

- 保持现有字体、色彩和桌面左列表/右详情的结构。标识来自岗位、平台、HR 原话预览和具体待办，不一律叫“HR 新消息”。默认显示待处理，可切全部记录及具体请求类型。
- 首屏只有紧凑页头、一个“读取新消息”主操作、来源/任务筛选和消息本身。运行时提供停止与一句进度；读取详情折叠，单条关联问题显示在对应详情中。登录/平台整体故障仍有明确操作提示。
- 详情按 HR 原话、简短岗位判断、当前草稿排列。保留不推荐的判断，不将礼貌草稿措辞当岗位推荐。默认一版主草稿，备用版本折叠或显式切换。
- 当前会话属于 BOSS 时提供确认发送；智联仅编辑、复制与原会话人工处理。平台能力说明就地出现，不长篇放在页头。
- 批量发送必须主动进入，默认零选择；一个会话最多一版。退出清空本次选择，未发送文字照常保存。活动发送状态和停止入口不会因为切换筛选/退出批量而消失。
- 保留自动保存、保存失败不离开当前项、复制所见文字、不可变发送目标和单击确认语义。UI 不增加额外确认环节，不扩大智联发送能力。
- 窄窗先列表，选中后切详情，有“返回消息列表”；不让几十条列表把详情推到页底。键盘可操作，焦点位置可理解，隐藏面板不占布局。

## 视觉取舍

复用 RoleFlow 现有墨色正文、橙色强调、浅色背景和系统中文字体，不新增字体下载、插画或装饰卡片。唯一强调是当前选中的消息和当前回复操作。数字表使用轻分隔线；运行日志、备用回复、批量操作各自在用户需要时出现。

## 验收与边界

临时数据库验证重复/跨平台/跨用户/未满 48 小时/缺少 JD/已处理记录；本地浏览器验证数字到记录、待处理到回复、窄窗返回、批量零默认、草稿保存及失败保留。只读检查现有 8788 数据和可见页面，测试不修改用户资料、不访问真实招聘平台、不发送消息。完成后仅推送当前开发分支，不合并、打包、发布或改版本。
