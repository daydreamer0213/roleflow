# RoleFlow 后台消息详情读取纠偏设计

## 1. 结论

消息发现必须允许 RoleFlow 专用 Edge 处于最小化或被其他窗口完全遮挡。当前实现把
`document.visibilityState === "visible"` 当成“窗口内活动标签页”的唯一证据；当整个
Edge 窗口不可见时，所有标签页都会返回 `hidden`，因此在创建临时详情页之前误报
`BOSS_MESSAGE_DETAIL_NOT_BACKGROUND`。

本次只纠正这个误拦截，不放宽 BOSS 登录、风控、固定标签页、同窗单临时页、岗位身份、
串行访问、访问额度、节奏、清理和失败即停边界。

## 2. 真实证据

- 本轮消息发现启动前，岗位页和消息页均通过登录及 DOM 预检。
- 失败发生在启动后的约 27 毫秒，临时详情页尚未创建，也未消耗浏览器访问额度。
- 专用 Edge 中三个页面均为 `readyState === "complete"`、`document.wasDiscarded === false`；这只能
  排除页面被丢弃，不能排除隐藏页面进入 frozen 生命周期、暂停计时器和异步回调。
- 专用 Edge 处于系统后台/最小化状态时，三个页面的 `visibilityState` 均为 `hidden`。
- `CdpBrowserAdapter.createTab()` 已使用原生 `Target.createTarget({ background: true })`，
  并在创建后核对新目标、同一窗口和可见页集合；真正的阻塞来自详情读取器额外要求
  创建前必须恰好存在一个 `visible` 页面。

## 3. 方案比较

### 方案 A：保留现状，要求用户每次恢复 Edge

安全证明最强，但与后台自动运行目标冲突，也会把普通的最小化或窗口遮挡当成故障。
本轮真实验收已经证明该方案会阻塞正常使用，因此不采用。

### 方案 B：只信任 `background: true`，删除创建后的核验

改动最少，但如果浏览器忽略后台参数、创建到新窗口或清理失败，就无法及时停止。
这会丢失项目已有的真实账号边界，因此不采用。

### 方案 C：允许零或一个可见页，并保留创建后全量核验（采用）

窗口正常可见时，继续保存并核对原来唯一可见标签页。窗口最小化或完全被遮挡时，保存
空的可见页集合。两种情况下都必须满足：

1. 创建请求明确使用 `background: true`；
2. 只新增一个标签页；
3. 新标签页位于两个固定 BOSS 标签页所在的同一窗口；
4. 新标签页自身不得变为 `visible`；
5. 读取期间可见页集合不得改变；
6. 岗位 ID、标题和公司必须匹配当前消息会话；
7. 临时页必须关闭，关闭后固定标签页、全部标签页 ID 和原可见页集合必须完全恢复。

零可见页状态下无法证明“窗口内部当时选中了哪个固定标签页”，但能够证明没有页面对用户
变为可见，并且临时页最终不存在。消息详情读取本身只读，不执行沟通或投递；这个剩余差异
不构成阻塞后台运行的合理风险。

## 4. 实现范围

- `src/adapters/sites/boss_message_detail_reader.js`
  - 将创建前基线从“必须恰好一个可见页”改为“允许零或一个，两个及以上仍停止”。
  - 后续同窗、单临时页、不可见、身份和完整清理检查保持不变。
- `src/dashboard/message_discovery_view.js`
  - `BOSS_MESSAGE_DETAIL_NOT_BACKGROUND` 只描述真正的后台证明失败，不再把窗口最小化列为
    需要人工恢复的前提。
- `tests/boss_message_detail_reader_smoke.js`
  - 把既有“零可见页必须拒绝”场景改成成功读取并完整恢复的回归场景。
  - 保留新页可见、跨窗口、多个新页、身份不符和清理失败的停止测试。
- `tests/dashboard_message_discovery_smoke.js`
  - 更新面向用户的错误说明断言。

不新增依赖、浏览器扩展、配置项或重试层，不修改扫描、沟通发送和 BOSS 节奏策略。

## 5. 第二轮真实验收补充：后台冻结与会话选择

放开零可见页基线后，真实只读验收又暴露了两个独立问题：

1. 固定消息页在后台时，BOSS 的会话状态可以同步切换，但依赖计时器的后续加载不会继续；
   对同一隐藏目标调用 CDP `Page.setWebLifecycleState({ state: "active" })` 后，100ms 计时器恢复，
   同时当前前台页、窗口和标签页可见集合均未改变。
2. 当前 BOSS 会话行的 DOM `click()` 与中间 Vue 事件转发不能稳定完成后台选择。真实组件层级中，
   `boss-item` 最终由外层 `boss-list.handleClick()` 更新所选会话；因此只能在会话 ID、岗位 ID、
   消息 ID、行号、组件身份和扫描时冻结的 `friendId` 摘要全部复核后调用这个已观测处理器一次。
   原始 `friendId` 不离开页面上下文，也不写入日志或持久化状态。

最终方案仍不恢复窗口、不聚焦标签页：

- 专用 Edge 启动时关闭后台计时器和渲染器节流，作为基础运行参数；
- 每次读取或选择固定消息页前，先核对固定页绑定，再把该页生命周期恢复为 active，随后再次核对绑定；
- 临时详情页只有在已经证明“同窗、唯一新增、目标 URL 正确、保持后台”后才恢复 active，恢复后再次
  核对固定页、临时页和可见集合，再注入读取辅助函数；详情就绪轮询的每一轮和关键读取后都重复
  这项核对，一旦固定页、窗口、路径或可见集合漂移便立即停止；
- 生命周期恢复不是前台激活，不调用 `Page.bringToFront`，不改变发送、投递、登录、风控、身份、
  访问额度、节奏和清理边界。

## 6. 验收标准

- 回归测试先在当前代码上因 `BOSS_MESSAGE_DETAIL_NOT_BACKGROUND` 失败。
- 修改后，同窗固定标签页全部 `hidden` 时可完成一次后台详情读取并关闭临时页。
- 新标签页变为可见、进入新窗口、目标身份不符或清理失败时仍立即停止。
- 定向消息发现、浏览器传输、Dashboard 消息发现测试通过。
- 在真实专用 Edge 保持后台/最小化的状态下重新运行只读消息发现，不要求用户把 Edge
  保持在前台；仍不允许真实回复发送。
- 固定消息页可在隐藏状态完成会话选择，且前台页不改变。
- 临时详情页恢复生命周期后仍保持后台，辅助函数在最终文档中重新注入，读取后关闭并恢复精确基线。
