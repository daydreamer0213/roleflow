# RoleFlow 首次关键词搜索页准备设计

**日期：** 2026-09-01  
**状态：** 用户方向已确认，进入实现  
**所属：** v1.2.0 首次使用验收整改

## 1. 目标

新用户完成简历分析并得到初始本地筛选方案后，RoleFlow 在后台给固定的 BOSS
搜索页补上一个推荐关键词。用户随后打开该页时，BOSS 已展示城市、地铁、商圈等
完整平台筛选项，可以直接补充精细条件，再回到 RoleFlow 开始第一轮岗位发现。

这一步只减少首次准备成本，不开始岗位扫描，不填写或发送消息，也不投递岗位。

## 2. 用户流程

1. 用户上传简历，等待画像、匹配卡和初始本地筛选方案生成完成；
2. RoleFlow 从初始方案选择第一条有效的高优先级关键词，优先级顺序为 A、B、C；
3. 如果固定 BOSS 搜索页尚无关键词，RoleFlow 在后台打开带该关键词的搜索结果页；
4. 页面沿用现有 URL 中的城市及其他平台筛选参数，只清除翻页参数；
5. 用户自行打开 BOSS 搜索页，补充城市、地铁、商圈、经验等平台筛选条件；
6. 用户回到 RoleFlow，确认匹配卡和本地筛选方案后开始岗位发现。

## 3. 不覆盖用户选择

- 固定搜索页已有非空 `query` 时直接跳过，不区分它来自用户还是旧流程；
- 只在一次简历后台处理成功完成后尝试，不在 Dashboard 每次打开或每轮岗位发现时运行；
- 不根据后续方案编辑自动改写 BOSS 页面；
- 不重建固定标签页，不切换标签页到前台，不改变沟通页；
- 不自动选择城市、地铁、商圈等无法仅凭简历可靠决定的平台条件。

## 4. 浏览器与风控边界

准备前必须重新核验固定的 `BOSS-SEARCH` 与 `BOSS-COMMUNICATION`：二者仍在同一
窗口、搜索页仍是 `/web/geek/jobs`、沟通页仍是 `/web/geek/chat`，且没有登录失效、
安全验证或页面身份变化。

导航复用现有 BOSS 列表页访问额度、随机节奏、冷却和检查点，不调用
`Page.bringToFront`。任一检查失败时立即停止此次准备。

## 5. 失败语义

搜索页准备是首次体验增强，不是简历成果的组成部分：

- 画像、匹配卡和本地筛选方案已完成后，准备失败不得把 onboarding 任务改回失败；
- 失败只记录脱敏错误编号和 run ID，不记录简历或关键词正文；
- 用户仍可手动在 BOSS 搜索页输入关键词并继续使用；
- 重试简历处理时仍遵守“页面已有关键词就跳过”，不会覆盖用户刚设置的条件。

## 6. 验收合同

- A/B/C 混排的方案选择首个 A 级有效关键词；没有 A 时按 B、C、原顺序回退；
- 空关键词方案不导航；
- 当前搜索 URL 无关键词时，导航结果新增推荐 `query`，保留其他筛选参数并移除
  `page`；
- 当前搜索 URL 已有关键词时零导航；
- 标签页数量、路径、窗口、登录或风控状态不符合固定边界时零导航并返回明确错误；
- 导航使用固定搜索页、既有访问额度和列表页节奏，不抢占前台；
- 子进程正常完成后触发一次准备；准备失败不改变已完成 onboarding 状态；
- 完整离线测试继续通过，不访问真实 BOSS 页面。

## 7. 非目标

- 自动推断或设置城市、地铁、商圈；
- 自动开始岗位发现；
- 自动沟通、投递、申请或简历同意/拒绝；
- 在方案每次修改后同步 BOSS；
- 新增浏览器、队列、前端框架或第三方依赖。
