# BOSS 后台静默扫描设计

日期：2026-08-12  
状态：实机否定；隐藏标签 CDP 坐标点击无法可靠切岗，且不得作为静默扫描方案

> 请勿继续实施本文方案。后续以 `2026-08-12-boss-explicit-dual-detail-mode-design.md` 为准。

## 1. 结论

RoleFlow 的真实只读扫描必须在后台静默运行：不得切换或激活 Edge、不得弹出终端、不得新建浏览器窗口或标签，也不得依赖持续回复的 Codex 任务充当进程守护。

采用最小改动：

1. 右栏详情切岗继续使用现有精确岗位 ID、坐标定位和 CDP 鼠标事件，但删除 `Page.bringToFront`。
2. 点击后继续执行现有三重岗位身份、标题、加载状态和 JD 完整性校验。
3. 后台点击没有可靠更新目标岗位时失败关闭，保留待续；不回退到激活窗口、DOM 合成点击、独立详情页或接口直读。
4. 扫描进程复用现有 `startPlanScan()` 的 `windowsHide: true`、隐藏子进程和数据库生命周期记录。主控只读取 SQLite 心跳和聚合结果，不向运行中的守护任务反复发送消息。

## 2. 已观察事实

- 2026-08-12 的正式 Gate D 扫描由单独 Codex 任务持续承载。主控向该任务发送新消息后，用户观察到反复跳出前台；该扫描已在 7 条完整详情处停止，并标记为 `interrupted`，不得作为正式评测样本。
- `src/dashboard/server.js` 的 `startPlanScan()` 已使用 `windowsHide: true` 和 `stdio: ["ignore", "pipe", "pipe"]`，现有产品入口具备隐藏启动能力。
- `src/adapters/sites/boss.js` 的 `readVisiblePaneDetail()` 在定位每个非当前岗位前明确调用 `browser.bringToFront(tabId)`。
- `EdgeControlAdapter.bringToFront()` 调用 CDP `Page.bringToFront`，其语义就是激活标签页。
- `clickAt()` 本身通过 CDP `Input.dispatchMouseEvent` 发送坐标事件，不要求代码显式激活标签页。
- 现有回归测试反而要求“先聚焦再定位坐标”，因此当前离线合同没有覆盖后台静默要求。

## 3. 方案比较

### 方案 A：后台 CDP 点击，保留严格身份校验（推荐）

删除显式 `bringToFront()`，仍从当前页面读取精确岗位 ID 和可见坐标，再调用现有 `clickAt()`。点击后的成功条件完全不变。

优点：改动最小；保留真实输入事件、限速、检查点和身份安全；不引入新依赖。  
风险：某些 Edge/BOSS 版本可能不接受后台输入事件。处理方式是失败关闭，不抢前台。

### 方案 B：恢复 DOM 或 Vue 组件合成点击

不需要激活窗口，但历史证据表明“调用成功”不等于页面确实切岗；它弱化了可信输入边界。

结论：不采用。

### 方案 C：直接调用 BOSS 页面接口读取详情

可能完全避免 UI 点击，但会改变当前扫描的数据路径、会话行为、访问预算和风控面，需要重新建立接口合同与安全评测。

结论：不在本次整改范围内。

## 4. 浏览器执行合同

`readVisiblePaneDetail(tabId, job, signal, assertTabBindings)` 的执行顺序保持不变，仅修改激活阶段：

1. 检查停止信号、固定标签绑定、搜索页、登录和风控状态。
2. 从冻结 URL 提取目标岗位 ID。
3. 等待安全节奏并预留一次 `pane_detail_read`。
4. 若当前右栏已经精确匹配，直接复用。
5. 若当前选择稳定地指向其他岗位：
   - 要求浏览器存在 `clickAt()`；
   - 不调用 `bringToFront()`；
   - 在后台读取 `__bossCardActivationPoint(expectedJobId)`；
   - 校验返回岗位 ID、坐标和可用状态；
   - 只发送一次 CDP 鼠标点击。
6. 点击后重新检查固定标签、搜索页和三重岗位身份。
7. 只有 `activeJobId`、`componentCurrentJobId`、`paneJobId`、标题和完整 JD 全部通过时才成功。
8. 背景点击无效、身份漂移或超时时，按现有结果审计记录失败并保留待续。

禁止新增任何会激活窗口的后备路径。

## 5. 后台进程合同

- 正式扫描从现有产品扫描生命周期入口启动，必须保留 `windowsHide: true`。
- 不使用可见 PowerShell、终端窗口或新 Edge 窗口。
- 不创建“每次有进度就回复”的 Codex 守护任务。
- 进度仅来自 SQLite：进程 ID、`scan_runs` 心跳、批次状态、目标结果和聚合计数。
- 运行中不得操作 Edge，也不得发送会让另一个任务重新响应的消息。
- 进程异常退出时，必须由项目现有 `recordScanRunProcessExit()` 收口；未收口的 `running` 记录不能用于评测。

## 6. 验收标准

### 离线

- 详情切岗测试断言没有调用 `bringToFront()`。
- 后台点击仍只执行一次，并且发生在坐标和岗位 ID 校验之后。
- 点击后身份漂移、点击无效、加载超时均失败关闭。
- 浏览器传输测试保留 `bringToFront()` 能力，因为沟通等其他显式前台流程可能仍使用它；本次只禁止扫描详情路径调用。
- 全量离线测试通过。

### 真实 Edge

- 新建空操作表基线，不复用 2026-08-12 的中断基线。
- 在普通 Edge 已登录的两个固定标签下运行只读扫描。
- 扫描期间不激活 Edge、不切换 Codex 任务、不弹终端、不新开标签或窗口。
- 至少观察一次“当前岗位切换到其他岗位”的后台点击，并由数据库结果确认三重身份校验后的完整 JD。
- 若后台点击不被页面接受，扫描安全停止；不得为了完成评测恢复 `bringToFront()`。
- 只有完整正式扫描达到 Gate D 数据门槛后，才运行一次固定评测导出。

## 7. 非目标

- 不修改沟通、发送消息或投递权限。
- 不调整 BOSS 限速、恢复期、访问预算、岗位覆盖目标或推荐阈值。
- 不新建浏览器抽象层、守护服务、Windows 计划任务或第三方依赖。
- 不启动 Wave 5。
