# RoleFlow 桌面端界面重设计

**日期：** 2026-08-30
**状态：** 已确认方向，进入实施
**范围：** RoleFlow 本地 Dashboard 的信息架构、视觉系统和页面布局

## 目标

在不改变现有求职业务逻辑、数据口径和 BOSS 安全边界的前提下，把当前功能完整但信息拥挤的 Dashboard 改造成桌面端优先、克制、专业、容易判断下一步的求职工作台。

界面首先回答四个用户问题：

1. 现在最值得做什么？
2. 当前进行到哪里？
3. 数据说明了什么？
4. 下一步需要我做什么？

页面不向普通用户解释系统为什么这样设计。模型、预算、恢复、执行阶段等内部信息只在影响用户操作或排查异常时出现。

## 已确认的产品结构

求职不是一条只执行一次的线性路线，而是三个不同节奏的工作流：

- **日内岗位循环：** 发现岗位 → 筛选确认 → 推进投递或沟通 → 按需再发现一轮。一天可以执行多轮。
- **跨天反馈循环：** 岗位结果成熟 → 漏斗诊断 → 调整招呼语、简历或策略 → 从下一次求职动作开始新轮次。
- **异步消息任务：** HR 新消息随时出现，作为高优先级事项插入，但不属于日内岗位循环的固定步骤。

反馈样本继续遵守现有规则：投递或沟通结果满 48 小时后成熟，周末顺延；30、50、70 个成熟样本分别对应初步观察、可比较结论和正式诊断。策略变化前后的数据分轮保存，只用于对照，不混入同一轮统计。

## 导航与页面归属

桌面端使用固定分组侧栏，保持当前服务端路由和页面能力：

- **工作台**
  - 今日任务
- **求职**
  - 发现岗位：开始或继续当前工作流，本轮进度与已完成分析的岗位
  - 岗位记录：待处理、已推进和历史岗位
  - 求职体检：当前策略轮次、漏斗诊断和前后对照
- **沟通**
  - 消息与回复：发现 HR 新消息、编辑草稿、单条或批量发送
  - 发送记录：沟通清单、执行状态与历史记录
- **成长**
  - 简历工作室：简历资料和定向优化入口
  - 面试训练：通用简历面试训练和复盘
- **低频入口**
  - 模型与设置
  - 运行诊断

上下文页面继续保留返回路径。`/workflow` 归入“发现岗位”，`/queue` 和 `/jobs` 归入“岗位记录”，`/communication/new` 与 `/communication` 归入“发送记录”。

## 视觉方向

### 性格

克制、专业、精致，像一张长期使用的本地求职工作桌。视觉不使用通用 SaaS 大卡片墙，也不靠强渐变、夸张圆角和装饰性动画制造层级。

### 色彩

- **纸灰 `#F4F5F2`：** 页面底色
- **表面白 `#FFFFFF`：** 当前工作区和输入区域
- **墨绿黑 `#172421`：** 最高优先级事项、主要文字
- **克制翡翠 `#176B59`：** 可操作状态、进度和正向结论
- **雾绿 `#E4EFEB`：** 选中、建议和轻提示
- **暖砂 `#D99148`：** 仅用于风险、明显流失点和需要注意的差异

颜色表达含义，不作为装饰。一个页面最多只有一个墨绿黑主焦点。

### 字体与密度

继续使用系统中文字体，不下载字体、不增加前端依赖。标题使用中等字重和紧凑字距，正文保持稳定行高；数据和辅助标签通过字号与颜色降级，不使用大量粗体。

桌面内容宽度充分利用可用空间，主要操作区保持舒适留白。历史记录、状态计数和技术信息优先使用分隔线、紧凑列表或折叠区，不为每条信息创建卡片。

### 标志性结构

RoleFlow 的标志性元素不是装饰图形，而是“当前工作面”：页面始终有一个最明确的当前行动或结论，其余信息围绕它展开。步骤编号只用于真实有顺序的流程，例如当前岗位轮次或面试题目。

## 页面设计

### 今日任务

- 顶部只展示当前最优先事项，例如 HR 新消息、未完成岗位轮次或等待用户确认的清单。
- 主区域展示今日岗位推进数量、当前轮次和下一步。
- 已完成轮次折叠成一行摘要，不重复生成大卡片。
- 右侧展示当前反馈轮次的结论、样本强度和建议。
- 不显示“不阻塞继续投递”等设计者解释。

### 发现岗位

- 主视图优先展示已分析完成的岗位，后台进度只占一条紧凑状态带。
- 推荐、待确认和暂不推荐通过筛选标签切换。
- 岗位使用紧凑列表，展示标题、公司、薪资与工作安排、匹配原因、系统评价和查看入口。
- 采集预算、模型、详细阶段、恢复信息进入“运行详情”；异常时再主动展开。
- 本轮完成后引导用户确认推荐岗位，而不是展示技术完成报告。

### 岗位记录

- 使用按行动紧迫程度排序的表格式列表，不使用岗位卡片墙。
- 第一层筛选是“需要处理、进行中、已结束”，第二层才是具体状态。
- 每行展示岗位身份、系统评价、当前进展、最近变化和下一步。
- 详情按需展开或进入详情页，不在列表重复完整 JD 和全部分析。

### 消息与回复

- 左侧只列 HR 新消息和待处理草稿；已读、送达只保留本次统计数量。
- 右侧一次只处理当前消息，阅读顺序固定为：岗位判断 → HR 原文 → 回复草稿 → 操作。
- 草稿编辑区域是主要工作面，自动保存状态轻量显示。
- 点击确认发送、复制或标记已手动发送时，当前编辑文字直接作为确认输入，不增加二次确认。
- 多条草稿可选择后批量串行发送。批量栏仅在有选择时出现。
- 发送安全边界、身份核对、停止与不确定结果处理保持现有实现，不在视觉改造中削弱。

### 求职体检

- 阅读顺序是：当前结论 → 最大卡点 → 前后轮次变化 → 建议行动。
- 30/50/70 样本强度使用一条证据尺表示，不拆成多个指标卡。
- 漏斗显示各环节的分母和转化率，并突出最大流失环节。
- 当前轮次与上一轮独立显示；策略改变后从下一次求职动作开始新轮次。
- 等待成熟、状态未知、分组比较和计算规则作为次级信息。

### 简历工作室

- 用户选择原始简历和投递方向后，系统直接生成完整优化稿。
- 编辑器是主视图；修改清单与依据作为右侧或下方说明，不要求逐条审批。
- 用户可直接接受完整稿或在稿件上继续修改。
- 每项修改说明“改了什么”和“基于什么岗位证据或简历事实”，不编造经历。

### 面试训练

- 默认突出基于简历的通用面试训练。
- 当前题目和回答输入是唯一主焦点；题目依据轻量展示。
- 已回答内容与复盘折叠到历史区，不在答题时同时占据主要画面。
- 岗位定向训练保留为次级模式，不阻塞通用训练。

### 设置、诊断和资料维护

- 复用同一侧栏、页面标题、表单和状态样式。
- 设置按任务分组，诊断信息保持完整但默认使用可扫描的分段布局。
- 初次使用和空状态明确告诉用户下一步，不展示没有行动价值的占位卡片。

## 交互与反馈

- 主按钮使用明确动词，例如“发现新消息”“查看推荐岗位”“确认发送”。
- 同一动作在按钮、进行中状态和完成提示中使用一致名称。
- 长时间运行只显示一个用户可理解的当前阶段、总体进度和可用操作。
- 错误说明发生了什么以及用户可以怎么继续；错误码放在详细信息中。
- 键盘焦点始终可见，表单标签和状态区保留可访问名称。
- 动画只用于状态变化和列表进入，遵守 `prefers-reduced-motion`；首轮实现不加入非必要动画。

## 技术方案

- 继续使用现有 Node.js 服务端渲染 HTML、原生 CSS 和少量原生 JavaScript。
- 不引入 React、Vue、Tailwind、组件库、构建工具或新的运行时依赖。
- 共享侧栏和页面外壳集中在 `src/dashboard/ui/`。
- 视觉令牌和共享布局集中在 `src/dashboard/assets/roleflow.css`；页面专用样式沿用现有类命名并逐步替换。
- 页面数据继续来自现有 view model 和服务，不修改数据库结构、统计口径、消息学习或 BOSS 执行器。
- 页面迁移按可独立验证的批次完成，避免一次性重写整个 Dashboard。

## 测试与验收

- 为导航分组、当前页归属、关键页面结构和关键按钮文案保留离线回归检查。
- 现有功能烟雾测试继续验证表单、隐藏字段、端点和安全语义。
- 使用本地 fixture 在桌面宽度检查页面：无横向溢出、主操作可见、焦点顺序合理、控制台无脚本错误。
- 完成后从用户视角走通：今日任务 → 发现岗位 → 确认岗位 → 消息回复 → 求职体检 → 简历优化 → 面试训练。
- 不访问真实 BOSS，不产生真实发送、投递或申请。

## 非目标

- 不改变岗位匹配算法、二维表生产决策或积分路线。
- 不改变反馈成熟时间、样本阈值或策略轮次数据模型。
- 不增加自动投递、自动申请或未经当前目标确认的外部写入。
- 不引入新的前端框架、组件库或图表依赖。
- 不在视觉重设计中重写业务服务、存储层或浏览器执行器。
