# RoleFlow 首次启动与安装体验收口设计

## 目标

解决 v1.3.0 人工验收发现的四项首次体验问题：

1. 专用 Edge 启动后自动补齐固定的 BOSS 搜索页和沟通页，不再依赖用户点击“刷新工作区”。
2. 已有启用搜索方案时，空白搜索页自动带入优先级最高的搜索词，让用户直接补充城市、地铁、商圈等平台筛选条件。
3. 用可重复测量区分 Edge 正常的多进程开销、页面负载和真正的异常增长，不用破坏后台运行或浏览器安全能力的猜测式参数换取表面降占用。
4. 安装和覆盖升级都显示系统原生的安装位置选择页；默认路径保持合理，用户可自行修改。

本轮不改变岗位分析、消息发现、真实沟通、投递或申请规则，也不新增任何真实 BOSS 写入权限。

## 已确认根因

### 搜索页与沟通页形成循环依赖

当前工作区只有在搜索页已经被识别为有效搜索结果页后，才创建固定沟通页；初始关键词准备又要求搜索页与沟通页已经构成完整固定页对。结果是：空白搜索页无法自动获得关键词，沟通页也无法自动创建，用户只能先手工输入关键词，再点击“刷新工作区”。

当前关键词补偿还绑定于新版 onboarding 完成记录。已有有效搜索方案、但没有这类新记录的升级用户不会进入补偿路径。本次验收数据库即属于这种情况：存在启用方案和非空关键词，但没有可供补偿使用的 onboarding 运行记录。

### Edge 暂无重复启动或泄漏证据

本次只读样本只有一个专用 Edge 浏览器根进程。浏览器采用 Chromium 多进程结构，当前四个页面对应多个 renderer、utility 和 GPU 子进程；这能解释相当一部分内存占用，但不能据此证明泄漏。独立浏览器资料目录首次运行还会生成缓存和浏览器组件数据，这些是磁盘占用，不应与内存混为一谈。

现有后台计时与渲染策略用于保证最小化窗口仍可运行，不在没有对照证据时删除。浏览器安全组件、登录资料和 BOSS 页面能力也不得为降低数字而关闭。

### 安装器在升级时自动隐藏目录页

Inno Setup 的 `DisableDirPage` 当前使用默认 `auto`。检测到同一应用的既有安装记录时，升级会隐藏安装目录页并沿用旧目录，因此用户看不到修改入口。

## 推荐设计

### 1. 工作区分两步收敛

工作区准备保留现有固定页和同窗约束，但把“登录已确认”和“搜索条件已完整”分开处理：

1. 未登录、风险验证、浏览器身份异常或窗口歧义时，保持现有停止行为，不创建沟通页。
2. 已登录且唯一搜索页身份可信，但搜索词为空时，允许在同一窗口后台创建唯一沟通页和工作台页。
3. 只有搜索页、沟通页和工作台页的身份均重新确认后，才进入关键词准备。
4. 关键词准备完成后自动执行一次串行工作区复查，把公开状态更新为“已就绪”。用户不需要再点击“刷新工作区”。

所有创建操作继续使用后台标签，不调用扫描与消息流程禁止的前台切换。启动助手原有的一次性用户引导例外保持不变。

### 2. 关键词来源改为当前启用方案

自动准备不再要求必须存在 onboarding 运行记录：

- onboarding 刚完成时，优先使用该运行产生的新方案。
- 应用启动或用户恢复工作区时，如果没有待处理的新方案，则使用当前主候选人的启用方案，与首页现有候选人选择规则保持一致。
- 关键词仍按 A、B、C 优先级及方案内顺序选择第一项。
- 当前 URL 已有非空 `query` 时立即跳过，不覆盖用户输入，也不改变已有城市、区域、地铁、商圈、薪资或经验参数。
- 当前方案没有关键词时保持空白并提示用户完善方案，不猜测岗位方向。

同一 Dashboard 进程对同一方案只完成一次成功准备；失败不会被永久标记，下一次显式恢复或工作区重新收敛仍可重试。数据库中的旧 onboarding 事件继续兼容，不做迁移。

### 3. Edge 性能按证据处理

本轮先修复启动拓扑，随后使用独立的 `D:` 测试资料目录和本地页面进行冷启动测量，不读取真实 BOSS 内容：

- 记录浏览器从启动到本地控制连接稳定、再到工作区就绪的耗时。
- 记录根进程和子进程数量、工作集内存，以及就绪后稳定时点的变化。
- 核对自动启动只生成工作台、搜索页、沟通页，不产生重复窗口或重复固定页。

若固定三页下没有持续增长或重复进程，本轮结论为“未发现 RoleFlow 泄漏”，不添加激进参数。只有独立 A/B 证明禁用专用 Edge 扩展等单一措施确实降低资源、且不影响登录、后台最小化、页面身份和 CDP 稳定性时，才纳入实现；否则只记录测量结果。

### 4. 使用安装器原生目录选择页

安装器显式设置：

- `DisableDirPage=no`：新安装和覆盖升级都显示“选择安装位置”。
- `UsePreviousAppDir=yes`：升级时仍把旧安装目录作为默认值，用户无需修改即可继续原路径。

不开发自定义“高级设置”页面。Inno Setup 原生页面已经提供路径输入和浏览按钮，功能更稳定、维护成本更低。

修改安装目录只影响程序文件。候选人数据、设置、日志和专用 Edge 登录资料继续使用 `%LOCALAPPDATA%\RoleFlow` 下的稳定用户目录，因此更换安装位置不会复制或删除这些资料。安装器原有的运行进程核对、安装后自检和卸载保护保持不变。

## 失败处理与安全边界

- 登录、风控、窗口歧义、固定页身份变化或后台建页无法确认时立即停止自动收敛，页面显示现有可操作提示。
- 自动关键词导航继续经过 BOSS 访问节奏和预算控制；不会因首次体验优化绕过节奏、冷却或身份复查。
- 自动准备只能补空的 `query`；任何已有搜索词都视为用户当前选择。
- 不自动关闭用户标签页，不清理浏览器缓存，不删除扩展、登录资料或历史数据。
- 性能验证只使用本地页面和测试资料目录，不访问真实 BOSS，不执行真实沟通或投递。

## 验证方案

### 自动回归

1. 工作区只有已登录的空搜索页时，会后台补齐沟通页，但状态仍保持“需要搜索条件”。
2. 未登录或风险状态不会提前创建沟通页。
3. 只有启用搜索方案、没有 onboarding 运行记录时，仍会为白页准备关键词。
4. 已有搜索词时不导航、不覆盖用户筛选条件。
5. 准备成功后自动复查并进入“已就绪”；失败后仍可重试，且不会形成重复页。
6. 安装器完整构建、自检、覆盖安装与显式自定义目录安装均通过；覆盖升级默认显示旧目录。
7. 聚焦检查通过后运行完整离线门禁。

### 性能验收

使用同一台机器、同一 Edge 版本和独立测试资料，至少记录一次冷启动和一次热启动。比较修复前后的就绪耗时、进程数量和稳定内存；不以单个瞬时峰值判断泄漏。

## 用户可见结果

- 返回用户打开 RoleFlow：完成登录后，搜索页、沟通页和工作台会自动形成固定工作区。
- 已保存方案时，搜索页会自动带入一个推荐关键词；用户只需在 BOSS 补充细致筛选，再回到 RoleFlow 开始发现岗位。
- 浏览器准备较慢时，工作台继续显示准备状态，不要求用户用刷新按钮推动流程。
- 安装或升级时始终可以查看并修改安装位置。

## 不在本轮范围

- 不改变固定三页之外的真实 BOSS 页面规则。
- 不自动关闭用户打开的额外页面。
- 不减少 JD 覆盖、筛选质量或后台运行可靠性来换取资源数字。
- 不改版本号，不推送、不合并、不打包、不创建 Release；这些操作需要后续明确授权。
