# RoleFlow Windows 安装产品化设计

**日期：** 2026-08-13
**状态：** 概念方案已获用户确认，书面规范待用户复核
**所属：** beta.4 人工验收整改子项目 C

## 1. 目标

把当前开发者 ZIP + BAT 流程升级为普通 Windows 用户可理解的按用户安装、启动
和卸载体验，同时继续保留便携 ZIP 供开发和故障恢复。

本设计选用 Inno Setup，不在 beta.4 引入 MSIX、自动更新服务或自定义桌面壳。

## 2. 当前真实缺口

- `Install.bat` 只调用 PowerShell，只有控制台文字，没有图形进度。
- 安装结束立即启动工作台，用户无法区分安装和启动。
- 每次安装运行完整 93 项开发回归。
- 缺 Node 时临时下载，网络速度和失败状态不透明。
- 没有 Windows“已安装的应用”记录和卸载程序。
- `Start.bat` 可能显示终端或只在终端中给出错误。
- 普通 Edge 模式依赖 Edge Control 扩展和 bridge，但 beta.3 发布包明确不包含它。

## 3. 方案选择

### 方案 A：继续增强 BAT

可以增加文字百分比和卸载脚本，但仍不是标准 Windows 安装体验。拒绝。

### 方案 B：Inno Setup 按用户安装器

原生提供向导、进度、快捷方式、已安装应用和卸载；可以继续运行现有
PowerShell/Node 架构。采用。

### 方案 C：MSIX

卸载和更新模型更现代，但需要签名、应用身份、数据目录和浏览器集成改造。暂不
采用。

## 4. 安装包内容

安装器包含：

- RoleFlow 生产代码、文档、许可证和必要配置；
- 已安装的生产 `node_modules`；
- 固定版本的便携 Node.js 22；
- 安装启动脚本；
- 不含数据库、简历、模型密钥、日志、报告和浏览器 profile；
- 不含测试目录和发布构建缓存；
- 不含 `search_page_api` 的额外运行配置。

完整离线测试只在构建安装器前运行一次。最终用户安装过程中只执行轻量自检：

- 文件完整性；
- Node 可执行；
- Edge 是否存在；
- 本地端口可用性；
- RoleFlow dashboard 可启动。

不在用户机器执行 `npm ci` 或 93 项开发测试。

## 5. 安装行为

### 5.1 权限和路径

- 默认按当前用户安装，不请求管理员权限。
- 默认程序路径：
  `%LOCALAPPDATA%\Programs\RoleFlow`。
- 安装向导允许选择其他目录和其他磁盘。
- 开发构建工具和缓存继续放在 `D:\DevData`，不向 `C:` 写入大体积构建缓存。

### 5.2 向导页面

1. 欢迎与版本；
2. 许可证；
3. 安装位置；
4. 可选桌面快捷方式；
5. 安装进度；
6. 环境自检结果；
7. 完成页：
   - 启动 RoleFlow；
   - 查看浏览器连接说明；
   - 打开 README。

安装失败显示当前阶段、中文原因和日志路径。成功前不得显示“安装完成”。

### 5.3 快捷方式和启动

- 开始菜单：RoleFlow、RoleFlow 使用说明、卸载 RoleFlow。
- 桌面快捷方式默认勾选但允许取消。
- 快捷方式调用 `scripts/launch-installed.ps1`，PowerShell 窗口隐藏。
- launcher 继续复用现有 `start-workspace.ps1` 和 dashboard 身份检查。
- 启动失败使用本机消息框显示中文原因和日志路径，不弹出长期黑色终端。
- 不通过进程名批量结束 Node/PowerShell；所有停止操作必须核对 dashboard
  `/health` 的 `projectRoot` 和监听 PID。

## 6. 用户数据与卸载

Inno Setup 只自动删除安装器写入的程序文件。运行后产生的下列内容默认保留：

- `data/jobs.sqlite` 及其安全备份；
- `.runtime/settings`；
- `.runtime/secrets`；
- `.runtime/resumes`；
- 用户报告和日志。

卸载前：

1. 查找 8787 监听者；
2. 读取 `/health`；
3. 只有 projectRoot 等于本安装目录时才停止；
4. 等待数据库进程退出；
5. 执行程序文件卸载。

卸载向导提供未默认勾选的：

> 同时删除本机 RoleFlow 数据、简历、模型设置和日志

勾选后再次列出精确目录并确认。删除范围只能是经过解析并验证属于当前安装目录的
明确数据子目录；不得使用宽泛环境变量或递归删除用户目录。

卸载结束说明：

- 程序是否已删除；
- 用户数据是否保留；
- 保留数据的确切位置；
- 如保留，重新安装同一路径后可以继续使用。

## 7. Edge Control 分发边界

当前本机 Edge Control manifest 标记为 `UNLICENSED`，RoleFlow 没有可验证的再分发
许可。因此 beta.4 安装器不得把该扩展或 bridge 复制进公开安装包，也不得自动从
不受 RoleFlow 控制的地址下载未知版本。

在获得兼容的明确许可和固定 release 前，安装器：

- 检测 bridge 配置、进程和扩展连接；
- 已存在且健康时继续普通 Edge 模式；
- 缺失时显示“浏览器连接组件尚未安装”的独立步骤和现有本地安装说明；
- 不自动回退到另一个浏览器 authority；
- 允许用户退出安装后再准备依赖；
- 便携 CDP 继续作为用户显式选择的备用模式，不设为静默 fallback。

这意味着 beta.4 可以交付标准 RoleFlow 安装/卸载，但对全新电脑的“真正一键完成”
仍受 Edge Control 再分发权限制。公开宣称一键安装前必须单独完成以下二选一决策：

1. 为 Edge Control 提供可再分发的兼容许可证和固定版本；
2. 另立项目，把产品默认浏览器 authority 改为无需该组件的方案。

该外部决策不阻塞安装器外壳、运行时捆绑、快捷方式和卸载实现。

## 8. 构建流程

新增可重复构建入口：

```text
BuildInstaller.bat
  -> 完整离线测试
  -> 创建不含用户数据的 release stage
  -> 校验 Node、依赖和许可证清单
  -> 调用固定 Inno Setup compiler
  -> 生成 dist/RoleFlow-Setup-<version>.exe
  -> 输出 SHA-256
```

Inno Setup 是构建时工具，不进入用户运行时。构建机上的安装器缓存放在
`D:\DevData`。发布包中的版本号必须与 `package.json` 和 release notes 一致。

保留：

- `BuildRelease.bat` 和便携 ZIP；
- `Install.bat` 作为便携包/开发入口，但文档明确它不是标准安装器；
- `Start.bat` 作为故障恢复入口。

## 9. 升级行为

同一 AppId 的新版本默认覆盖程序文件，不删除用户生成数据。升级前：

- 停止且只停止当前安装目录对应的 dashboard；
- 不修改正在使用的数据库；
- 安装完成后运行轻量自检；
- 不自动启动 BOSS 扫描或消息发现。

beta.4 不实现后台自动更新。用户下载新安装器后手动升级。

## 10. 回归与验收

### 构建检查

- 安装包不含 `jobs.sqlite`、简历、密钥、日志、报告或浏览器 profile。
- 安装包包含 Node 和生产依赖，不需要联网安装 npm 包。
- 版本、许可证、NOTICE 和 SHA-256 完整。
- 安装阶段不运行完整测试。

### 干净目录矩阵

1. 默认路径安装；
2. 自定义 `D:` 路径安装；
3. 不创建桌面快捷方式；
4. 缺 Edge Control 时显示可理解的依赖说明；
5. 已有健康 Edge Control 时启动本地工作台；
6. 启动失败时无常驻黑色终端，错误含日志路径；
7. 默认卸载保留用户数据；
8. 重新安装后读取保留数据；
9. 明确勾选后删除经过验证的本机数据；
10. 升级安装不丢数据。

所有测试使用临时目录和匿名临时数据库，不操作当前主项目数据库和真实 BOSS。

## 11. 发布限制

- 未购买代码签名证书前，安装器可能出现 Windows 信誉提示；发布说明必须如实说明。
- 不得把未获许可的 Edge Control 放入安装包。
- 不宣称支持自动更新。
- 不删除或隐藏 AGPL/NOTICE。
- 便携 ZIP 和标准安装器必须清楚区分。

## 12. 不在本子项目范围

- MSIX；
- 自动更新服务；
- 代码签名证书采购；
- Edge Control 重新授权或重写；
- 默认切换到 portable/CDP；
- 浏览器行为和 BOSS 采集逻辑改造；
- Wave 5。
