# 沟通恢复与结果判定最小修复设计

日期：2026-08-14  
状态：用户已批准

## 1. 已确认问题

### 1.1 恢复入口使用了过期的 Edge 标签绑定

覆盖安装后，数据库保留了上一轮的 Edge window/tab 数值 ID。沟通页同时显示
“验收这个岗位并自动暂停”和“重新检查浏览器页面”，用户可以先按执行按钮。
子进程启动后才发现当前标签 ID 已变化，于是以
`COMMUNICATION_BROWSER_BINDING_MISMATCH` 中断，且没有点击岗位。

### 1.2 明确成功的请求被通用弹窗覆盖

岗位 #2 点击一次后，BOSS 的 `friend_add` 请求返回 HTTP 200、业务码 `0`，
但页面同时存在一个通用弹窗。当前验证器先检查弹窗，再检查成功请求，因此把结果
记成 `COMMUNICATION_USER_ACTION_REQUIRED`。后续只读证据证明该岗位已经进入
“继续沟通”状态。

弹窗内容可能受到用户招呼语和 BOSS 页面流程影响，不能作为固定文案解析，也不能
覆盖已经确认的官方接口成功结果。

## 2. 目标

1. 恢复 Edge 沟通时，在启动子进程前自动刷新固定标签绑定；失败时不启动、不点击。
2. 点击前岗位身份校验保持不变。
3. 点击后若同页监听到 BOSS 官方 `friend_add` 成功响应，直接记为成功。
4. 不读取招呼语，不解析确认框文案，不重新进入岗位，不增加点击或导航。
5. 保持单次点击、结果不明不重试、登录/风控/标签漂移立即停止。

## 3. 最小方案

### 3.1 自动刷新恢复绑定

Edge 批次从 `paused` 或 `interrupted` 恢复时，现有控制接口先复用现有的只读
rebind 检查：

- 读取两个固定 operator 标签及其数值 ID；
- 检查登录、风控和冻结搜索范围；
- 捕获当前搜索 URL 与滚动位置；
- 在本地数据库把 binding generation 加一。

只有 rebind 成功后，批次才进入 `running` 并启动沟通子进程。任何检查失败都在
启动前返回，不触发 BOSS 写动作。子进程保留现有的最终绑定复核，防止检查后标签
又发生变化。

页面不再同时要求用户选择“先检查”还是“直接执行”：恢复执行按钮内部完成上述
只读检查。现有独立 rebind API 保留给诊断，不增加新状态、数据库迁移或恢复令牌。

### 3.2 官方成功响应优先于通用弹窗

结果判定保持以下最小顺序：

1. 登录失效或风控：立即停止。
2. 当前页面已明确变成其他岗位或岗位不可用：保持现有安全结果。
3. 精确 BOSS origin/path 的 `friend_add` 返回 HTTP 成功且业务码为 `0`：
   记为 `succeeded`。
4. 没有明确成功响应，但出现通用弹窗：记为
   `COMMUNICATION_USER_ACTION_REQUIRED`。
5. 请求失败、冲突、无法解析或没有匹配请求：沿用现有失败/不明确处理。

这只调整已有条件的优先级，不新增页面操作。招呼语和弹窗正文不参与判断，证据
仍只保存经过脱敏的 endpoint 类型、HTTP 状态、业务码类别和耗时。

## 4. 非目标

- 不自动继续当前真实批次，不操作真实 BOSS 页面。
- 不重放已点击的岗位 #1 或 #2。
- 不启用 `search_page_api`，不使用 `standalone_detail`。
- 不调整扫描、JD 覆盖、匹配质量或推荐规则。
- 不做沟通状态机重构，不新增依赖。
- 不创建标签、不推送或发布，除非用户另行明确授权。

## 5. 回归测试

测试先行，只增加能证明当前两个真实问题的最小用例：

1. interrupted Edge 批次恢复时，先完成 rebind，再启动子进程；rebind 失败时
   批次不进入 running，子进程启动次数为 0。
2. `friend_add` 成功与通用弹窗同时出现时，结果为 `succeeded`，浏览器点击次数
   仍为 1，没有额外导航。
3. 没有成功请求而只有通用弹窗时，仍为
   `COMMUNICATION_USER_ACTION_REQUIRED`。
4. 风控、登录失效、目标漂移和失败请求继续沿用现有停机行为。
5. 运行沟通定向测试和完整离线套件。

离线验证通过只代表代码路径已修复。是否能继续真实批量沟通，仍需用新的可安装
验收版本进行一次用户明确授权的单岗位端到端验收。
