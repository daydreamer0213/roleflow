# RoleFlow 专用 Edge 工作区自动收敛设计

## 背景与根因

2026-08-25 的安装版验收中，专用 Edge 已经启动，但工作流仍因缺少 BOSS 搜索页或沟通页而要求用户手动补页。现场还出现了浏览器实际已有工作台、搜索页和沟通页，而 Dashboard 仍保留 `ambiguous` 旧状态的情况。

这不是单个选择器错误，而是生命周期编排缺口：

- 启动脚本只等待浏览器进程就绪，不等待工作区完成一次稳定检查。
- 首次工作区整理是一次性、异步、尽力而为；启动恢复期间的短暂歧义会永久留在 Dashboard 快照中。
- 未登录时，工作区整理创建搜索页后提前返回 `login_required`，不会创建沟通页。
- 登录完成后没有自动续跑；工作流入口只检查并拒绝，不先执行一次安全整理。

## 目标

1. 用户只负责项目无法代替的登录、验证码和风控确认。
2. RoleFlow 自动维持同一专用 Edge 窗口内的工作台、一个 BOSS 搜索页和一个 BOSS 沟通页。
3. 缺页时只在后台创建缺失页面；已有正确页面时不导航、不刷新、不重复创建。
4. 启动恢复、登录完成和工作流开始前都能幂等地收敛到可用状态。
5. 短暂的 Edge 会话恢复状态不会被永久记录为故障。

## 非目标

- 不接管用户的普通 Edge。
- 不自动处理登录、验证码或 BOSS 风控。
- 不删除来源不明的用户标签页来强行满足拓扑。
- 不允许扫描、分析、消息发现或沟通流程调用 `Page.bringToFront`。
- 不改变消息发现获准使用的单个后台临时详情页规则。

## 设计

### 1. 明确三层就绪状态

分别维护：

- `application`：Dashboard 本地服务是否可用。
- `browser`：专用 Edge 进程和 CDP 连接是否可用。
- `workspace`：工作台、搜索页、沟通页和登录状态是否满足产品操作。

启动成功不等于 BOSS 已登录，但启动流程必须至少完成一次稳定的工作区检查，才能把结果展示给用户。`login_required` 是可预期状态，不是启动失败。

### 2. 引入串行、幂等的工作区收敛器

沿用现有 `prepareWorkspaceTabs()` 的安全创建能力，在其外层增加唯一的工作区收敛入口：

1. 等待 Edge 恢复后的标签页列表稳定：每 250 毫秒检查一次，最多等待 5 秒，要求连续两次得到相同的标签页身份、窗口归属和可见页集合。
2. 串行执行整理，复用现有队列，禁止两个请求并发创建页面。
3. 只处理三种可证明拓扑：仅工作台、单个 BOSS 引导/搜索页、完整固定工作区。
4. 缺少搜索页时，以同窗口现有页为锚点在后台创建搜索页。
5. 登录已确认且缺少沟通页时，在同一窗口后台创建沟通页。
6. 缺少工作台时，在同一窗口后台创建工作台。
7. 每次创建后重新核对标签页 ID、窗口 ID、URL 类型和前台页集合；不满足即清理本次创建的页面并停止。

收敛器不得导航或刷新已经正确的 BOSS 页面。它只在缺页时发出一次已知 URL 的后台创建请求。

### 3. 登录后的自动续跑

当状态为 `login_required` 时：

- 仅在用户调用启动入口时，允许现有启动引导把搜索页带到前台一次。
- 后台每 10–15 秒随机间隔检查一次登录状态，最多持续 30 分钟；检查只读取当前页面，不产生搜索、详情或沟通请求。
- 登录确认后立即串行续跑收敛器，在后台补齐沟通页和工作台，然后停止登录监测。
- 监测超过限定时间后停止；用户再次打开 Dashboard 或开始工作流时会触发新的收敛，不要求点击专门的“重新检查”按钮。

### 4. 工作流入口先自愈再拒绝

需要浏览器的工作流在最终 readiness gate 前执行：

1. 确认或恢复专用 Edge。
2. 执行一次工作区收敛。
3. 读取新的工作区状态。
4. 只有登录、风控、无法证明的窗口/标签页冲突仍存在时才返回用户操作提示。

因此，“缺少搜索页/沟通页”不再直接成为用户错误。

### 5. 启动脚本等待正确边界

`start-workspace.ps1` 不再只因 `browser.ready=true` 就立即宣布完整准备完成。它需要等待工作区离开 `unchecked/converging`：

- `ready`：展示可开始操作。
- `login_required`：启动成功，并引导用户登录。
- 可安全重试的短暂 `ambiguous`：在限定窗口内重新检查。
- 稳定存在的真实冲突：Dashboard 继续可用，并展示具体处理信息，不制造“启动成功后又启动失败”的矛盾状态。

## 错误与安全处理

- 所有整理保持单窗口、串行和后台执行。
- 只有用户调用的启动引导可以使用一次 `Page.bringToFront`；其他触发源必须传入 `startupGuidance:false`。
- 页面创建失败时只清理本次调用创建的标签页，不动原有页面。
- 登录、风险控制和页面身份无法确认时立即停止，不循环导航。
- 工作区检查不消耗岗位详情访问额度；任何后续真实 BOSS 操作仍遵循原有冷却、预算和检查点。

## 测试与验收

离线回归必须覆盖：

- Edge 恢复时标签页列表短暂变化，稳定后自动收敛。
- 仅工作台时后台创建搜索页；登录后自动补齐沟通页。
- 搜索页或沟通页被用户关闭后，工作流开始前自动补齐。
- 页面已经齐全时不创建、不导航、不刷新。
- 登录检查不会抢前台。
- 多窗口或重复 BOSS 页面保持安全停止，不误删用户页面。
- 启动脚本区分 `ready`、`login_required` 和真实冲突。

人工验收只需观察：重启电脑后普通打开快捷方式，完成登录，RoleFlow 自动形成完整工作区；关闭其中一个固定 BOSS 页后，从 Dashboard 开始一轮，缺页应在后台补齐且当前前台不变化。
