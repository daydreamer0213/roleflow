# RoleFlow 本轮任务安全结束设计

日期：2026-09-03  
状态：已实现

## 1. 背景与问题

用户开始一轮岗位检索后，当前页面只在“正在执行”的部分状态显示暂停和结束操作。一旦本轮进入 `interrupted`（已中断）或无需继续执行但仍占用活动名额的复核状态，后端虽然允许停止，页面却不再显示“结束本轮”。

这会形成用户可见的死路：

- 本轮没有继续运行；
- 用户无法主动结束；
- 该记录仍被视为活动中的本轮；
- 用户因此无法开始下一轮。

本次真实验收中的直接触发原因是扫描进度保存触发冻结边界校验，当前本轮进入 `interrupted`，同时遗留 `pause_requested`。保存事务已回滚，因此现有日志只能确定“某项进度超过冻结边界”，不能可靠判断具体是哪一个计数器。缺少退出入口则是独立的产品缺陷，不应依赖修复这一次扫描异常来绕过。

## 2. 目标

让用户从开始岗位发现起，到真实沟通开始前，始终可以安全地结束当前本轮；结束后保留已经获得的有效结果，并释放活动本轮占用，使用户能够按现有额度和冷却规则决定是否开始下一轮。

同时补充足够但不泄露敏感页面内容的进度校验诊断，便于再次发生边界异常时直接定位根因。

## 3. 用户可见流程

### 3.1 入口覆盖

以下状态显示“结束本轮”入口：

- 本轮已创建、尚未实际开始；
- 正在发现岗位；
- 正在分析岗位；
- 正在等待暂停落稳；
- 已暂停；
- 本轮已中断；
- 等待用户复核，且本轮尚未建立沟通批次。

不在岗位流程中重复提供统一“结束本轮”的情况：

- 已经进入或建立真实沟通批次；
- 本轮已经完成、已经停止，或已经由其他终态结清。

真实沟通仍使用沟通页现有的“安全撤回”和结果不确定处理，避免把“停止岗位发现”和“停止可能已经产生外部结果的沟通”混为一件事。

### 3.2 确认信息

点击“结束本轮”后，复用现有确认面板，明确展示：

- 已发现、已分析、失败和未完成的数量；
- 本轮已使用的平台访问额度；
- 结束后是否会占用今天的一次运行名额；
- 已保存的岗位和分析结果会继续保留；
- 未完成的工作会停止，本轮不会被记为“已完成”。

用户确认后不再增加第二层确认。

### 3.3 结束后的结果

- 本轮状态转为 `stopped`；
- 控制请求清理为 `none`；
- 已保存岗位、分析和统计证据不删除；
- 未完成的本轮任务标记为停止；
- 当前本轮不再阻塞新一轮；
- 能否立即开始下一轮仍遵守现有每日额度和冷却规则；如果本轮已经访问过平台，结束仍按现有规则消耗一次运行名额。

## 4. 控制与数据流

### 4.1 复用现有停止能力

本次不增加数据库状态、不增加新接口，也不建立第二套取消机制。继续使用现有：

- `stop_requested` 控制请求；
- 停止确认接口；
- `stopped` 终态；
- 未完成任务结清和租约释放逻辑；
- 每日运行名额计算规则。

核心修改是让页面按照后端已经给出的 `canStop` 能力和当前是否存在沟通批次来展示入口，而不是仅根据“页面阶段必须是 active”这一狭窄条件决定。

### 4.2 有执行进程时

扫描或分析仍在运行时采用协作式停止：

1. 写入 `stop_requested`；
2. 不再开始新的工作单元；
3. 当前工作单元到达可安全保存的位置后结清；
4. 释放当前执行租约；
5. 将本轮转为 `stopped`。

这样不会在数据库写入中途强杀进程，也不会把部分写入误记为完成。

### 4.3 无执行进程时

本轮已暂停、已中断，或复核状态下已经没有活动执行进程时，确认结束后立即结清，无需等待不存在的后台任务。

遗留的 `pause_requested` 可以被本次停止请求替换，最终统一清理为 `none`。

### 4.4 沟通边界

如果本轮已经关联沟通批次，岗位流程页不显示通用“结束本轮”。用户应在沟通页处理：

- 尚未发送或明确未触发的任务可以安全撤回；
- 可能已经触发但结果未知的任务继续要求人工确认结果；
- 不通过结束岗位本轮来抹掉或跳过真实外部动作的状态。

## 5. 扫描进度边界诊断

继续保留当前冻结边界校验，不降低或绕过约束。校验失败时记录结构化、去敏后的诊断信息：

- 失败的具体不变量名称；
- 本次准备保存的计数值；
- 对应冻结上限；
- 当前目标序号和目标总数；
- 扫描批次、运行和请求的内部关联标识。

诊断不得记录岗位正文、聊天内容、候选人简历内容、Cookie 或页面凭证。用户页面仍显示可理解的处理建议；详细数字只进入本地诊断日志。

## 6. 实现范围

预计只做最小充分修改：

- 调整求职流程页面的停止入口展示条件；
- 在视图模型中明确是否已经进入沟通批次，或复用已有等价字段；
- 必要时补强停止动作在中断和复核状态下的即时结清；
- 将进度边界错误拆成可定位的去敏诊断；
- 增加对应离线回归测试；
- 更新用户说明和阶段交接文档。

不做以下事项：

- 不重写工作流状态机；
- 不新增数据库迁移；
- 不改变岗位评分、搜索条件或冷却策略；
- 不用“结束本轮”代替沟通安全撤回；
- 不访问真实 BOSS 页面进行常规测试；
- 不自动结束当前用户数据中的这一次本轮。

## 7. 验收标准

### 7.1 页面与交互

- `interrupted` 状态显示“结束本轮”，点击后显示现有确认信息；
- 没有沟通批次的 `review_required` 状态显示“结束本轮”；
- 已关联沟通批次时不显示岗位流程通用停止入口；
- 已完成或已停止的本轮不显示重复停止入口；
- 用户确认一次即可执行，不增加多余确认。

### 7.2 状态与数据

- 带有遗留 `pause_requested` 的中断本轮能够转为 `stopped`；
- 结束后控制状态为 `none`，活动本轮占用被释放；
- 已保存岗位和分析保留，未完成任务正确标记停止；
- 已经访问过平台时，运行名额计算保持现有规则；
- 正在扫描时仍按安全边界协作停止，不出现部分写入被标为完成。

### 7.3 诊断与回归

- 每一种扫描进度越界都能从去敏日志中看到具体字段、当前值和上限；
- 用户界面不暴露内部堆栈或难懂的单一错误编号；
- 现有暂停、继续、正常完成、沟通安全撤回和运行额度测试继续通过；
- 完整离线测试通过后才允许提交实现结果。

## 8. 当前中断本轮的兼容性

当前真实验收遗留的中断本轮不需要手工改库。新版本加载后，应直接显示“结束本轮”；用户确认后通过正常停止链路结清。

在用户明确点击前，项目不会自动改变这次本轮，也不会自动访问或操作真实 BOSS 页面。
