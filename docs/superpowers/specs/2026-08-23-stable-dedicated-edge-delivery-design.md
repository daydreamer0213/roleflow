# RoleFlow 普通用户稳定专用 Edge 交付设计

**日期：** 2026-08-23
**状态：** 方向已获用户确认，书面规范待用户复核
**基线：** `main@9cf5b41c8af7cfb8143ec0af4afc6db32b0fa099`
**开发分支：** `codex/stable-dedicated-edge`

## 1. 结论

RoleFlow 面向普通 Windows 用户时，默认使用由 RoleFlow 启动的专用 Microsoft Edge，
不再把 Edge Control 作为安装和启动前置条件。

专用 Edge 仍使用电脑里真实安装的 `msedge.exe`，但采用 RoleFlow 自己的浏览器
profile。该 profile 改为当前 Windows 用户下的稳定目录，不再跟随源码目录、工作树、
解压目录或程序安装目录变化。用户首次登录 BOSS 后，覆盖安装、升级版本或移动程序
目录都继续使用同一份登录状态。

内部兼容名称 `portable` 暂时保留，避免无意义地改写数据库和命令契约；用户界面统一
称为“RoleFlow 专用 Edge”。普通 Edge + Edge Control 降为明确的开发者高级选项。

## 2. 已确认的事实

### 2.1 Edge Control 来源与许可

- 本机 `D:\codex-plugins\edge-control` 与公开归档仓库
  `C4AL/codex-edge-control-bridge` 的 README、插件清单、扩展清单、bridge 和安装脚本
  SHA-256 完全一致。
- 公开仓库已于 2026-04-22 归档。
- 仓库根目录没有 `LICENSE`，插件清单明确写为 `UNLICENSED`。
- 公开可查看源码不等于获得复制、修改和再分发许可。

因此 RoleFlow 安装包继续排除 Edge Control，不自动下载它，也不把它作为普通用户
依赖。后续若取得版权所有者的明确授权，可再独立评估商店扩展方案；本课题不等待该
外部条件。

### 2.2 当前登录状态问题

当前 `start-portable-edge.ps1` 默认把 profile 放在：

```text
<当前 RoleFlow 根目录>\.runtime\edge-profile
```

这份 profile 本身会保存 `Local State` 和 Cookies，但不同工作树、安装目录和解压目录
会得到不同 profile。本机证据是：

- `D:\Guo\ZhiPing\.runtime\edge-profile` 存在完整状态；
- 当前 Codex 工作树没有该 profile；
- 旧的 `E:\RoleFlow` 安装目录也没有该 profile。

所以“每次像是重新登录”的主要原因不是 Edge 不保存状态，而是 RoleFlow 把浏览器
身份错误地绑定在程序副本上。

### 2.3 当前专用 Edge 能力

现有 `CdpBrowserAdapter` 已经提供：

- 标签页列表；
- `Browser.getWindowForTarget` 可靠窗口身份；
- 同一窗口后台创建标签页并核对结果；
- 后台 DOM 读取、JavaScript 执行和 CDP 指令；
- 鼠标事件；
- 标签页关闭和身份漂移停止。

因此无需开发第二套浏览器 bridge。当前主要缺口是产品编排仍然偏向 Edge Control：

- `start-workspace.ps1` 默认模式仍为 `edge`；
- 新工作流入口拒绝 `portable`；
- Dashboard 消息发现的浏览器工厂写死为 `edge`；
- 沟通清单界面默认选择 `edge`，部分重新绑定逻辑也只处理 `edge`；
- 专用 Edge 工作区没有统一强制两个固定 BOSS 基线标签页。

## 3. 用户目标

普通用户只需要：

1. 安装 RoleFlow；
2. 启动 RoleFlow；
3. 第一次在专用 Edge 中登录 BOSS；
4. 准备一个岗位搜索页和一个沟通页；
5. 以后直接启动，登录状态和 RoleFlow 数据都继续存在。

成功标准不是“CDP 端口能连接”，而是用户不需要理解 Node、扩展、bridge、profile、
工作树或浏览器 authority，也不会因为升级或换安装目录重新登录。

## 4. 范围

### 4.1 本课题包含

- 稳定的专用 Edge profile 路径；
- 普通用户默认启动专用 Edge；
- 启动模式显式传递到 Dashboard 和后续任务；
- 扫描、JD、分析、消息发现、草稿和沟通批次使用同一浏览器 authority；
- 两个固定 BOSS 基线标签页在专用 Edge 中的同窗身份检查；
- 现有四课题在专用 Edge 下不退化；
- 安装、升级、卸载和错误提示同步调整；
- 删除会触发 360 的假 `msedge.exe` 测试方式，用无进程测试接缝保留等价校验；
- 离线回归和一次真实人工验收。

### 4.2 本课题不包含

- 打包、修改或发布 Edge Control；
- 开发新的 Edge 商店扩展；
- 自动更新服务；
- 代码签名证书采购；
- 自动 BOSS 监控、自动扫描或自动发送；
- `search_page_api` 修复或验证；
- 通用 `standalone_detail`；
- 公司背景调查扩展；
- Wave 5 或全项目重写。

## 5. 稳定 profile 设计

### 5.1 默认路径

普通用户默认 profile：

```text
%LOCALAPPDATA%\RoleFlow\BrowserProfile
```

选择 `%LOCALAPPDATA%` 是因为普通 Windows 电脑不能假设存在 `D:`，并且该位置天然按
Windows 用户隔离。继续保留现有 `-ProfileDir` 显式覆盖能力，供开发者或需要把较大
浏览器数据放到其他磁盘的用户使用；不增加一套新的配置系统。

profile 路径解析只保留一个实现，由专用 Edge 启动、端口身份检查、扫描启动和测试
共同使用。任何调用者都不得自行拼接 `.runtime\edge-profile`。

### 5.2 生命周期

- 安装包不包含 profile。
- 第一次启动按需创建稳定目录。
- 覆盖安装和升级不改动该目录。
- 改变程序安装目录不改变该目录。
- 普通启动、失败恢复和测试不得删除 profile。
- 卸载默认保留 profile。
- 只有用户在卸载界面明确选择删除浏览器登录数据，并再次看到精确目录后，才允许
  删除该目录。

### 5.3 旧 profile 迁移

本课题不扫描磁盘寻找旧 profile，也不自动合并多个浏览器身份。

对已有测试用户，只允许一次明确的迁移：用户给出精确旧目录，确认所有使用该
profile 的 Edge 已关闭，再复制到空的稳定目录。目标已存在时停止，不覆盖、不合并；
源目录保留到人工验收通过后再由用户决定是否删除。

迁移通过独立的维护入口执行，不嵌入普通启动、安装或升级流程。没有执行迁移的用户
也可以直接在稳定 profile 中重新登录一次；程序不得因此阻止正常启动。

公开新用户不需要迁移，只在稳定目录登录一次。

### 5.4 并发和锁

- 9222 已有监听时，必须验证监听进程的真实 `msedge.exe` 路径和
  `--user-data-dir` 等于稳定 profile；不匹配立即停止。
- profile 正被另一无 CDP 的 Edge 进程使用时，停止并提示关闭该专用 Edge；不得删除
  Chromium 锁文件，也不得结束普通 Edge。
- 不自动换端口或换 profile 绕过冲突，因为那会创建第二浏览器身份。

## 6. 浏览器 authority 贯穿

### 6.1 启动时冻结

`start-workspace.ps1` 的普通用户默认模式改为内部 `portable`，固定 CDP 端口 9222。
它启动 Dashboard 时显式传入：

```text
browserMode=portable
cdpPort=9222
profile=<稳定 profile>
```

Dashboard `/health` 返回本进程的浏览器模式和端口。已有 Dashboard 的模式与本次启动
请求不一致时，启动停止并提示先关闭旧工作台；不得静默复用另一个 authority，也不
得自动切换到 Edge Control。

### 6.2 工作流

- 新工作流默认接受并冻结 `portable/9222`。
- 恢复任务继续使用创建时冻结的浏览器模式和端口。
- 运行期间不能把专用 Edge 工作流切换为 Edge Control，反之亦然。
- 扫描继续只使用 `trusted_pane`。

### 6.3 消息发现

- 消息发现使用 Dashboard 启动时冻结的浏览器 authority，不再写死 `edge`。
- 读取仍使用固定沟通页，完全后台执行，不调用 `Page.bringToFront`。
- 新会话缺少完整可信 JD 时，仍只允许一个同窗口、`active: false` 的临时详情标签页；
  串行读取、计入共享预算和冷却，检查点完成后关闭。
- 草稿只保存在本机，不自动填写或发送。

### 6.4 沟通批次

- 沟通清单默认冻结 `portable/9222`，不再让普通用户选择自己不理解的 transport。
- CDP 已提供可靠窗口身份，因此专用 Edge 也必须执行与 Edge Control 相同的固定标签
  绑定、目标复核和结果复核。
- 真实外部发送仍要求当前不可变批次的明确授权；默认浏览器改变不构成发送授权。
- 不确定结果不重试、不回放历史批次。

Edge Control 入口继续存在，但只在高级入口显式选择；它不能成为专用 Edge 失败后的
自动 fallback。

## 7. 固定标签页和前台行为

专用 Edge 使用同一个窗口中的三个长期页面：

- 一个 `/web/geek/jobs` 搜索页；
- 一个 `/web/geek/chat` 沟通页；
- 一个本机 RoleFlow Dashboard。

扫描和沟通前均重新解析当前标签 ID，并要求两个 BOSS 标签页具有同一可靠
`windowId`。不得使用历史 ID、字符串化数字 ID 或标签顺序猜测身份。

首次登录时可以只打开 BOSS 登录/搜索页。用户完成登录并再次检查后，启动助手在同一
窗口后台补齐沟通页和 Dashboard，并验证路径和窗口身份。发现多余 BOSS 窗口、多个
搜索页或多个沟通页时停止，不自动关闭用户页面。

唯一允许抢前台的地方仍是用户主动启动工作区：准备完成后引导到 Dashboard，需登录
时引导到 BOSS。扫描、JD、分析、消息发现、沟通、轮询、恢复和重试都不得调用
`Page.bringToFront`。

## 8. 安装和用户界面

### 8.1 安装器

安装器继续包含 RoleFlow、固定 Node 和生产依赖，不包含 Edge Control 或浏览器
profile。安装后轻量自检检查：

- 真实 Microsoft Edge 存在；
- 稳定 profile 父目录可创建；
- 8787 和 9222 没有身份冲突；
- Dashboard 可以启动。

自检不访问 BOSS，不运行完整开发测试，也不生成假 `msedge.exe`。

### 8.2 用户文案

用户界面使用：

- “RoleFlow 专用 Edge（推荐）”；
- “使用当前 Edge（高级，需要浏览器连接组件）”。

不向普通用户显示 `portable`、CDP、9222、bridge 或 authority 等内部词。错误提示必须
说明用户应关闭哪个窗口、重新点击哪个入口，以及数据保存在哪里。

### 8.3 文档一致性

实现完成后同步更新 README、产品说明、日常流程、运维说明、交接文档和下一阶段
文档，消除以下旧描述：

- 当前 Edge + Edge Control 是普通用户默认；
- 项目目录内 profile 是长期身份；
- 专用 Edge 只是手动备用；
- 消息发现与专用 Edge 的实际支持不一致。

## 9. 360 测试冲突处理

当前 `startup_scripts_smoke.js` 会编译并运行一个未签名、名为 `msedge.exe` 的临时测试
程序。这不是普通用户路径，但会触发本机 360。

本课题不通过改名继续模拟恶意特征，也不降低启动身份检查。改为：

1. 把 profile 解析、启动参数生成和进程身份判定拆成可直接输入测试数据的纯逻辑；
2. 离线测试使用伪造的进程快照和端口身份数据，不生成或执行任何可执行文件；
3. 真实 Edge 启动、关闭和登录持久性留给受控人工验收；
4. 删除完整测试对临时假 `msedge.exe` 的依赖后，再恢复 101/101 的统一测试入口。

这保留了“只接受真实 Edge + 正确 profile + 正确端口”的安全结论，同时消除杀毒软件
冲突源。

## 10. 错误处理

以下情况全部停止，不做自动恢复：

- 9222 被其他进程占用；
- 9222 属于不同 Edge profile；
- 稳定 profile 正被另一个无法验证的 Edge 使用；
- Dashboard 的浏览器模式与本次启动模式不一致；
- 固定搜索页或沟通页缺失、重复、跨窗口或路径漂移；
- BOSS 登录失效、风控、页面丢失；
- 临时详情标签页无法证明后台打开或无法证明关闭；
- profile 迁移目标非空或源目录身份不明确。

错误信息不得建议用户关闭所有 Edge、结束所有 Node 或删除 profile。

## 11. 验证

### 11.1 离线回归

至少覆盖：

- 默认 profile 不随项目根目录变化；
- 显式绝对 `-ProfileDir` 仍被采用；
- 启动参数正确引用含空格的 profile 路径；
- 端口属于错误 profile 时停止；
- Dashboard 模式不一致时停止；
- 新工作流、恢复任务、消息发现和沟通批次保持同一 authority；
- CDP 下两个固定 BOSS 标签页同窗绑定；
- 后台临时详情标签页的创建、身份复核和清理；
- 卸载默认保留浏览器 profile；
- 明确删除只作用于精确稳定 profile；
- 完整回归不再生成假 `msedge.exe`。

### 11.2 人工真实验收

只在离线验证全部通过后进行：

1. 在安装 360 的电脑上安装未发布候选包；
2. 启动专用 Edge，确认使用真实 Microsoft Edge；
3. 登录 BOSS，准备一个搜索页和一个沟通页；
4. 完全关闭专用 Edge；
5. 再次启动 RoleFlow，确认仍然登录；
6. 覆盖安装同版本候选包后再次确认登录；
7. 改变 RoleFlow 程序安装目录后再次确认登录；
8. 只读执行一次扫描和一次消息发现，确认后台运行且不抢前台；
9. 确认消息缺 JD 时最多出现一个后台临时详情页，并在完成后关闭；
10. 只生成草稿，不执行真实发送；
11. 普通卸载确认 profile 保留；
12. 删除型卸载只在再次明确授权后单独验收。

真实发送不属于本轮默认验收；如需验证，必须另行针对当前不可变样本授权。

## 12. 交付顺序

1. 稳定 profile 解析和无可执行文件的启动测试接缝；
2. 专用 Edge 默认启动与 Dashboard authority 身份；
3. 新工作流、消息发现和沟通批次统一 authority；
4. 专用 Edge 两个固定 BOSS 标签页的安全绑定；
5. 安装、卸载、文案和权威文档同步；
6. 完整离线验证；
7. 用户辅助下的真实人工验收；
8. 验收通过后再决定提交合并，不自动推送或发布。

## 13. 完成标准

只有同时满足以下条件才算完成：

- 普通安装不需要 Edge Control；
- 用户只需首次登录一次；
- 升级和移动安装目录不丢登录；
- 扫描、JD、分析、消息发现、草稿和沟通批次没有 transport 分裂；
- 所有 BOSS 行为保持既有安全、冷却、预算和后台约束；
- 360 不再因离线测试中的假 `msedge.exe` 报警；
- 全部允许的离线测试和人工验收通过；
- 没有自动发送、自动推送、自动发布或未授权外部写入。
