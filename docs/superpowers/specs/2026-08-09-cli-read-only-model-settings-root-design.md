# CLI 只读模型设置根目录设计

## 背景

当前候选 worktree 的运行时设置不包含可用于批量筛选的已验证模型配置。主工作区虽然保留了正式设置，但它的源码提交落后且工作树不干净，不能用它替代候选代码做验收。

需要让候选代码在不复制、不移动、不写入模型设置或 DPAPI 密钥的前提下，显式读取一个获准的外部设置根目录。该能力只用于当前 CLI 的真实模型扫描验收。

## 方案选择

1. 复制或链接 `.runtime`：会扩大凭据和工作树写入风险，排除。
2. 用主工作区旧源码执行：无法验证候选提交，排除。
3. 为 `scan` 增加显式只读 `--model-settings-root`：候选源码保持执行主体，模型设置原地只读，采用。

## 接口与边界

`node src/cli.js scan --model-settings-root <外部项目根目录> ...`

- 未提供该参数时，保持现有行为：模型设置根目录仍为当前代码根目录。
- 提供该参数时，根目录必须是存在的本机绝对目录，且其规范化后的目标不能在当前 worktree、用户主目录或系统临时目录之下；URL、相对路径、缺失路径和非目录均拒绝。
- 外部根目录必须包含 `.runtime/settings/model.json`。CLI 不会回退到当前 worktree 的 `configs/model.json` 或运行时目录。
- 外部设置读取会以 `readOnly: true` 传入模型设置层。若设置为旧 schema、需要密钥迁移，直接以稳定错误码拒绝；不得调用任何迁移、保存或删除逻辑。
- 该参数只影响 `scan` 的 primary / batch backup 模型读取。`dashboard` 和所有模型设置保存 API 继续固定使用当前代码根目录，绝不接受外部根目录。
- 外部根目录的原始路径、端点、密钥、DPAPI 文件、提示词、模型响应正文均不记录到日志、SQLite、工作流 planner 或 Git。

## 实现

`src/core/model_settings.js` 提供受测试的外部根目录校验函数，并让 `loadModelSettings`、`resolveRuntimeModelConfig` 与 `resolveRuntimeBatchBackup` 支持只读加载。只有“旧 schema 需要迁移”这一分支在只读模式下改变为安全失败；默认本地设置路径继续保留原有迁移行为。

`src/cli.js` 在 `scan` 的模型初始化前解析该参数，并把返回的 `{ root, readOnly }` 同时传给 primary 与 backup 解析器。帮助文本说明其只读用途。`run.ps1` 已原样透传参数，无需改动。

## 验证

1. 针对路径校验覆盖：有效外部目录、相对路径、URL、当前 worktree、用户目录、临时目录和缺失设置文件。
2. 针对只读加载覆盖：旧 schema 被拒绝，设置文件和密钥目录均不发生写入。
3. 针对 CLI 边界覆盖：`scan` 的模型解析选项使用外部根目录且标记只读；未提供参数保持当前根目录和可迁移行为。
4. 完成后运行聚焦 smoke、完整离线套件，并只在全部通过后恢复 V4 的真实只读校准。

## 非目标

- 不把外部根目录支持扩展到 dashboard、模型设置保存、沟通或投递路径。
- 不修改正式主工作区、其数据库或其中的模型设置文件。
- 不改变 BOSS 的只读、串行、限量和风险即停规则。
