# 沟通续接与搜索条件解耦验收

## 用户可见变化

- 沟通固定搜索页不再要求保持扫描时的城市、地铁等条件；仍只处理用户确认的不可变岗位清单，结束后返回这次启动时的搜索页与滚动位置。
- 工作流页与自动沟通页展示批次失败原因、影响和下一步；错误编号放在技术信息里。执行前失败不再看起来像点击无反应，结果不明确仍须先人工核对。
- 重启后的空搜索页可补回同方案未完成本轮的冻结关键词和条件（继承与通用模式）；已有关键词或筛选不覆盖，页面准备不会启动扫描或沟通。

## 根因与实现

旧 CLI 与 Dashboard 的重新绑定将“扫描范围相等”当作沟通门槛，但执行器实际按不可变岗位 URL 打开详情、核对身份，不需要搜索结果。两个等值守卫已删除；固定标签、浏览器权限、合法返回 URL、代次、逐岗位身份、点击账本与歧义阻断保持不变。直接 CLI 的已绑定暂停批次在开始前重绑定，已经运行的批次仍严格检查本次页面状态。

批次中断原本已保存，却没有进入两页的展示模型；现复用错误指导和统一提示片段，且标题、概览和剩余工作使用批次实际状态。启动首词准备新增读取同一候选人/方案的活动本轮，复用既有搜索 URL 与目标生成器，不新增恢复框架。
