## 下一项开发顺序

新集成分支同时承载两个独立课题，按各自证据分别设计、实施和验收：

1. **消息发现模块**：先核对现有消息读取、岗位上下文和意图分类链路，解决“正式邀约”和“只是提到面试”等语义被混淆的问题；结果先回答用户真正需要知道的事项，再自动生成本地回复草稿。读取继续后台串行、共享冷却，并最多使用一个受控临时详情页；草稿不等于发送授权。
2. **岗位分析模块**：把结论、岗位内容、公司业务、候选人匹配度、薪资范围和当前可支持的公司机会评价作为主要输出，内部匹配依据不再占据用户主视图；同时修复“首次失败但重试已成功”后历史记录与当前状态混淆的问题。
3. 每个课题先完成代码证据审查和独立设计，再写实施计划；实施时保留能证明关键行为的最小回归检查，并重新运行完整离线门禁。
4. 需要真实页面时先做最小只读验收。真实沟通只允许新建单岗位不可变批次，并在执行该条外部写前取得用户明确授权；不得使用当前扫描清单或历史批次推断授权。
