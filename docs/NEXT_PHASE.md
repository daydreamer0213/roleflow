# RoleFlow 下一阶段主控索引

> 更新于 2026-08-17。本文件记录四个独立课题的最终状态和边界。四个课题均已完成设计、实现、自动回归和各自所需的人工验收。

## 总体原则

- 四个课题相互独立。项目精简只针对整个代码库，不是另外三个产品功能的统一重构框架。
- 每次只设计、实现和验收一个课题；共享文件发生冲突时串行推进。
- 保持 v1.0 的 BOSS、安全、质量、数据基线和先验证后提交边界。
- 设计先确定真实用户流程、数据来源、失败边界和验收标准，再写实施计划。
- 不把历史 plan/spec 的待办状态当成当前需求。

从不可替代的产品结果和安全/质量底线出发，证明哪些代码应删除、缩短、随功能迁移或保留。在不改变产品行为的前提下减少真实冗余。

### 状态

`██████████ 100%` 已完成设计、实施和本地验证；位于 `codex/first-principles-audit`，未推送、未合并、未发布。

### 完成结果

- 正式产品扫描和恢复入口只接受 `trusted_pane`；`search_page_api` 的研究实现和历史失败证据保留，但不能进入产品链路。
- 扫描状态文字由 today view model 统一负责，SQLite 持久化状态到真实 HTTP 页面已有回归覆盖。
- 删除两个无消费者模块和逐项证明无调用的旧函数；没有拆分大文件，也没有删除 BOSS 安全、存储兼容、恢复或质量代码。

### 保留结论

- `src/dashboard/server.js`、`src/cli.js` 和 `src/adapters/sites/boss.js` 仍是职责集中点，但只在后续独立功能实际触碰时迁移职责。
- 不以文件大小或删行数继续扩大精简；新的删除候选仍必须重新证明无生产价值并通过对应回归门。
- 课题 1 到此结束，不作为课题 2、3、4 的统一改造框架。

- 不追求预设删行比例。
- 不做大爆炸模块拆分、换框架、换数据库或微服务化。

## 课题 2：消息发现的岗位理解与回复草稿

### 目标

对已沟通岗位的招聘方回复和 HR 主动新招呼，结合岗位详情与消息原文，向用户解释岗位并生成可人工复制的推荐回复草稿。

### 状态

`██████████ 100%` 已完成确认设计、实施计划、功能实现、安全复审、最终全量离线回归和当前分支真实登录 BOSS 后台只读验收；位于 `codex/first-principles-audit`，未推送、未合并、未发布。

### 完成结果

- 每个会话先重新读取并验证稳定 BOSS 岗位 ID；本地已有完整 JD 时零浏览器访问，缺失时才允许打开一张同窗口、`active: false` 的临时详情页。
- 临时详情读取严格串行，复用现有详情随机节奏、微冷却、阶段冷却、访问预算和恢复检查点；任何已发出的尝试都计数，失败结果不自动重试。
- 岗位基本字段、完整 JD 和分析来自同一条完整观察，避免新旧记录拼接成不存在的岗位上下文。
- 已完成分析通过十字段安全投影生成五项用户决策：岗位职责、JD 可证明的公司业务、匹配度、原始薪资和是否值得继续聊。低匹配与不推荐优先解释规则保护结论、硬性缺口或岗位质量风险；详细证据仍留在岗位库，不在消息卡展开。
- 面试邀约、薪资、隐私、缺失事实、身份不明或模型结构不合法时仍显示消息结果，但不生成草稿；普通安全沟通每个岗位最多两份草稿。
- 消息正文处理后清空，`securityId` 不进入数据库、日志、状态接口或错误消息；页面只有复制和本地状态记录，没有填写、发送、沟通或投递动作。
- 安全复审修正了稳定 ID 绕过、失败标签清理归因、错误泄密、中止后身份复核、恢复冷却、同观察一致性、混合敏感问题和非法模型结果不可见等问题。无法证明归属的新标签页不会被猜测关闭，而会停止并要求人工恢复基线。
- 真实验收又修正了临时标签初始空白地址等待、独立详情页 DOM 身份读取、硬边界岗位的消息上下文分析，以及消息已读后的可恢复身份核验。普通网页请求不能伪造内部分析能力。

### 已确认设计

- 权威规格：`docs/superpowers/specs/2026-08-16-message-discovery-job-understanding-reply-drafts-design.md`。
- 用户决策卡规格：`docs/superpowers/specs/2026-08-17-message-discovery-decision-card-content-design.md`；实施计划：`docs/superpowers/plans/2026-08-17-message-discovery-decision-card-content.md`。
- 初始实现提交范围：`c11f38a` 至 `73ae57b`；真实岗位读取最终修复：`15a3dab`；决策卡实现与解释修复：`daf5f89`、`6a3c79f`、`e74ba61`。
- 当前普通 JD 主线仍只有 `trusted_pane`；消息发现临时详情是唯一获批的低频 `standalone_detail` 例外，`search_page_api` 未启用、未修复、未验证。

### 真实后台只读验收结果

- 设计前的最小只读 DOM 校准已经完成，并确认稳定岗位 ID 与 `securityId` 入口存在。
- 当前分支 Dashboard 使用隔离验收数据库处理一个真实新沟通样本：本地缺少完整 JD 时只创建一张同窗口、`active: false` 的临时详情页，Dashboard 始终保持活动标签，详情身份和完整 JD 核验成功后临时页关闭，最终恢复为两张固定 BOSS 标签和一张 Dashboard。
- 后续决策卡验收命中本地完整缓存，没有创建详情页或增加详情访问。结果按固定顺序显示岗位职责、公司及业务边界、低匹配结论、原始薪资、是否值得继续聊和消息下一步；公司资料不足被明确标注，面试邀请显示中文标签并按安全规则不生成草稿。旧四组证据标题和内部枚举均未出现。
- 全程没有调用 `Page.bringToFront`，没有填写输入框、发送回复、发起沟通或投递。正式生产数据库和模型设置未修改；详细证据见 `docs/superpowers/reports/2026-08-17-message-discovery-job-understanding-reply-drafts-acceptance.md`。

## 课题 3：通用模式与继承模式

### 目标

让用户明确知道哪些条件控制平台采集，哪些条件用于 RoleFlow 本地精筛，并为通用模式和继承模式提供各自合适的设置。

### 状态

`██████████ 100%` 已完成确认设计、实施计划、功能实现、100 项允许执行的离线回归和两份全新空 operational baseline 的真实后台只读验收；位于 `codex/first-principles-audit`，未推送、未合并、未发布。

### 完成结果

- 方案 v2 明确分离平台采集条件与 RoleFlow 本地精筛条件；旧方案双读兼容，新用户和旧方案默认继续使用继承模式。
- 通用模式保存城市、BOSS 薪资档、经验、学历和职位类型；继承模式读取并展示当前 `BOSS-SEARCH` 范围，但预览不导航。
- 工作流启动时冻结方案、模式、原生筛选目录与本地策略；扫描和恢复只消费不可变快照，方案后续修改不会污染已启动任务。
- 直接命令行通用扫描曾被当前页错误覆盖成继承模式；无效运行被排除，修复 `4a19e9d` 后新增端到端回归，未解析的已保存平台条件现在失败即停。
- 有效双模式样本均发现 75 个、去重 38 个岗位。继承/通用完整 JD 覆盖率为 93.1%/97.1%，硬性错误推荐为 3/1。
- 46 个并集岗位中人工判断 29 个相关；继承/通用相对召回率为 93.1%/79.3%。两次结果交集 Jaccard 为 65.2%，BOSS 排序和时间波动使其不能解释为严格模式因果。
- 通用模式多发出 6 次详情读取，增加 74.105 秒总耗时和 26.250 秒冷却。本次质量权衡不足以支持改变默认值，默认继续为继承模式。
- 两次验收均保持固定标签、前台标签和标签数量不变，无登录、风控或页面丢失中断，无外部写。课题 3 验收结束时共享近 24 小时列表跳转额度为 `16/16`；这是当时的验收记录，不再作为课题 2 的待办条件。

## 课题 4：逐岗位进度与明确进度条

### 目标

让用户准确理解扫描、JD、分析和沟通正在处理什么、已完成多少、还剩多少，同时消除不必要的整页刷新和闪烁。

### 状态

`██████████ 100%` 已完成设计、实施、Chrome 隔离验收和本地验证；位于 `codex/first-principles-audit`，未推送、未合并、未发布。

### 完成结果

- SQLite 读模型统一提供四条独立进度：扫描岗位、完整 JD、分析岗位和沟通岗位；没有制造缺乏真实权重依据的总百分比。
- 扫描与 JD 保持交错：`completed`、`partial`、`failed` 都计入已处理搜索目标；JD 分母严格使用 `read + pending`，无需详情的 `notRequired` 岗位不进入分母。
- 扫描适配器只把已经观察到的卡片、详情和目标终态写入 checkpoint；浏览器命令调用数回归证明没有增加 BOSS 操作，也没有改变随机节奏、冷却或失败即停边界。
- 分析页服务端渲染岗位名称和公司，约 2.5 秒的轻量轮询只返回任务 ID、位置、状态和允许的错误码；沟通页按不可变批次条目 ID 更新。完整 JD、分析内容、消息、沟通证据和任意内部错误正文不进入轻量响应。
- 同阶段逐岗位变化只局部更新。页面隐藏时零请求，恢复可见时立即读取，始终最多一个请求在途；阶段结构变化、沟通歧义、批次或岗位集合漂移和终态最多整页刷新一次。
- Chrome 本地隔离验收覆盖 `scanning`、`analyzing`、`paused`、`review_required`、`interrupted` 五个状态和 4 个视口，共 20 页；零浏览器/请求/外部请求错误、零横向溢出、零运行中动画。证据保存在 `.runtime/workflow-progress-evidence/`。
- 课题 4 阶段的 212 个 JavaScript 文件语法检查全部通过；课题 3 收尾后当前允许执行的 100/101 项离线检查全部通过，唯一未运行的是会生成未签名 `msedge.exe` 测试桩并触发 360 的 `startup_scripts_smoke.js`。
- 当前真实 BOSS 访问和外部写均为 0。生产代码仍只有 `workspace-tabs` 在用户主动启动工作台时的一次前台引导调用；两个浏览器适配器保留实现该能力所需的传输方法，其他流程没有调用。
