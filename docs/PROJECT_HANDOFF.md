## 3. 当前不可改变的边界

完整规则以根目录 `AGENTS.md` 为准，主控尤其要保留以下约束：

- BOSS 默认只读；沟通、发送消息和申请岗位等外部写动作必须针对当前不可变样本获得明确授权。
- 浏览器严格串行，静止基线只保留 `BOSS-SEARCH` 和 `BOSS-COMMUNICATION` 两个固定标签；消息发现仅在本地没有完整可信 JD 时允许增加一张同窗口、`active: false` 的临时详情页，读完后回到固定基线。每次从当前绑定重新读取数值 tab ID。
- 扫描、JD、分析、消息发现、沟通、轮询、重试和恢复期间禁止 `Page.bringToFront`、窗口激活和任何前台焦点恢复。唯一例外是用户主动启动工作台且未指定 `-NoOpen` 时，`workspace-tabs` 可在就绪检查后调用一次 `Page.bringToFront`：就绪时引导到 Dashboard，未登录时引导到 BOSS；不得把该例外复用于其他路径。
- 当前岗位详情主线只用 `trusted_pane`；`search_page_api` 保留但不修、不验、不优化、不删除；禁止一般用途的 `standalone_detail`。唯一例外是低频、后台、串行且受共享冷却保护的 `message_discovery_detail`。
- 登录、风控、页面丢失、标签身份漂移、目标不一致或结果不明确时立即停止，不自动重试。
- 不降低 JD 覆盖、召回或匹配质量。可能降低质量的方案必须先量化并由用户决定。
- 筛选规则实质变化后必须使用全新空 operational baseline；失败或中断数据库不参与质量评测。
- 不启动 Wave 5，不做全面重构，不修现实路径不可触发的理论问题。

## 5. 架构方向

- 继续使用渐进式模块化单体，不采用大爆炸拆分、微服务、ORM、依赖注入容器或前端框架迁移。
- 先证明代码无调用或无产品价值，再删除；不要以行数作为唯一成果指标。
- `src/dashboard/server.js`、`src/cli.js` 和 `src/adapters/sites/boss.js` 是职责集中点，但文件大不等于应整体重写。
- 后续功能只迁移实际触碰的职责；保留 BOSS 安全代码、存储兼容门面、质量基准和恢复测试。
- 课题 4 继续复用 SQLite 和现有 HTTP 轮询：扫描、完整 JD、分析和沟通分别使用自己的真实分子/分母，不计算伪造的跨阶段总百分比。
- 课题 3 把平台采集范围与 RoleFlow 本地精筛拆成版本化方案字段；新任务冻结完整方案、模式和原生筛选目录，恢复任务只消费启动快照。旧方案和新用户继续默认继承模式。
- 扫描与完整 JD 在同一采集阶段交错进行；扫描“已处理”只统计 `completed`、`partial`、`failed` 终态目标，完整 JD 分母严格为 `read + pending`，`notRequired` 不进入分母。
- 扫描卡片、详情和目标进度沿现有串行适配器路径 checkpoint；回归测试证明没有增加 BOSS 导航、读取、点击或前台操作。常规扫描和 JD 产品主线仍只有 `trusted_pane`。
- 消息发现先从当前会话重新解析稳定岗位 ID，再按该 ID 复用完整本地 JD；没有完整缓存时才允许打开一张同窗口后台临时详情页。岗位字段、JD 和分析必须来自同一条完整观察，不能把新岗位字段与旧 JD 拼接。
- 消息详情访问复用既有详情节奏、访问预算和恢复检查点；恢复后先补做已经到期的详情冷却，再允许下一次浏览器访问。无法确认归属的新标签页不会被猜测关闭，而是停止并提示人工恢复浏览器基线。
- 消息结果使用十字段安全决策投影，只展示岗位职责、JD 可证明的公司业务、匹配度、原始薪资和机会结论；低匹配与不推荐优先解释规则保护结论、硬性缺口或岗位质量风险，不展示内部证据数组。模型结构失败、薪资、隐私和身份不明等结果形成可见的无草稿人工处理项；真正的面试邀约只生成固定的本地非承诺询问草稿，不确认时间、形式或候选人可用性。每个岗位最多两份草稿，页面只提供本地复制和本地状态记录，不提供填写或发送到 BOSS 的动作。
- 消息正文只在当前内存流程中使用并随后清空；`securityId` 仅用于当次可信后台导航，不写数据库、日志、状态接口或错误消息。
- 用户决策与消息语义修正规格为 `docs/superpowers/specs/2026-08-17-message-discovery-user-decision-semantics-fix-design.md`（设计/计划 `c3c9108`，实现 `f1a7260` 至 `a2ce0c4`，最终安全闭环 `c58a63f` 至 `ed0b27d`）：模型沟通意图不再被“面试”等词覆盖，摘要仅短期传递，状态接口不含摘要。
- BOSS 详情访问节奏以站点为单位跨扫描、消息发现和候选人档案共享；v16 迁移保守合并旧节奏，已到期的冷却不会因切换流程或档案被绕过。
- 分析岗位名称和公司只由服务端渲染，轻量轮询只按任务 ID 更新状态；沟通页按不可变批次条目 ID 原地更新。页面隐藏时不请求，恢复可见时立即读取，始终最多一个请求在途；歧义、批次漂移和结构阶段变化最多触发一次整页刷新。
- Chrome 隔离验收证据位于 `.runtime/workflow-progress-evidence/`：`chrome` 渠道、5 个状态 × 4 个视口共 20 页，零控制台/页面/请求/外部请求错误，零横向溢出，降低动画模式下运行中动画为 0；已人工查看分析态 1440×900 和 375×812 全页截图，四条进度和 6 个岗位状态清晰可读。
- 所有代码修改先完成本地自动验证和必要的本地人工验收，再提交；不得提交后才开始主要验证。
